# 数据工程课大改版设计稿 · 视频课 + 单一项目全程带练

> 现课名：**机器学习 & 数据工程全栈项目班**（prod slug: `data-engineer-data-analyst`）
> 本文是**改版方向设计稿**，确认后再落 `outline.json`。

## 改版三条定死的口径

1. **知识点全部录播视频**，学生按自己节奏看——**视频复用现有 100h 直播录播精剪**（不重录）。**报名即全部开放**，不锁周次。
2. **一个老师带全程**：老师不讲技术点（视频承载），角色是**每周现场用 AI Coding 真敲 + 答疑解惑**——不是讲思路、放 PPT，是当场把这一层的 milestone 真做出来（哪怕现场调试、让 AI 改一版），学生看资深工程师真实的 AI 编码过程，再回去做进自己项目。
3. **全程只做一个项目**：一条**端到端的数据工程管道**，报名即启动，**10 周**里每周长一层，老师带这一个项目从立项到结营。

## 运转模型：边学边做的循环（10 周）

```
报名完成 = 开营
   ├─ 视频库全部开放  ──►  学生按自己节奏学（学到哪一层知识）
   └─ 项目同时启动    ──►  老师带着把项目里对应那一层做出来
                              （老师全程答疑：项目问题 + 知识点问题）
   ════════════ 10 周后 ════════════►  一个完整的端到端数据管道项目
```

**核心不是"上课"，是"边学边做"**：视频教你某一层（如 Extract、上云、数仓），老师就**现场用 AI Coding 把这一层真敲出来**、带着你把它落进你自己的那个项目里，卡住了随时问——问技术点也行、问项目怎么搭也行。10 周攒出一个完整作品。

## 1. 一句话讲清改了什么

**旧：** 6 位导师、100+ 小时直播讲课，3 个月，2 个人项目 + 1 团队项目，学生「来听课」。
**新：** 知识全录播（自主看）+ **一个资深数据工程师用 10 周带你做完一条端到端数据管道**。

> 差异化：从「听 6 个大牛讲课」→「自己按节奏学视频 + 一个老师全程带你把一个真实项目做出来、能直接写进简历」。
> 完全对齐平台「多通道学习、围绕学习目标不围绕直播课、学员自主节奏」。

## 2. 三层结构

| 层 | 是什么 | 形式 | 谁负责 |
|----|--------|------|--------|
| **知识层** | 14 模块所有技术知识点 | **录播视频**（复用现有直播录播精剪，报名即全开，self-paced） | 视频库 |
| **带练层** | **唯一的一个端到端项目** | **老师现场 AI Coding 真敲 + 答疑**（唯一同步环节） | **一个老师**，全程 |
| **陪跑层** | 入营→结营全程关系 | 答疑（项目问题 + 知识点问题）+ 项目 review + 结营验收 | **同一个老师** |

**「一个老师带全程」**：学生 10 周只对一个人。老师**不讲课**，核心是**现场 AI Coding 把项目 milestone 真做出来 + 答疑**——覆盖 DE 全栈、能评审架构、能 review 代码（师资表 Principal/Staff 级如 Gucheng Zhu / Chao Mu / Leo 可担）。老师同步工时 ≈ **2-3h/周 × 10 周 ≈ 25-30 小时** + 异步 review。**备课极轻**：知识点靠视频、现场 AI Coding 不用排练完美 demo，知道这周该长哪一层、环境备好即可（准备 20-30 分钟）。

## 3. 唯一的项目：一条端到端数据管道（每周长一层）

学生从头到尾只做这一个项目，但它**每周加一层**，10 周长成一个 portfolio 级的完整数据工程系统：

```
数据源(API/文件)
   → Extract 抽取(Python ETL)
      → 落库(SQL) → 上云(S3/Lambda/serverless)
         → 数仓建模(dbt) → 批处理(Spark) → 编排(Airflow) + CI/CD
            → 数据应用层：ML 模型 或 AI(RAG/text-to-SQL)
               → 可视化(Tableau/Power BI) → 安全加固 → 部署交付
```

> **ML/AI 不是单独项目、也没砍**——它是这条管道的**一层**（W8 接进去），学生按兴趣选 ML 建模或 AI 应用（RAG/text-to-SQL）接一个即可，深度靠视频自学。

## 4. 10 周推荐节奏（项目每周长一层）

> 视频全程开放、学生自主学，这张表是**推荐节奏**（不是硬锁日程）——它同时是老师带练/答疑的锚点：老师每周聚焦项目该长的这一层、现场 AI Coding 敲出来，学生按这个顺序边学边做最稳。
> **为什么 10 周**：受众有 Python/SQL 底子但偏学生/初级，8 周偏紧、12-16 周太长且带练成本高；10 周 × 每周 2-3h 是可持续的中间值（老师估：IT 经验 8-12 周、学生 12-16 周）。最重的两层（上云、批处理）各拆 2 周。

| 周 | 项目这周长哪一层（老师现场 AI Coding + 答疑） | 对应自学视频（原模块） |
|----|--------------------------|----------------------|
| **W1** | 立项 + 选题 + 架构设计 + 环境（Git/Linux）+ 数据源确定 | M1 基础、M2 概览 |
| **W2** | **Extract 层**：API/文件抽取 + Python ETL + SQL 落库 | M2 Extract、M4 SQL |
| **W3** | **上云①**：容器化（Docker）+ AWS 基础（IAM/S3/VPC）配置 | M3 AWS、Docker |
| **W4** | **上云②**：Serverless（Lambda）部署 + 云数据库 | M3 Lambda、云数据库 |
| **W5** | **数仓 + 转换**：数据湖/数仓建模 + dbt 转换 | M7 数仓、M8 dbt |
| **W6** | **大数据**：Spark SQL 批处理接入 | M8 HDFS/Spark |
| **W7** | **编排 + CI/CD**：Airflow 编排 + GitHub Actions 自动化 | M8 Airflow、M5 CI/CD |
| **W8** | **数据应用层**：ML 模型 或 AI（RAG/text-to-SQL）二选一接入 | M9 机器学习、M6 AI Engineer |
| **W9** | **加固 + 交付**：数据安全/脱敏 + 可视化 + 部署收尾 + 文档 | M12 安全、M10 可视化、M5 部署 |
| **W10** | **结营 Demo Day + 作品集打磨 + 求职**（简历 / Mock / 内推） | M13 敏捷、M14 求职辅导 |

每周固定：**项目带练直播 ~1.75h**（老师现场 AI Coding 把本周这层真敲出来 + code review）+ **答疑 Clinic ~0.75h**（卡点自由问）+ **异步 review**（提交后书面反馈），合计每周 **2-3h**。
原「M13 敏捷」既是视频，也在项目里真跑（每周迭代 = 一个 sprint）。

## 5. 招生形态连带调整

1. **cohort 保留**：知识视频自主学，但带练直播按批次跑（保留现有 Batch 制），维持节奏和同伴感。
2. **项目归属**：全程一个项目，默认**每人一个 portfolio 项目**（各自拥有，最利于写简历/内推）。若想做小组共建也可，但不再有"个人项目 + 团队项目"的双轨。
3. **价格 & 卖点**（marketing/sales 决策，我不擅自定）：人力从 6 人变 1 人高触点，卖点从"名师阵容"→"**10 周一个老师现场 AI Coding 带你做出一条能写进简历的端到端数据管道**"。建议维持价位、重写卖点。
