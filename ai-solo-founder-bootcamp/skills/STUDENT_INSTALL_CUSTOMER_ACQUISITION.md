# OPC Customer Acquisition 学生 Skill

`opc-customer-acquisition` 用来设计一轮小规模获客实验：定义可核验的 ICP、选择一个渠道、建立有来源的潜客名单、逐条审批外联，并用真实回复和转化事件判断继续、调整还是停止。

## 安装到 Codex

1. 下载并解压课程提供的 Skill 包。
2. 把 `opc-founder-os` 和 `opc-customer-acquisition` 两个完整文件夹复制到 `~/.codex/skills/`。
3. 重新打开 Codex或新建任务。
4. 输入：`运行 $opc-customer-acquisition，基于我的真实客户证据选择一个渠道，先写实验上限和停止规则，不要发送消息。`

两个 Skill 必须读取同一个 Founder Workspace，让获客实验沿用同一份客户、Offer 和销售证据。

## 使用前准备

- 已通过课程验证的目标客户与 Offer；
- 你有权访问并用于本次目的的潜客来源；
- 当前交付容量、预算和每周可投入时间；
- 过去的销售 Pipeline 或真实回复（如有）；
- 本轮实验可以接受的联系上限、支出上限和风险停止线。

公开网页上的联系方式不等于允许营销。不要上传支付密钥、账号密码、完整私人名单、敏感属性或与实验无关的个人信息。

## 推荐使用顺序

1. 把 ICP 写成可以逐项核验的纳入条件和排除条件。
2. 比较渠道后只选择一个主要渠道和一个消息假设。
3. 让 Skill 检查每位候选人的来源、资格和允许联系的路径。
4. 让 Skill 生成少量个性化草稿；你逐条检查收件人、权限、内容和发送时间后亲自发送。
5. 把真实发送、回复、会议和 Proposal 证据脱敏后带回，计算带分母的漏斗数据。
6. 到预先约定的复盘点执行 `continue`、`revise` 或 `stop`；每轮只改变一个主要变量。

## 安全边界

- 不批量群发通用 AI 文案，不绕过平台限制，不购买来源不明的名单。
- 不联系已退订、已排除或无法确认允许联系路径的人。
- AI 不得冒充你继续真人对话、同意商业条款或承诺结果。
- AI 生成的回复、会议、打开率、转化和截图一律不能进入漏斗。
- 出现投诉、退订异常、平台警告或新的隐私风险时，立即停止实验并交给人工检查。

## 什么才算完成

- `drafted`：只有 ICP、名单、消息和实验计划；
- `executed`：真实外联已发送，证据和结果记录到预定复盘点；
- `verified`：reviewer 已检查来源权限、真实漏斗证据、计算、风险处理和实验结论。

缺失的送达或打开数据应写 `unknown`，不能填成 0。样本不足时要写清缺少什么，不能因为一个回复就扩大群发，也不能因为无人回复就自动宣布渠道无效。
