## 0. 先说清楚这门课的特殊之处（读完再往下看，否则会误用模板）

`course-funnel-architect` 的默认模型是：一门课自己拆出「$29 引流课 → 自学/教学/陪跑三档主课」。**这门课不是那个模型的标准情况**，原因是两条真实数据：

1. **这门课自己在生产环境就是单一 SKU**——查 `admin-cms/programs/by-training/695f55f8d6221b0fef013efb` 只有 1 条 program 记录（`6959ff4c084cf0f0766c9936`），`tuition: 399` / `promoTuition: 299`，没有第二档价格，也没有直播/陪跑选项。[来源：生产环境 API，2026-07-03 查询]
2. **它自己的课程文案已经把自己定位成另一门课的入口**——outline.json 的 `cardDescription` 写的是"AI Engineer 进阶学习的**官方前置入门课**"，`courseObjective` 最后一条明确写"为后续深入学习 Agent、多智能体、MCP、模型微调等**进阶内容**打下扎实基础"。[来源：`curriculum/ai-engineer-rag/public/outline.json`]

换句话说：这门课在公司整条 AI Engineer 产品线里，扮演的角色更接近"引流课"，而不是"要拆三档的主课"。真正的"主课"是另一门已经存在、已经有自己 `FUNNEL_PLAN.md` 的课——`ai-engineer-bootcamp`（12 周技术课 + 12 周 P3 企业孵化，现价 **$3,850 AUD / 促销价 $3,000 AUD**，来源：生产环境 API `admin-cms/trainings?search=AI Engineer` + `admin-cms/programs/by-training/66e3e7641664e500126d237f`，7 期 program `6a2f619866cf989b58c499bb` 定档 2026-08-29 开课，5 期 program `698c339dbb0ad7fe43b0c99d` 已招 65 名学员；WebFetch `jiangren.com.au/program-course/ai-engineer-bootcamp` 交叉核实同一价格）。

**这带来一个必须摆出来的冲突，见 §5。**

## 1. 漏斗定位

- **本课自身角色**：全公司 AI Engineer 产品线里的"入门/引流层"，不是独立的三档主课产品。
- **本课时长**：4 周，79 节课（37 视频 + 25 Lab + 5 AI Tutor Quest + 12 Info/自学），self-paced 无排期。[来源：outline.json 统计 + PERSONAS.md §0 已核对生产环境 syllabus 一致]
- **目标用户**：见 `PERSONAS.md` 三个 persona（A 转型型技术人 ~55%、B Bootcamp 试水者 ~25%、C 求职防御型 Cloud 工程师 ~20%，占比均为 AI 推测，非真实报名统计——样本只有 3 人）。
- **业务模式**：**不套用标准 A/B/C/D 分类，走自定义变体**——本课不内部拆三档，它整体对应"跨课程漏斗"里的一个环节。详细论证见 §4。
- **引流课形态**：N/A（本课不是"主课"，不需要在自己名下再设计一层引流课；但下面 §5 要讨论"要不要在本课之下再加一个更便宜的真引流课"这个开放问题）。
- **核心承诺**：4 周从"会用 AI"到"能独立搭一个非生产级 RAG 原型"，为报考 `ai-engineer-bootcamp` 打基础。[来源：outline.json `courseObjective`]
  - 🚨 不承诺金钱/收入/入职/包就业，禁用"副业"一词——只承诺过程结果（作品/技能/准备度）。

## 4. 为什么不做"本课自己拆三档"

按 `main-course-tier-design` 的默认逻辑，三档差价按"承诺什么结果"分：自学版看完+社群、教学版跟着做+批改、陪跑版做出可展示作品。套到这门课上会遇到三个真实障碍：

1. **课程本身就是纯自学录播**（type: video，无直播、无 1v1、无排期），"教学版""陪跑版"需要的直播/批改/mentor 服务本课完全没有，硬造出来等于凭空承诺一个现在不存在的服务，会踩"禁止编造"红线。
2. **只有 3 名真实学员**，样本小到无法判断"有没有人愿意为更贵的陪跑档付费"——没有任何数据支持拆三档能带来增量收入,拆错了反而会把现在还算清楚的"$299 入门 → $3,850 旗舰"两级阶梯搞乱。
3. **公司已经有一门相邻定位、真正提供直播+1v1+批改的课**（`ai-engineer-bootcamp`），如果本课再造"教学版/陪跑版"，等于在内部打自己的旗舰课，价格带会打架（比如本课教学版卖 $800，旗舰课教学版卖 $3,000，两者内容重叠度高的话，用户为什么不直接等旗舰课打折）。

**结论：本课维持单一 SKU，不建议现在跑 `/main-course-tier-design`。** 如果未来学员数上升到能看出付费分层需求（比如有学员反馈"想要更多批改但不想报旗舰课"），再重新评估，需写新的决策日志条目说明触发原因。

## 5. 🚨 引流课定位冲突——需要用户拍板

这是本文档最重要的一条发现，必须先摆出来再往下走：

**`ai-engineer-bootcamp/FUNNEL_PLAN.md`（2026-07-03 版本）§4 已经提议造一个新的独立引流课**——标题候选《一个下午，从零跑通你的第一个 RAG + Agent》，$29 AUD，2-3 小时，衍生自旗舰课 Phase 3 RAG 模块，目标是给旗舰课的三个 persona 建立"这课真能带我动手"的信任。这份文档写得很清楚这是"提案，未做用户测试"。

**但这门课（`ai-engineer-rag`）在自己的课程文案里，已经把自己定位成"官方前置入门课"，主题同样是 LLM/Prompt/RAG，且是真实在卖、真实有 3 名学员的产品，不是提案。** 两门课的引流定位有明显重叠：

| | `ai-engineer-rag`（本课，已存在） | `ai-engineer-bootcamp` 提议的新引流课（未建） |
|---|---|---|
| 状态 | 真实在售，3 名学员 | 提案阶段，未开发 |
| 价格 | $299 / $399 AUD | 提议 $29 AUD |
| 内容 | 4 周 79 节课（LLM/Prompt/Embeddings/RAG 系统性讲解） | 提议 2-3 小时单次 quick win（RAG+Agent demo）|
| 官方定位 | outline.json 明说"官方前置入门课"，导向 `ai-engineer-bootcamp` | 提议衍生自 `ai-engineer-bootcamp` Phase 3，导向同一门课 |

这不是"两个不同阶段"（比如 $29 → $299 → $3,850 三级阶梯），这是**两个不同价位但目标高度重合的入口**，都想干"把人导进 `ai-engineer-bootcamp`"这件事。如果两个都做，会出现"用户先花 $29 还是先花 $299"的路径混乱，营销素材也不知道该导流去哪个。

**需要用户拍板的两个方案（本文档不替用户做这个决定）**：

- **方案 1：三级阶梯**——保留本课 $299/$399 作为"中间档"（比免费试学更深入、比旗舰课便宜很多），额外建一个真正 $29 的超低门槛 quick win 挂在最前面，专门捕捉"完全没决定要不要学"的冷流量；本课定位调整为"付费验证型"中间层（对应 Persona B "先花小钱试水"）。三门课依次导流：$29 quick win → $299 本课 → $3,850 旗舰课。
- **方案 2：本课就是唯一引流层**——放弃 `ai-engineer-bootcamp/FUNNEL_PLAN.md` §4 那个 $29 新引流课提案，改成直接强化本课与旗舰课之间的转化路径（即 §6 要设计的过渡序列），理由是本课已经有真实销量和"免费试学 3 节"兜底，没必要再造一个更便宜但内容更单薄的入口跟自己抢流量。

**建议**：如果用户选方案 2，需要回头把这个决定同步写回 `ai-engineer-bootcamp/FUNNEL_PLAN.md` 的决策日志（本次任务范围内不改那份文档，只在这里记录发现）。
