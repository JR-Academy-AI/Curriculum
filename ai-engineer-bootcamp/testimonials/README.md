## 这个目录是干什么的

**学员拿到的 offer、学员说的原话，唯一的存放地。**

在这个目录建立之前，AI Engineer 班的学员反馈只有零散一份
`feedback/2026-06-24-cohort05-julie-function-calling.md`（那是课程内容反馈，
不是就业战报），offer 则完全没有归档——散在班级群、1v1 记录和个人截图里。
结果是 marketing 想写案例时找不到素材，销售想举例时只能凭印象说。

以后 **收到一条就存一条**，存在 `students/` 里，一个学员一个 md。

---

## 放什么 / 不放什么

**放：**
- 学员拿到的 offer（公司、岗位、时间、包裹范围、有没有截图）
- 学员的原话感言（testimonial）——学完最大的变化是什么，逐字记，不润色
- 学员做出来的项目 / 作品链接（AI Engineer 班学员通常有 RAG / Agent 项目）
- 这条素材**能不能对外用、能用在哪几个渠道**（consent）

**不放：**
- 活密码 / token / 学员账号密码（任何 git 都不进，这是全公司红线）
- 没影的事。学员没说过的话不许替他编，offer 没确认不许先写上去

课程内容层面的反馈（某节课讲得好不好、哪里没听懂）继续放同级的
`feedback/`，不要塞进这里——两者的下游用途不同。

---

## 三条红线（写之前先看）

1. **不承诺包就业。** offer 记录只能是**事实陈述**（「A 同学 2025-11 拿到 X 公司
   Y 岗位 offer」），**禁止**推导成「学完就能拿 offer / 保 offer / 包上岸 / 必进大厂」。
   对外文案引用这里的数据时同样受这条约束。
2. **原话不改。** 学员感言逐字录入，AI 和运营都不许润色、不许改得更漂亮。
   要精简版就在原话下面另起一行标「精简版（对外用）」，原话永远保留。
3. **同意才对外。** 这个仓库是 private，写真名和真公司没问题；但**对外用**必须
   看 `consent` 字段——学员勾了哪几个渠道就只能用哪几个。学员选匿名就用代称。
   **退费学员一律不上墙**，已收的素材移到 `_archived/` 并注明原因。

## 怎么用（日常四步）

1. 学员报喜 / 结业回访拿到 offer 或感言 → 立刻建文件
   `students/{年份}-{展示名}.md`，从 `_TEMPLATE.md` 复制。
   - 实名：`students/2026-julie.md`
   - 匿名：`students/2026-anon-01.md`
2. 逐字填。拿不准的字段写「待补」，**不要猜**。
3. 更新 `INDEX.md` 顶部的汇总表加一行（一条 = 一行）。
4. 说一句「发布」，Claude 会 commit + push。

## 谁会来拿这里的数据

| 下游 | 拿去干嘛 |
|------|---------|
| 销售页 OFFER WALL（`/program-course/ai-engineer-bootcamp/`） | 真实 offer 卡片 + 一句话感言 |
| `PROMOTION_PLAN.md` / `PROMOTION_PLAN.us.md` / 小红书 / 公众号 | 案例段、学员故事切角 |
| Sales 跟进话术 | 举同类背景学员的真实例子（只能用 consent 允许的） |
| `PERSONAS.md` / `PERSONAS.us.md` refresh | 真实学员画像回灌，替换 AI 推断 |
| `JD_SKILL_MAP.us.md` 校准 | 学员真拿到的岗位 vs 我们抓的 JD 对不对得上 |

引用时一律回链到具体的 `students/{文件}.md`，不要二次转述后就失去出处。
