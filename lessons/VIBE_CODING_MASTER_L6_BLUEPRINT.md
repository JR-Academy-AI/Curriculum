# Vibe Coding 大师课 · 第六节蓝图

> 状态：DRAFT 0.2（2026-07-30 改版：从动手工作坊改为**诊断课**）
> 主题：Agent —— 会遇到的问题、怎么定位、怎么改
> 课型：**90 分钟讲解 + 投屏演示 + 一段 10 分钟现场诊断练习**（不做长任务实操）
> 本文只定义课程，不包含 deck 实现。
> 承接第五节：L1–L5 你一直在给 Agent 准备「对的输入」（人 / 产品 / 视觉 / 交付 / 能力五层 SoT）；L6 第一次把 Agent 本身拆开，然后回答三个问题：**它会怎么坏 · 坏了怎么看出来 · 看出来了怎么改。**

> ### 0.1 改版说明（v0.1 → v0.2）
> v0.1 是 130 分钟动手工作坊：学员在第 50 分钟交一个长任务后台跑，老师边讲边让他们看自己屏幕，最后做 A/B 对照。**实测时长装不下**，改为 90 分钟诊断课：
>
> | | v0.1（作废） | v0.2（本版） |
> |---|---|---|
> | 课型 | 动手工作坊 | 讲解 + 投屏演示 + 诊断练习 |
> | 时长 | 130 min | 90 min |
> | 主干 | 交任务 → 看它跑歪 → 重交 | **问题 → 定位 → 改** |
> | 学员动手 | 跑两次真实长任务 | 对着预录记录填**诊断单** |
> | A/B 对照 | 课上现场跑 | 老师**预录投屏**（保住冲击力，不吃课堂时间）+ 挂进作业 |
> | 核心产物 | 观察日志 | **诊断单**（症状 → 机制 → 处方） |
>
> 五条跑偏机制从「中段素材」升格为**本节主干**；「怎么改」不是新内容，而是把交付单 / 计划先行 / 可执行验证 / 落盘 / 打断重组成**五条机制各对一个处方**。

## 1. 课程定位

第五节结束时，你已经会给 Agent 准备很好的输入了。但有两件事一直没解释：

- 为什么同一个项目、同一个工具、同样认真地交任务，这次二十分钟干得漂亮，那次四十分钟回来一堆要重做的？
- 为什么它前十分钟很守规矩，越到后面越不听话？

到今天为止，你对这两件事的解释只能是「看它今天心情」。而这句话等于承认了一件事：**你不知道你在指挥什么。**

这节课把运气换成机制。而且不停在「懂原理」——**懂原理不解决问题，会诊断才解决问题。** 所以本节的形状是一条诊断链：

```text
      ①  会遇到的问题
   长任务只有五种死法，每种都有一个你认得出的症状
                  ↓
      ②  怎么定位
   从症状反查机制：三个问题 + 一张反查表
                  ↓
      ③  怎么改
   五条机制 → 五个处方，每条都落到一个具体动作
                  ↓
   从「看它今天心情」变成「我知道它会怎么坏，所以我提前把那个口堵上」
```

一句话定位：

> 第六节不教你怎么把 Agent 用得更花，教你**它坏的时候你能看出来是哪儿坏了，并且知道改哪一处。**

> 系列主线仍在走：L1–L5 是「往 context 里放对的东西」，L6 是「看懂 context 怎么被消耗、坏在哪、怎么修」。**所有 SoT 的物理作用，就是让它每一轮重读 context 时读到的是对的东西** —— 这条收束仍是本节的高点（P08）。

## 2. 学员起点

学员上课前应有：

- 前五节的体感。**本节不要求学员有可跑的环境**（这是相对 v0.1 最大的放宽）——不做长任务实操，所以没带电脑也能上，看得懂投屏就行。
- 一点「被 Agent 坑过」的经历。开场那个钩子要靠它起作用；没有的话老师的投屏案例能补上。
- 纸笔或一个文档 —— 要填**诊断单**。

## 3. 学习目标

课程结束后，学员能够：

1. 说清 **Agent = 模型 + 工具 + 循环**，以及它**每一轮都重新读一遍 context 再决定，不是带着记忆往前走**。
2. 说清 **它没有记忆，只有 context**：所有「它怎么又忘了 / 瞎编 / 不守规范」都先当 context 问题查。
3. 把 **L1–L5 的所有 SoT 重新解释成 context 治理**，从「照做」升级到「知道为什么」。
4. **认出五条跑偏机制**（context 稀释 / 压缩丢细节 / 错误累积 / 目标漂移 / 进度幻觉），并能把每条对上一个自己见过的症状。
5. 用**定位三问**查问题：这件事现在在它 context 里吗 · 它是在查还是在猜 · 这句「完成了」我自己验过吗。
6. 用**症状 → 机制反查表**，从一个现象倒推到根因，而不是笼统地说「它今天不行」。
7. 独立完成一次**诊断**：拿到一份跑偏记录，填出「症状 → 机制 → 处方」。
8. 给出**五条机制各自的处方**，且每个处方都是一个具体动作（交付单四格 / 计划先行 / 可执行验证 / 落盘 / 打断）。
9. 守住铁律：**它说「完成了」不算完成，判据必须来自它之外。**
10. 认出**该打断的三个信号**，并知道打断之后要给它新 context、什么时候该重开会话。

## 4. 非目标

本节明确不做：

- **不做长任务实操**（这是本版最主要的收敛）。学员不跑 A/B，只做诊断练习。完整的 A/B 对照挂到作业。
- 不教用 SDK / API 造 agent 产品。
- 不讲 MCP / Hooks / Subagent 的配置细节（留后续；子 agent 是 L7）。
- 不讲模型内部（transformer / attention / 参数量）。
- 不背参数、不调配置。全程不教任何「把 X 设成 Y」。**唯一例外见 §5.8**：番外「让它少说点」会提到「思考显示可以关 / 改摘要」这一类设置**存在**，但只讲判断（三种「太长」怎么分、别拿调低思考治啰嗦），不讲任何参数名和档位值。
- 不引与具体模型版本绑定的行为参数（见 §14 数据纪律）。
- 不追求讲全所有故障，只讲**这五条**——它们覆盖绝大多数长任务翻车。

## 5. 核心教学决策

### 5.1 主干是诊断链，不是知识点清单
三段式**顺序不可调**：先让学员认出问题（有痛感）→ 再给定位方法（能自查）→ 最后给处方（能行动）。

判断线：任何一页如果既不属于「这是哪种坏法」、也不属于「怎么看出来」、也不属于「怎么改」，就砍掉。原理页（Agent 是什么 / context 是什么）**只保留到能支撑诊断为止**——它们是地基，不是主角。

### 5.2 每条机制必须配「症状」和「处方」，三者一一对应
这是本节的结构骨架，也是它区别于「Agent 原理科普」的地方：

| 机制 | 症状（学员认得出） | 处方（一个具体动作） |
|---|---|---|
| ① context 稀释 | 越到后面越不守规矩 | 关键约束**落盘**成文件，别只在对话里说一次 |
| ② 压缩丢细节 | 风格断层 / 重踩已解决的坑 | **决定和「为什么」落盘** + 一次一件事，别把五件事塞一个会话 |
| ③ 错误累积 | 每步都有道理，整体是错的 | **计划先行 + 你审计划**（最便宜的纠偏窗口） |
| ④ 目标漂移 | diff 比预期大三倍 | 交付单的**「边界」格**：只动什么、不要碰什么 |
| ⑤ 进度幻觉 | 总结全绿，自己跑全红 | **可执行验证** + 铁律：判据来自它之外 |

**没有处方的机制不讲。** 一条只能让学员"哦懂了"、下周操作不变的机制，属于科普不属于本节。

### 5.3 「怎么改」是重组，不是新增
交付单 / 计划先行 / 可执行验证 / 落盘 / 打断这些内容 v0.1 就有，但当时散在工作坊步骤里。本版把它们**重组成处方**，挂到各自要治的机制上。好处有两个：学员记得住（因为有对应关系），而且课上不需要新讲一堆东西——**这也是 90 分钟能装下的原因。**

### 5.4 诊断练习替代实操：不吃时间，但学员仍是「自己认出来的」
10 分钟，发一份老师**预录的真实跑偏记录**（带时间轴、Agent 的自述、实际输出），学员对着填诊断单。

为什么这个设计成立：
- **不依赖学员环境**——v0.1 最大的脆弱点（项目太小 / 跑不起来 / 跑太快没歪）全部消失。
- **保住「自己认出来」的效果**——比听老师讲十遍管用，这是 v0.1 想要的东西，用更便宜的方式拿到。
- **可控**——所有人看同一份材料，讲评时全班有共同语言。

**分两遍填**：练习时先填前两栏（症状 → 机制），学完处方之后回来补第三栏。第二遍是全课的收口动作。

### 5.5 A/B 对照不删，改成预录投屏
v0.1 的 A/B（裸交 vs 带交付单）是最有说服力的一幕，删掉可惜。改成**老师课前跑好、课上投屏对照**：并排放两段指令 + 两组结果（时长 / diff / 验证红绿）。冲击力保住，课堂时间从 30 分钟压到 3 分钟。完整的 A/B 挂进作业让学员回家跑。

### 5.6 进度幻觉仍是全课最重的一页
它是唯一**骗过验收环节**的机制：前四条骗的是 Agent 自己（东西是坏的，你迟早发现），第五条骗的是你——你读了一份漂亮总结就签收了。

所以它单独享有：深色配色 + 「最危险」标记 + 一份老师预录的真实样本（它说"测试已通过"、你自己跑是红的）。这份样本是**课前必备素材，现场几乎不可能稳定复现**。

### 5.7 延续 Vibe Coding 口径
全程不教命令、不教参数。本节的三个动作是**看（认症状）、查（定机制）、改（下处方）**——全是 Agent 替不了你的判断。

### 5.8 番外「让它少说点」：唯一触及设置的一段，且只讲判断不讲参数
学员反复问「它话太多 / reasoning 太长」，这是真实痛点，不该回避。但它跟 §5.7 有张力，所以按三条约束处理：

1. **挂到主干上，不当杂项**：话越多 → context 涨得越快 → 压缩来得越早 → **机制②提前发作**。所以它是处方级内容，不是闲聊。
2. **只讲判断，不讲参数名**：核心是让学员分清**三种「太长」**（思考过程 / 回答正文 / 写出来的文件），并纠正一个高频错误——**用「调低思考」去治「回答啰嗦」，结果是变笨了但话没变短**。具体设置各家工具叫法不同、版本更新快，一律「以你上课当天试出来的为准」。
3. **口头段，不配 slide**：deck 上没有这一页；白板写几个字即可。**时间紧第一个砍**（挪课后答疑）。

**caveman 必须连坑一起讲**：只教「压成电报体」不教「约束不能省」，学员回去会自己造出机制③和④。判断线是「caveman 该省客套，不该省约束和判据」，过头信号就是打断信号第一条（它开始猜）。收口一句：**短不是目标，信息密度才是。**

> 讲稿见 `RUNSHEET.md` §11；速查卡见其附录 B。

## 6. 课堂最终产物

每位完成者应有：

- 一张**填完的诊断单**：症状 → 机制 → 处方，三栏齐全（练习填前两栏，学完处方补第三栏）。
- 一份**症状 → 机制反查表**（老师发，学员带走当工作时的速查卡）。
- 一份**任务交付单模板**（目标 / 边界 / 验证点 / 里程碑）。
- **定位三问**能背下来。
- 一句话能说清：**我上次那个翻车，是五条里的哪一条，下次我改哪一处。**

## 7. 90 分钟流程

| 时间 | 阶段 | 课堂动作 | deck 页 |
|---|---|---|---|
| 0–8 min | 开场 · 这不是运气 | 钩子（两次差很远）+ 今日地图（问题 → 定位 → 改） | P00–P02 |
| 8–22 min | 地基：它到底怎么运转 | 模型+工具+循环 / 四拍 / 停止条件 / **它没有记忆只有 context** / 三种抱怨一种病 / SoT 收束 / context 不均质 | P03–P09 |
| 22–44 min | **① 会遇到的问题** | 五条机制总览 + 逐条讲（每条：机制 → 症状 → 投屏案例片段） | P10–P15 |
| 44–49 min | 休息 | — | — |
| 49–58 min | **② 怎么定位** | 定位三问 + 症状 → 机制反查表 | P16–P17 |
| 58–61 min | 定位演示 | 投屏一次真实跑偏，老师现场走一遍反查（含 A/B 预录对照） | P18 |
| 61–71 min | **现场诊断练习** | 发跑偏记录（RUNSHEET 附录 A 可直接用），填诊断单**前两栏** + 讲评 | P19 |
| 71–84 min | **③ 怎么改** | 机制 → 处方总览，然后五个处方逐条 | P20–P26 |
| 84–88 min | 番外 · 让它少说点 | 三种「太长」+ caveman（**口头，无 slide**，见 §5.8） | — |
| 88–90 min | 回填 | 回去把诊断单**第三栏**（处方）填上 | P19 复看 |
| 90–94 min | 收尾 | 小结 + 作业（含完整 A/B）+ 预告 L7 | P27 |

> 节奏提示：**「① 会遇到的问题」是全课最长的一段（22 分钟），也是痛感来源，别赶。** 「③ 怎么改」的七页都是处方页、不是新概念，每页 2 分钟足够——学员在①②已经被铺垫好了。
>
> 含番外合计 94 分钟，略超 90。**番外是第一个可砍的**（挪课后答疑，或等有人问起再插入）——砍掉即回到 90 分钟。

## 8. 各阶段教学细节（要点）

### 地基段：只讲到够用（8–22 min）
四句话，讲完就走，不展开：

1. **Agent = 模型 + 工具 + 循环**。补全是"问题进去答案出来"；Agent 能自己决定下一步做什么。
2. **循环四拍**：读 context → 决定 → 执行拿结果 → 结果回灌 → 回到第一拍**重新读一遍**。重点在「重新读一遍」——它不是带着记忆往前走。
3. **停止条件里有个「它认为」**：它认为不用再调工具了，就停。它认为的对不对是另一回事。这三个字是机制⑤和铁律的源头。
4. **它没有记忆，只有 context**。于是三句抱怨变成同一种病，于是前五节所有 SoT 的物理作用被点破（系列收束页），于是「context 不是均质的」成为机制①的地基。

### ① 会遇到的问题（22–44 min）
先给**总览页**（五条一次摊开），再逐条。逐条的讲法固定为三拍：

1. **机制**：它内部发生了什么（一两句，不深挖）
2. **症状**：你在屏幕上会看到什么（这句要能让学员当场点头）
3. **案例**：投屏一段老师预录的真实片段

第五条（进度幻觉）讲完要停一下，把「前四条骗的是它自己，这条骗的是你的验收环节」说清楚，并投那份真实样本。

### ② 怎么定位（49–58 min）

**定位三问**——遇到任何异常，按顺序问这三句：

```markdown
1. 这件事现在在它的 context 里吗？
   → 往回翻：那条规矩/那个决定，最后一次出现在多久之前？
   → 命中：机制① 稀释 / 机制② 压缩

2. 它是在查，还是在猜？
   → 看它这一步的依据：有具体的文件、行号、命令输出，还是「应该 / 大概 / 我假设」？
   → 命中：机制③ 错误累积

3. 这句「完成了」，我自己验过吗？
   → 别读它的总结，自己跑一遍那个命令。
   → 命中：机制⑤ 进度幻觉
```

（机制④ 目标漂移不需要问——看 diff 大小就知道。）

**症状 → 机制反查表**（本节最实用的一页，学员要带走）：

| 你看到的 | 大概是哪条 | 先查什么 |
|---|---|---|
| 越到后面越不守规矩 | ① 稀释 | 那条规矩最后一次出现在多久之前 |
| 后半段风格断层 / 重踩已解决的坑 | ② 压缩 | 中间有没有发生过压缩 / 总结 |
| 每步都有道理，但整体方向错 | ③ 累积 | 往前找第一个「应该 / 大概」出现在哪一步 |
| diff 比预期大很多 | ④ 漂移 | 回看你的指令里有没有「顺便 / 一并 / 该修的都修」 |
| 总结全绿，自己跑全红 | ⑤ 幻觉 | 它说的那个验证，输出在哪 |

点破一句：**「它今天不行」不是诊断，是放弃诊断。** 上面每一行右边那一栏，都是三十秒内能查完的动作。

### 定位演示 + A/B 预录对照（58–61 min）
老师投屏一份真实跑偏记录，当场走一遍：看到什么症状 → 查右边那一栏 → 落到哪条机制。

紧接着投 A/B 对照（老师课前跑的两次）：

```text
A（裸交）：帮我把这个项目里的 xxx 重构一下，顺便该修的都修一修。

B（带交付单）：
目标：把 xxx 重构成 yyy。
边界：只动 src/xxx/ 下的文件，不要碰配置、不要顺手改别的模块、不要加新抽象。
验证点：每改完一个文件都要 typecheck 通过；全部改完 build 要过。
里程碑：先给我一份计划（改哪些文件、什么顺序、每步怎么验证），我确认后再动手。
```

并排给两组结果（时长 / 改了几个文件 / 验证红绿 / 有没有进度幻觉），然后点一句：A 那句话里「顺便该修的都修一修」，**就是机制④的许可证。**

### 现场诊断练习（61–71 min）
发跑偏记录（时间轴 + Agent 的自述 + 实际输出）——**现成材料见 `RUNSHEET.md` 附录 A**，学员填诊断单**前两栏**：

```markdown
| # | 我看到的症状 | 我判断是哪条机制 | 处方（学完 ③ 再回来填） |
|---|---|---|---|
| 1 |  |  |  |
| 2 |  |  |  |
| 3 |  |  |  |
```

讲评时**不问「对不对」，问「你依据哪一条症状」**——本节要练的是推理链，不是答案。

### ③ 怎么改（71–84 min）
先给**机制 → 处方总览表**（§5.2 那张），让学员看到一一对应关系，然后逐条展开处方。逐条讲法：这个处方治哪条机制 → 具体怎么做 → 一句为什么有效。

五个处方里有两个要讲透，因为最反直觉：

**计划先行为什么值钱**（治机制③）：改一段计划 5 秒——它列了五个文件，你说"第三个别动"；等它改完二十个文件才发现方向不对，改回来 40 分钟，**而且这四十分钟它踩的坑全留在 context 里继续影响它**。L4 让 Agent 先出 scaffold plan、L5 让它先起草 SKILL.md，你当时照做了，理由就是这个：**在最便宜的时候纠偏。**

**可执行验证 + 铁律**（治机制⑤）：
- ❌ 口头验证「你检查一下有没有问题」——它检查完还是它说的，你等于让被告自己当法官。
- ✅ 可执行验证——typecheck / build / 跑测试 / 截图 / curl。**能自动跑出红绿的，才叫验证。**
- 铁律：**它说「完成了」不算完成。** 那是它的停止条件，不是你的验收条件。**判据必须来自它之外。**

**落盘**（治机制①②）单独说一句，因为它直接回收全系列：context 会被稀释、会被压缩，**文件不会**。关键约束、决定、以及"为什么这么决定"，写进文件——这就是前五节所有 SoT 在做的事。加一条配套动作：**一次一件事**，别把五件事塞进一个会话。

### 回填（84–86 min）
让学员回到诊断单，把第三栏填上。这是全课的收口：**症状 → 机制 → 处方**一条链走完，学员手上有一份自己填的、可带走的东西。

## 11. 老师课前准备

v0.2 对老师素材的要求**比 v0.1 更高**——学员不动手了，所有案例都得老师拿出来：

- 🔴 **一份完整的裸交跑偏录屏**（最重要）。要能在里面指出至少三条机制。逐条讲机制时截片段用，定位演示时整段走一遍。
- 🔴 **一份进度幻觉样本**：它说「测试已通过」+ 你自己跑是红的，两个画面。现场几乎不可能稳定复现，**必须预录**。
- 🔴 **A/B 两次的真实结果**（课前跑好）：两段指令 + 两组数字（时长 / 改了几个文件 / 验证红绿 / 有没有幻觉）。
- 🔴 **诊断练习材料**：一份带时间轴的跑偏记录（Agent 自述 + 实际输出），要求里面**至少埋三条不同机制**，且难度递进（第一条明显、第三条要想一下）。
- 学员讲义三张纸：反查表 / 定位三问 / 交付单模板（+ 打断速查）。课前发。
- 诊断单空白表（三栏）。

## 12. 高频风险与课堂降级

| 风险 | 处理 |
|---|---|
| 学员没有痛感（没被坑过） | 开场钩子多花一分钟，请两位讲自己的经历；投屏案例顶上 |
| 诊断练习没人填得出 | 老师带着填第一条当示范，剩下两条学员自己 |
| 练习讲评变成对答案 | 只问「你依据哪条症状」，不判对错——练的是推理链 |
| 五条机制讲太快、学员没记住 | 这段有 22 分钟，是全课最长段，**不许赶**；宁可砍处方段的展开 |
| 有人追问参数怎么设 | 标准答复：今天讲的东西不靠设置（§5.7） |
| 课堂变成吐槽大会 | 每条抱怨必须落到一条机制上；落不上的记白板，课后查 |
| 时间不够 | 优先级：**五条机制（P10–P15）+ 反查表（P17）+ 诊断练习（P19）+ 处方总览（P20）+ 铁律（P24）** 必须保；地基段可压到 8 分钟，处方逐条可只讲计划先行和可执行验证 |
| 时间有余 | 加讲 A/B 对照的细节、或现场再做一份诊断 |

## 13. 作业

1. **翻你自己最近一次翻车**，填一张完整诊断单：症状 → 机制 → 处方。
2. 用**任务交付单**交一个真实任务（四格填全，边界和验证点不许空）。
3. 至少做一次**独立验证**——不看它的总结，自己跑一遍，记录跟它自述一致不一致。
4. **补做课上没做的 A/B**：同一个任务裸交一次、带交付单一次，记下时长 / diff / 验证红绿的差别。
5. 把你的**任务交付单做成一个 Skill**（回收 L5：重复 ≥3 次 + 结构固定 = 该 Skill 化），并调用一次。
6. 交一句话：**如果重来，我会在哪一步就拽住它。**

## 14. 官方依据与数据纪律

- **Agent = 模型 + 工具 + 循环**、循环的停止条件：Anthropic 官方 tool use 与 agent 设计文档。
- **context 管理的三条不同路径**（清理旧工具结果 / 压缩总结 / 落盘到会话之外）：官方 long-running agents 文档。本节只讲这三类**做的是不同的事**、各自会丢什么——**不讲参数、阈值、开关**。机制②「压缩保住了做了什么、丢掉了为什么」即出自此。
- **长任务的规格要一次给全**：官方长任务指南指出完整规格一次说清优于多轮挤牙膏补充。这是交付单处方的依据。
- **进度幻觉**（报告未经验证的进度）、**早停**、**范围膨胀**、**过度验证**、**context 焦虑**：均为官方长任务 / prompt 调优文档记录的真实行为模式与对策方向。机制⑤和铁律出自此。
- **数据纪律（不变）**：deck 上**只讲机制类别与判断线，不引任何与模型版本绑定的行为描述、参数名、阈值或跑分**——这类信息讲完就过期，而且会把课程变成「背配置」。判据是：**换个模型、换个工具也成立**的才留。
- **v0.2 的素材纪律（新增）**：学员不动手了，案例全靠老师预录，所以 deck 上出现的示例数字（时长 / 文件数 / 测试失败数）都是**示意性占位**，老师投屏时用自己真实跑出来的数据。P11 的「服从程度」用定性档位（守 / 基本守 / 开始飘 / 不守了），**不编百分比**。
