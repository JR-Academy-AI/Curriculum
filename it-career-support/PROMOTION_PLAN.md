## 0. 先说这份计划最大的前提问题：这门课现在到底在不在正常招生

这不是走个流程的免责声明，是这份计划能不能真正执行下去的第一个卡点。

`curriculum/it-career-support/public/prod-state.json` 这个文件不存在。这个文件是 Skills Data Manager（内部叫 SDM，是本地内容和 production 数据库之间做同步比对的工具）跑完一次同步后留下的本地快照缓存。它不存在，**不代表课程没上线**——`production-ids.json` 里有真实的 `trainingId: 6510338e4e6d79002bf31ee1`，销售页 `https://jiangren.com.au/program-course/it-career-support` 能正常打开，早鸟价 A$90+GST / 正价 A$199+GST 都是从销售页真实抓取的（来源见 `PERSONAS.md` 第 0 节，2026-07-03 抓取）。这一点 `FUNNEL_PLAN.md` 已经讲清楚了，这里不重复论证。

但这份 PROMOTION_PLAN 要处理一个 FUNNEL_PLAN 没深挖的问题：**这门课已知的两次开班——Cohort 1（2024-01-14）、Cohort 2（2024-06-26）——距今已经两年了，本次调研没有找到任何 Cohort 3 或者"现在是滚动招生（随时报名随时开始自学，只有 11 次直播 Group Tutorial 需要凑批开班）"的证据。** 换句话说，现在有两种可能，这次调研没法替运营拍板是哪一种：

1. 这门课已经从"按 Cohort 开班"切换成了"随时报名、自学为主、直播另行安排"的持续销售模式——如果是这样，这份计划里所有"倒数第 N 天"的开班时间轴逻辑都要改成"常青（evergreen）推广"逻辑，不是一次性冲刺。
2. 这门课其实已经停止主动招生，销售页还挂着只是因为没人下线——如果是这样，在没人拍板"要不要重新启动"之前，启动任何一条渠道任务都是在浪费团队产能。

本地还有一条辅助证据支持"这门课的自动化链路从没走完过一整圈"：`production-ids.json` 里 `programs` 字段是 `{"1": "651bbdefe05bd70070ec3d1d", "2": "65ae20f032b918002c416120", "3": null}`，而且这份文件顶部 `meta.lastSyncedAt` 和每一条 lesson 的 `syncedAt` 全部是 `null`。这说明本地曾经准备过 Program 3（第三期）的同步位，但从没真正写入过，同时整份映射文件本身可能也从没跑完一次真正的同步。这不能证明"没有 Cohort 3"，只能证明"这门课的本地工具链记录不完整，不能拿它反推真实招生状态"。

**所以这份计划的第 4 节时间轴第一条任务，必须是"找运营/课程主理人确认这门课现在的真实招生状态"，不是直接冲小红书选题。** 下面第 1-3 节（定位摘要、目标反推、渠道矩阵）可以先写，因为它们是"如果要推广，该怎么推"的方法论准备，不依赖具体开班日期；但第 4 节时间轴里除了这条确认任务之外，其余全部标"⏸ 待确认招生状态后启动"，不能假装已经有一个确定的开班日在倒数。

## 1. 课程定位摘要

> 详细 persona / 痛点原话 / 异议都在 [`./PERSONAS.md`](./PERSONAS.md)，这里只抽最关键的几条，用来指导下面的渠道和文案方向。

**主推内容角度**（按证据扎实程度排序，不是按销售页自己怎么写排序）：

1. **内推 / 人脉入口，权重最高**——这是这次调研里唯一有两条互相独立来源印证的洞察。新足迹论坛上认可这门课价值的用户 tk0007 说的是"几千块钱能换回人脉和下一份工作入门资格，我觉得也是值得的"；V2EX 另一条独立帖子里的用户说"如果没有内推，可能真的没有 HR 联系你们"。两个不相关的渠道、两个不认识的人，说的是同一件事：**这批用户愿意为"帮我连上人脉/拿到内推入口"付费，不是为"教我技术"付费**。所以推广文案的核心钩子应该是"怎么进圈子"，不是"教了多少节课"。
   `[来源: PERSONAS.md Persona B 购买触发器]`
2. **具体、可执行的求职方法，不是"市场很难"的科普**——V2EX 帖子里的用户已经自己总结出了三条具体经验（身份是敲门砖 / 没内推 HR 不理你 / 面试听力要流畅不是要口音标准），这说明这批人已经知道市场难，缺的是"怎么把这几件事具体做到"的执行帮助。文案如果还在讲"澳洲 IT 市场竞争激烈"这种大道理，对这批人是废话，他们已经过了这个阶段。
   `[来源: PERSONAS.md Persona B 痛点 Top 3]`

**明确不要用的角度**（这条不是"权重低"，是"用了会反噬"，所以单独列，不混进上面的正面清单）：

- ❌ **"零基础转行拿大厂 offer"的案例包装**。新足迹上三位独立用户（hxsh2000 / ろげん / cherubickid）公开质疑过这类案例，说实际上多数人本来就有 IT 学位或相关背景，是被夸大的营销叙事。这条质疑就挂在讨论"匠人学院"这门课本身的帖子下面，不是泛泛而谈——是有真人在质疑我们自己。继续拿这个角度做主打卖点，等于往一个已经被公开戳破的坑里跳。销售页当前的 `suitable` 字段写着"转行 IT 新手"是这门课卖点之一，这不是说要把这类用户从目标人群里删掉，而是**推广素材不要用"看，他零基础也成功了"这种案例展示去吸引他们**，换成上面第 1 条"内推入口"或第 2 条"具体方法论"的角度更站得住。
   `[来源: PERSONAS.md Persona C]`

**One-liner**（只有中文站，这门课没有英文版素材，见 `PERSONAS.md` 第 0 节语言范围说明）：
- 中文：**"不止教你写简历，帮你搞懂内推怎么找、为什么没内推 HR 根本不会理你。"**——这句话直接对应上面第 1 条最扎实的证据，没有承诺具体结果（不说"包拿 offer"），符合 skill 红线。

**目标人群**（从 `PERSONAS.md` 抽，按证据强度排序，不是按销售页写的顺序）：
- Persona A — 纠结留澳还是回国的应届 IT 求职者（有 V2EX 真实求助帖印证）
- Persona B — 已在澳洲但进不了内推圈子的求职者（两条独立来源互相印证，四个 persona 里证据最硬）
- Persona C — 销售页宣称的"转行 IT 新手"（⚠️ 证据薄弱且有真实用户公开质疑，不建议作为推广主打对象，见上）
- Persona D — 想晋升的在职初中级开发者（⚠️ 完全没有独立证据，纯粹沿用销售页文案）

**售价档**（从 `FUNNEL_PLAN.md` 复制，目前只有一档，不是三档）：
- 正价：A$199 + GST
- 早鸟：A$90 + GST
- ⚠️ 教学版 / 陪跑版目前都只是方向性提案，价格待定，不能写进任何对外文案（详见 `FUNNEL_PLAN.md` 第 3.2 节）

**承诺红线**（不可写进任何推广文案的内容，公司统一红线 + 本课专属一条）：
- ❌ 月入 X 元 / 副业收入 / 接单变现
- ❌ 包就业 / 拿 offer / 入职 N 大厂
- ❌ **本课专属**：不承诺"帮你拿到内推"这个具体结果——第 1 条内容角度讲的是"这门课能帮你搞懂内推怎么找、连上圈子"，这是过程和资源承诺，不能滑成"我们保证给你内推"这种结果承诺，两者一线之隔，写文案的人要注意分寸
- ✅ 只承诺：方法论 / 练习机会（31 节互动 Lab）/ 模拟面试和薪资谈判演练（Group Tutorial）/ 学习社群

## 2. 目标与漏斗反推

> ⚠️ 这一节按 skill 模板要求写出反推公式的骨架，但**所有 N 值目前都是空的**，不是因为偷懒不填，是真的没有可以填的数字：没人告诉我们下一期目标招多少人，甚至不确定"下一期"这个概念现在成不成立（见第 0 节）。硬填一个数字会被下游当真，比留白更危险。

```
报名目标：N 人（目前只有单一价格，不分自学/教学/陪跑三档）
  ↓ 主课转化率：⚠️ 待补——没有这门课历史两期的真实转化数据
引流课页面/试听转化目标：⚠️ 不适用——引流课还没正式立项（FUNNEL_PLAN.md 第 4 节只是方向假设）
  ↓ 各渠道流量分摊：⚠️ 待补——见下方渠道矩阵，只能先定"用哪些渠道"，定不了"每个渠道要扛多少流量"
```

**这一节唯一能现在确定的事**：`PERSONAS.md` 第 3 节已经指出，这批用户里至少 A、B 两类会**主动搜索"这个机构怎么样"**做决策参考（新足迹那条讨论帖的楼主原话是"今天搜到这个"）。这意味着，在算流量分摊之前，更该优先做的一件事是**确保搜到我们的时候看到的是正面/可信的信息**，而不是先假设一个渠道配比。第 3 节渠道矩阵会把这一条落到具体渠道选择上。

**下一步要拿到这些数字才能把本节填完**（跟 `FUNNEL_PLAN.md` 第 5 节、`PERSONAS.md` 第 6 节是同一个卡点，不是重复的待办）：
1. 这门课过去两期的真实报名人数、早鸟价转化率——运营/销售系统数据。
2. 这两期学员当初是从哪个渠道知道这门课的——这个数据一旦有了，能直接把下面渠道矩阵里"哪个渠道优先"从"基于论坛证据的合理推断"升级成"基于真实转化的排序"。

## 3. 渠道矩阵

> 每门课至少 5 个渠道，少于 5 个 → 流量结构脆弱、单点失败就崩盘（skill 通用红线）。但这里先说清楚一个前提：`COURSE_TYPE_PLAYBOOKS.md` 给 Type 1 课程的默认配置是"小红书 12 篇/周 × 8 周"这种满配打法，那套配置是给客单价 ¥2980-9800、团队专门为这一门课配置资源的旗舰课设计的。**这门课客单价只有 A$90-199，且没有证据显示公司会为它单独配一份满编营销资源，硬套满配等于用旗舰课的成本打一门引流课价位的产品，性价比不成立。** 所以下面渠道选择的逻辑是：先看 `PERSONAS.md` 里有没有真实证据支持这个渠道对这批人有用，再看资源消耗跟这门课的客单价配不配，两条都满足才排进"✅ 启用"。
