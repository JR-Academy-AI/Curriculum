# Vibe Coding 大师课（ai-builder）付费漏斗规划

> 维护人：Claude（本次规划）| 最近更新：2026-07-03
> 单一真相文档 —— 这门课任何漏斗 / 定价调整都改这里，不要在别处另起一份。
> 前置依赖：`curriculum/ai-builder/PERSONAS.md`（2026-07-03 重写版，ground truth 覆盖率约 0.28）。本文档的定价节奏、引流课设计、7 天过渡序列全部锚定这份画像文档，画像里标"⚠️ 待补"的地方，这里也只能给占位提案，不能假装有依据。

**先说清楚这门课现在到底是怎么卖的，因为这直接决定这份文档的性质**：ai-builder 不是一张白纸课程，是已经真实开了两期、正在招第三批人的课（01 期 2026-01-10 开课、02 期 2026-06-28 开课，写这份文档时刚开课 5 天）。但它**现在只有一个价格档位在卖**——没有自学/教学/陪跑三档，也没有引流课。所以这份文档不是"记录现状"，是**提议一套新漏斗**：要不要把现有单价课拆成阶梯、要不要加一个低价引流课，这是需要课程负责人拍板的产品决策，不是这次调研就能替你定的事。下面每一处提议价格都会标清楚"这是真实在卖的价格"还是"这是本次规划的占位提案"，两者绝不混着写。

## 1. 漏斗定位

| 项 | 内容 |
|---|---|
| 主课方向 | Vibe Coding 全栈 AI 开发能力升级——教的是把 Claude Code / Cursor / Codex 这类工具用出工程化水准，不是"转行拿 offer"的求职课。这条边界在 PERSONAS.md 第 4 节写得很清楚：想要保 offer / 保涨薪承诺的人应该导向 Alex 的 AI Engineer 求职课，两门课刻意分市场池子，不要在同一批人身上抢 |
| 主课时长 | 8 周，当前维护的主大纲（`outline.json`）是 111 节课、21 场直播、32 个 Interactive Lab，估计学时 107.3 小时，分 4 个 Phase：Phase 1 入门 & 个人 AI OS（33 节）/ Phase 2 Skills·MCP·Agent 架构（36 节）/ Phase 3 自动化替你干活（16 节）/ Phase 4 企业记忆系统 & 云端交付（26 节）。这是从 `outline.json` 直接读出来的字段，是真实数据，不是估的 |
| 目标用户 | 首轮核心是 PERSONAS.md 的 Persona A（在职华人开发者）和 Persona B（技术创业者/独立开发者），C（留学生）D（转码毕业生）是副线。这四个 persona 目前 ground truth 覆盖率只有约 0.28，也就是说四成不到的字段有真实数据撑着，六成多还是团队经验判断——下面凡是引用 persona 数据做定价/节奏依据的地方，都会标出这条数据本身扎不扎实 |
| 业务模式 | 现状最接近 skill 模板里的"没有模型"——比 A/B/C/D 四个选项都更原始：单一价格 $880 AUD，没有三档，没有引流课，靠内容本身和口碑招生。这份文档提议把它升级成**模式 A（完整四档：引流课 + 主课三档）**，理由见下面"为什么现在是合适时机" |
| 引流课形态 | 提议用**形态 1（单引流课）**，不是形态 2（多引流课）。理由：形态 2 适合"主课覆盖多个独立、可以任选入口的模块"，但 ai-builder 的 4 个 Phase 是递进关系（先搭个人 AI OS，才谈得上 Agent 架构和自动化），不是并行可任选的独立方向，硬拆成 4 个引流课没有意义。另外 PERSONAS.md 的 ground truth 还不够支撑"针对不同 Phase 设计不同引流课分别打不同 persona"这种精细化操作——现在连 A/B 两个核心 persona 的决策周期都是空的，谈不上分模块打法 |
| 核心承诺 | 借用课程官方文案（`outline.json` `courseObjective` 字段，真实数据）："建立从个人到企业的 AI 操作系统：用 Source of Truth 把你的经验/规范结构化成 AI 可读的第二大脑，用 ADLC 把整份 PRD 交给 Agent 端到端开发并部署，把重复流程交给 Agent 自动跑，最终能同时指挥多个 Agent 并行工作。"（ADLC = Agent Development Lifecycle，课程自造的方法论名词，意思是"把一个完整需求交给 AI Agent 从头到尾自己开发完，而不是人工拆成一个个小任务喂给 AI"）|

**为什么现在是升级漏斗的合适时机**：这次给 PERSONAS.md 做调研时找到了一条以前没有的真实数据——V2EX 帖子 `t/1224040`（「有没有推荐的 AI vibe coding 培训班啊」）下面几条真实回复，核心态度是"报班学 vibe coding 等于智商税，自己摸索就行"。这条异议如果不正面处理，会一直是这门课转化率的天花板，因为它质疑的不是"这门课好不好"，是"要不要花钱学这件事本身"。低价引流课刚好是回应这条异议最直接的办法——与其在销售页上反驳，不如让人先花小钱亲手做出一个东西，自己判断"这是不是我自己摸索能摸出来的水平"。这是这份漏斗提案的核心逻辑，不是照搬模板。

**自学版的一个明确风险，也写清楚**：现在只有一个价格档位时，想买这门课的人只有"买 $880"和"不买"两个选择。一旦推出更便宜的自学版，一部分原本会买 $880 教学版的人可能会改买更便宜的自学版——这是真实的产品风险（价格阶梯会分流高价档位），不是这份文档能替你判断值不值得，需要课程负责人权衡"多卖低价获客"和"教学版销量被自学版吃掉"这两头。

## 4. 引流课（提议方案）

> 全新方案，现在不存在。价格、主题、时长都是提议，需要内容团队实际产出脚本和 Lab 才能真正上线。

- **主题**：「1 小时上线一个 SSO 登录——AI Coding 及格线自测」
- **为什么是这个主题（不是随便挑的）**：课程自己的官方文案（`outline.json` `description` 字段，真实数据）里有这样一句话："衡量标准很简单——一个 LinkedIn / Google / GitHub 的 SSO 登录功能，你能不能一小时内从零做完上线。做不到，就还没入门。"这句话本身就是公司自己定的能力及格线，不是营销话术编出来的钩子。用这个当引流课主题有两个好处：第一，它把"这门课到底教什么水平的东西"具体化到一个可以自己验证的动作，而不是一句空话；第二，它正面回应了 PERSONAS.md 里那条最扎实的异议"报班等于智商税，自己摸索就行"——让人先花一小时亲手试试这个及格线，能做到的人大概率确实不需要报班（这门课也不该硬留他），做不到的人自己就有判断依据，比任何销售话术都有说服力
- **时长**：约 90 分钟（讲解 + 实操跟做）
- **定价**：$29 AUD / ¥99 CNY —— 沿用 skill 给的默认基线，不做偏离。理由：这批用户（PERSONAS.md 里明确写着"对报班本身持怀疑态度"）需要的是低风险试错，不是"贵一点显得更专业"，没有任何数据支撑往上调价，调价反而可能加重"这又是一个收割"的第一印象
- **Quick win 交付物**：一个能真实跑起来的 SSO 登录 demo（用 Claude Code / Cursor 实操做出来），加上一份诚实的自我定位反馈——用公司自己那条及格线告诉学员"你现在在及格线的哪一侧"，不是无脑说"你很棒快来报名"
- **在主课大纲中的对应位置**：Phase 1（入门 & 个人 AI OS）范围内的一个知识点浓缩版，学完引流课的人如果决定继续，Phase 1 剩下的 33 节课和后面 3 个 Phase 都是自然延伸，不需要重新适应课程节奏

## 5. 过渡 7 天序列（提议方案）

> D0-D7 的天数结构是 skill 模板的默认节奏，**不是**根据这门课用户真实决策周期定的——PERSONAS.md 里 Persona A/B 的"决策周期"字段都还是"⚠️ 待补"，没有真实数据支撑"7 天"这个具体数字。如果后续拿到 01 期学员反馈或咨询记录，发现真实决策周期明显偏长或偏短，这个序列的天数要重新调整，不要把 7 天当成验证过的结论。

| 时间 | 内容 | 为什么这么安排 |
|---|---|---|
| D0（引流课交付当晚）| 发 SSO demo 教程 + 自我定位反馈，**不推销** | 先让人自己判断水平，硬推销会撞上"割韭菜"那条负面认知，第一晚建立信任比赶着报价重要 |
| D1 | 分享一段真实的行业焦虑内容——比如"AI 写的代码谁来兜底、团队开始管不住 AI 生成的代码"这类真实存在的讨论（V2EX 上确实有真实热帖在聊这个，但引用时要注意这只是"这类话题有热度"的间接证据，不能包装成"这就是你的处境"） | 回应 PERSONAS.md 里"AI 写的代码谁来兜底"这条真实存在的社区焦虑，做的是共情不是推销 |
| D2 | 展示 Phase 1 剩余内容的具体片段——比如"个人 AI OS 怎么从你自己的经验里搭出来"的实操截图或短视频 | 直接回应"自己摸索就够了"这条核心异议：如果引流课只重复"AI 能加速写代码"这种网上到处都是的内容，异议会更强化；只有展示课程里真正结构化、市面教程少见的部分（ADLC 方法论、PRD 转 Agent 端到端执行），才是"自己摸索摸不出来"的真实证据 |
| D3 | 01/02 期真实学员产出案例（匿名化）| **这一步现在做不了**——需要课程运营/教务去要 01 期学员的真实毕业项目和反馈，这次调研工具够不到内部系统，只能标"待补"。在拿到真实素材前，D3 这天先跳过或者用 D2 的内容顶替，不要编一个假案例填空 |
| D4 | 开放答疑/Q&A，收集具体犹豫点 | 这一步除了转化，还有个额外价值——顺手把学员真实的犹豫点记下来（脱敏后进 CRM 或问卷），这正是 PERSONAS.md 第 6 节列出的"决策周期"和"异议 2-3 条"唯一可能补上的数据来源，做完这轮之后应该回头 refresh 一次 PERSONAS.md |
| D5 | 第一次正式亮出三档定价 + 说明差异 | 不在 D0 就报价，等到信任建立得差不多、异议也回应过一轮之后再谈钱，转化会比一上来就推销价目表更自然 |
| D6 | 提醒当期真实的开课时间/名额情况 | 只能陈述真实存在的开课节奏（比如"03 期 X 月 X 日开课"），**不能编造"仅剩 X 个名额"这类不存在的紧迫感**——这是 CLAUDE.md 反造假红线，也是这类对"割韭菜"敏感的技术用户最容易识破、也最容易因此彻底拉黑的套路 |
| D7 | 转化锚点，开放报名链接 | 序列走到这里该说的都说完了，直接给转化路径，不需要再堆一层话术 |

**反推销红线（不可违反）**：全程不承诺涨薪/转岗成功/接单收入，不用"副业"这个词，只承诺过程结果——做出可上线的作品、掌握一套可迁移的工作流、达到公司自定的及格线。这条和 CLAUDE.md 的课程承诺红线、`course-funnel-architect` skill 的红线是同一条规则，此处不重复展开。
