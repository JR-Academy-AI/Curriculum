# W1 教案 · 从“我想做点什么”到“有人愿意付钱” | Find a Problem Worth Solving

> 周日 14:00–17:00（3h）· 线下主场 + 卫星教室 + 同步直播。
> 大纲真相源：`COURSE_REDESIGN.md` / `public/outline.json`（lesson `L02`）。

## 0. 这节课到底要达成什么

**一句话目的**：把一个模糊 Idea 变成一张可以拿去找真人验证的创业机会卡，先证明问题值得解决，再决定做产品、公司还是服务。

### 现场过关线

| # | 产出 | 验收标准 |
|---|---|---|
| 1 | **创业机会卡 Opportunity Card** | 6 个字段写清：目标用户、问题、现有做法、方案缺口、初步方案、本周验证动作 |
| 2 | **一句可复述的问题** | 同学能复述“谁在什么场景遇到什么麻烦”，而不是只记住产品名 |
| 3 | **本周验证承诺** | 访谈 5 人、收集 3 个真实案例、找到 3 个竞品，并询问付费意愿 |

W1 不以写代码、搭网站、接通 Gmail / Calendar / Drive / Notion 或“跑满 5–7 个任务”为现场门槛。第一节先保证所有人找到一个足够具体、可以被真人证据推翻的问题。AI OS 只作为记录、研究和执行工具，不是第一节课的主角。

## 1. 先纠正创业起点：Idea 不是起点，Problem 才是

开场 20 分钟先拆七个常见错误：

1. 先想产品，再找用户；
2. 觉得用了 AI 就叫创新；
3. 一开始就想做平台；
4. 用户群体定义得太大；
5. 把自己的兴趣当成市场需求；
6. 还没访谈用户，就开始写代码；
7. 认为产品上线后自然会有人使用。

错误表达：**“我想做一个 AI 求职平台。”**

更好的表达：**“澳洲留学生申请 Graduate Program 时，每个岗位都要重复修改简历和 Selection Criteria。”**

课堂使用两个有一手来源的真实起点，不编成功故事：

- **Canva 前身 Fusion Books**：Melanie Perkins 先看到老师用难学的桌面设计软件制作校刊、往往耗费数百小时，于是把范围缩到澳洲学校校刊；第一位客户支付了 100 澳元订金。来源：Canva Newsroom 创始人回顾。
- **DoorDash 前身 PaloAltoDelivery.com**：创始人当时并不知道课堂项目能否成为公司，先用不到 10 美元的域名开始，并亲自完成第一单配送、获得配送报酬。来源：DoorDash 2024 Q4 股东信。

## 2. W1 最终产出：创业机会卡

机会卡回答 6 个问题：

1. **目标用户是谁**：不能写“澳洲中小企业 / 留学生 / 想学 AI 的人”。要具体到“在澳洲经营 1–5 人装修公司的老板”“毕业半年内、准备回国找工作的澳洲留学生”“每周需要制作大量短视频的小型教育机构市场人员”。
2. **他们遇到什么问题**：使用句式“当 ______ 发生时，______ 类型的用户很难 ______，导致 ______。”
3. **他们现在怎么解决**：Excel、微信、人工助理、ChatGPT、现有软件，或者根本不解决。
4. **为什么现有方案不好**：太贵、太复杂、不适合澳洲市场、不支持中文、数据分散、需要大量人工操作，或没有行业工作流。
5. **初步解决方案**：只写一句“我们帮助 ______，通过 ______，实现 ______。”AI 必须落到更快、更便宜或更简单的具体变化。
6. **本周验证动作**：访谈 5 个潜在用户、收集至少 3 个真实案例、找到 3 个现有竞品、验证是否有付费意愿。

问题示例：

> 当澳洲小型装修公司同时接多个项目时，老板很难及时整理客户电话、报价和工人安排，导致漏单、重复沟通和项目延期。

方案示例：

> 我们帮助澳洲小型装修公司，通过 AI 电话记录和报价草稿，减少客户跟进与行政工作。

## 3. Opportunity Card 为什么同时是 SoT v0.1

**SoT（Single Source of Truth）= 这门生意目前唯一算数的一页说明书。**

它不是：

- 十页商业计划书；
- “AI 帮企业提效”这种无法执行的口号；
- 写完永远不改的承诺。

它先解决项目管理的四个问题：

1. **优先级**：每个任务必须服务于当前客户、问题或交付假设；
2. **统一口径**：报价、网站、访谈、AI 提示词与交付流程都读取同一版；
3. **人机边界**：AI 能做什么、必须由谁检查、哪些决定禁止自动化；
4. **变更管理**：只有新证据改变了客户、问题、交付、边界或验证标准，才更新 SoT。

每周闭环固定为：**读当前 SoT → 只选一个任务 → 执行并人工检查 → 留下客户证据 → 决定要不要更新 SoT**。任务从 SoT 出发，证据回到 SoT；AI 新生成一份文案或创始人突然想到新功能，都不等于方向已经改变。

W1 的 Opportunity Card 就是 SoT v0.1：这一周只有这一版客户、问题、现有做法、方案缺口、初步方案与验证动作算数。进入执行阶段后，再补 AI / 人的边界与不做清单。

三个检查：同学能不能复述谁在什么场景遇到什么问题？这周的动作能不能带回真人证据？新证据能不能让你继续、修改或停止？W1 形成待验证假设，下周带证据回来更新。

### 现场理解测试

学生先选答案并说理由，再翻答案页：

1. 访谈证据缩小了真正愿意付费的客户范围 → **更新 SoT**；
2. AI 只是生成了一条新文案，经营方向没变 → **不更新 SoT**；
3. 创始人想到一个未经客户验证的新功能 → **记入待验证清单，不直接改 SoT**；
4. 客户明确拒绝 AI 自动发送邮件 → **更新初步方案，加入必须人工检查的边界**。

## 4. 课前准备

### 学员

- 笔记本和一个可用的 AI 对话工具；不强制 API Key 或付费订阅；
- 带来一个想解决的问题。没有方向也可以，课堂从两个模拟案例中选一个练习；
- 不要上传客户名单、私人邮箱、合同、财务或身份资料。

### 讲师 / 助教

- 投屏 deck、SoT 一页模板、反馈卡；
- 打印两份课堂模拟案例；
- 准备一个不含真实客户资料的 AI 演示工作空间；
- 卫星教室与直播测试；Founder Exchange 的私密分享范围由学员本人决定。

## 6. 两个商业案例

> 两例均为**课堂模拟 / 合成场景**，不是对真实公司的事实陈述。案例中的访谈数、试点数和收费方式都是待验证目标，不是已经取得的成绩。

### 案例 A：现有会计服务的经营改造

| 机会卡字段 | 课堂答案 |
|---|---|
| 目标用户 | 澳洲 5–20 人的 bookkeeping / accounting firm，可从行业协会与现有人脉列出 5 个访谈对象 |
| 问题 | 当月末资料不齐时，员工很难快速知道缺什么、谁来补，导致反复追问和关账延期（待验证） |
| 现在怎么解决 | 员工翻邮件和附件，用 Excel 手工列缺失项，再逐个联系客户 |
| 为什么不好 | 资料分散、重复复制、容易漏项；实际花多少时间和返工多少，目前 unavailable |
| 初步方案 | 帮助小型事务所用 AI 归类脱敏附件并起草缺失清单，由专业人员复核后联系客户 |
| 本周验证 | 访谈 5 家、收集 3 次追资料案例、比较 3 个工具，并询问是否愿为改进后的服务付费 |

讲师追问：客户为什么会买“少追一次资料、少返一次工”，而不是买“AI 很厉害”？哪些文件不能直接交给公共 AI 工具？

### 案例 B：物业维修工单助手

| 机会卡字段 | 课堂答案 |
|---|---|
| 目标用户 | 管理约 100–500 套住宅、没有专职维修协调团队的独立 property manager |
| 问题 | 当报修资料散在邮件和短信里时，经理很难一次收齐可分派信息，导致反复追问和漏单（待验证） |
| 现在怎么解决 | 在电话、短信、邮件和表格之间人工复制，再凭经验分派 |
| 为什么不好 | 资料分散、重复追问、依赖个人经验；漏单率和工时当前 unavailable |
| 初步方案 | 帮助独立物业经理用 AI 整理报修信息并起草工单，由经理批准紧急等级、供应商和费用 |
| 本周验证 | 访谈 5 位经理、收集 3 个工单案例、比较 3 种替代工具，并询问是否愿意付试点费 |

讲师追问：真正可卖的是“更快生成工单”，还是“减少来回追问和漏单”？哪些决定必须由人承担？

### 两例拆完后的四个判断

1. 客户是否具体到能找到五个人？
2. Job 是否写客户在特定情境下想取得的进步，而不是偷塞产品功能？
3. 现有替代、非消费与代价能否观察；AI 是否只负责可检查的一段？
4. 6 周证据是否可能推翻这个想法？如果永远不会被推翻，就不是验证标准。

## 7. Founder Exchange（30 分钟）

三人一组，每人 8 分钟，最后 6 分钟写反馈。

1. 本人用 90 秒念 Opportunity Card；
2. 同伴不看纸复述“谁在什么场景遇到什么问题、现在怎么处理”；
3. 只问三类问题：你在假设什么？谁能证明或推翻？下周最小动作是什么？

每人反馈卡只交一条：

> 我原本准备 ______；因为同伴指出 ______；所以下周先改成 ______。

交流的目标不是夸点子，也不是现场强制组队。目标是发现表达和证据链中最薄的一环，并找到可能提供访谈、行业信息或引荐的人。

## 8. AI 只帮助准备验证，不替代用户证据

### 最小配置

- 一个独立工作空间 / Project；
- 一页 Opportunity Card / SoT v0.1；
- 一条规则：事实与假设分开，不能确定就标“待验证”，遵守“不做清单”。

讲师发放本周包：`opc-founder-os` + `opc-business-sot`。学员在自己的 Founder Workspace 里运行：

> 请使用 `$opc-business-sot`，帮我把这张创业机会卡整理成 SoT v0.1。逐项问我，不要替我编客户证据；不确定的内容写“待验证”。

本周只发 Business SoT Skill；后续 Skill 按周发放。生成的文档状态只是 `drafted`，同伴复述和真实任务跑完才是 `executed`，达到本节过关线并完成规定 review 才能记为 `verified`。

先让 AI：

1. 用三句话复述这门生意；
2. 列出它仍然不得不猜的地方；
3. 说出哪些任务越过了“不做清单”。

学员从下面三项选一项现场完成：

- **现有替代证据**：找 3 个可核验替代，必须包含“忍着不做”，区分事实、推断和未知；
- **用户访谈提纲**：写 5 个不诱导的问题，只问过去行为，再写一封透明、不伪装销售的邀请；
- **真实触达草稿**：给一个确实认识或能联系的人写邀请，不虚构关系、不自动发送。

验收不是“生成了很多字”，而是：屏幕上有输出；本人指出并修正一处错误；写下要补的下一条证据。对外发送、上传客户数据或授权邮箱都不是课堂要求。三种状态全课统一为 `drafted → executed → verified`。

## 9. 讲师 review 与收尾

讲师选 3–4 份 Opportunity Card，每份只改一个最影响验证的问题：客户找不到、问题偷塞产品、现有做法不可观察、方案过大、验证动作无法推翻想法。不要替学员重写整份商业计划。

17:00 前逐人确认：

- 同伴能复述具体用户和问题；
- 反馈卡写了“因此改什么”；
- 已写下 5 / 3 / 3 / 付费意愿验证承诺；
- AI 如参与，只能准备访谈、竞品研究或触达草稿，不能生成客户证据。

讲师必须补一句：**这里完成的是待验证机会卡，不代表市场需求成立。真人访谈可以让你继续，也可以让你修改或停止。**

## 10. 课堂红线

- 模拟案例必须始终标注“课堂模拟 / 待验证”，不能讲成真实公司成绩；
- 涉及会计、税务、物业安全和公司结构，只讲工作边界与验证问题，不给专业意见；
- 不要求学员展示客户隐私、雇佣合同或商业机密；
- 不用任务数量、连接器数量或自动化数量冒充学习结果；
- 第一节的成功标准是：目标用户更具体、问题可以被真人证据推翻、本周验证动作已经写清。
