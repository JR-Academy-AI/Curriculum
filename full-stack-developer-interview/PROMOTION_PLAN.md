### 0.1 为什么是 Type 9，不是硬塞进 Type 1/2/5/7

`COURSE_TYPE_PLAYBOOKS.md` 的跨类型决策树走一遍会卡住，不是漏判，是这门课本身就不是标准形态：

- **目标人群像 Type 1**（求职转型）——PERSONAS.md 三个 persona 里 A（应届生找第一份工作）和 C（在职想跳槽）都是"要结果"的求职者，不是 Type 2 那种"不换工作只想提效"的在职人群。
- **但客单价和周期完全不是 Type 1 的量级**——Type 1 基线 ¥2980-9800、8 周重投入；这门课基础项只要 $299 AUD（早鸟 $270），全部加购堆满也就 $639 AUD，粗略按 1 AUD≈4.7 CNY 换算大约 ¥1400-3000（**这个汇率只用于对照分类表，是粗略参考，不是精确值**），量级只有 Type 1 的零头。历史 cohort 也从来不是 4 周以上的重课，是 2-3 周的短期冲刺（PERSONAS.md §0 cohort 表）。
- **Type 7（主课三档，跟随母 bootcamp）也不成立**——这门课不是任何 bootcamp 的附属档位，它本身就是独立产品，没有"母课"可以跟随。
- **Type 5（Fullday Workshop）价位接近但产品形态不对**——Type 5 是"一次性沉浸式"体验，这门课有 150 节课 9 个 phase 的内容库，是可以反复回看自学的资产，不是"上完就结束"的单场活动。
- **07 期自学制、无固定开班这一半，反而有点像 Type 8（认证课）的运营节奏**——常青、不追开班日期、靠 SEO 长尾——但这门课不是认证考试类目，内容也不适合走认证课那种"低频长文+长尾词矩阵"当唯一打法，还是需要主动内容种草。

**结论**：这门课是"求职结果导向的目标人群 + 远低于标准 bootcamp 的客单价/周期 + 直播冲刺场次和自学制产品并存"的组合，8 个类型里没有一个能不打折扣地套用。按 `COURSE_TYPE_PLAYBOOKS.md` 维护规则"课程类型不在 8 个里面 → 加 Type 9，不要硬塞"处理：**内容角度借用 Type 1 的"结果导向"逻辑但砍掉不适用的 OFFER 墙战术（下面 §1 说明为什么）；渠道投入强度对齐 Type 4/6 这类小体量课程（历史单期最多 12 人，不该按 Type 1 的 12 篇/周小红书节奏投入）；07 期常青部分借用 Type 8 的 SEO 长尾逻辑**。

## 1. 课程定位摘要

> 🧑 目标用户画像见 [./PERSONAS.md](./PERSONAS.md)（2026-07-03，运营侧 GT 70-75% / 心理侧 GT 0-5%）——本节只抽摘要，详细 persona/异议/决策周期几乎全是 ⚠️ 待补状态，不要假装这里有更多信息。

**One-liner**：系统过一遍全栈面试会考的东西——高频真题、白板算法、系统设计、AI 编程面试新趋势、简历和 Behavioral 准备，外加至少一次全流程模拟面试复盘。（措辞抄自 `FUNNEL_PLAN.md` §1 核心承诺草稿，尚未经课程负责人最终确认。）

**目标人群**（PERSONAS.md 三个 persona，画像有依据、其余字段几乎全 ⚠️ 待补）：
- Persona A — 求职卡壳的 IT/CS 应届毕业生（投了简历但过不了技术面）
- Persona B — Web 全栈班毕业生内部转化（已经是匠人学员，有项目经验缺面试实战）
- Persona C — 在职想跳槽、被叫去面试才发现讲不清楚项目的全栈工程师

**主推内容角度**（Type 1 逻辑砍掉不适用部分 + PERSONAS.md 仅有的可信信息交叉）：

| 内容角度 | 权重 | 为什么 / 依据 |
|---------|------|------|
| 内容体量真实、不是水课（9 phase / 150 节课，`GET public/outline.json` 统计，`FUNNEL_PLAN.md` §1 Q2 已列全表）| ⭐⭐⭐⭐⭐ | 这门课最大的信任问题不是"有没有效果"（没有校友 offer 数据能证明这个），而是"$299 一个刷题课是不是随便攒的"。用真实内容结构（往期精华录播/面试策略/前端后端高频突击/系统设计/AI 编程面试/算法白板/模拟面试冲刺）打消这个疑虑，比空喊"系统提升"更有说服力 |
| Persona B 姊妹课内部转化（Web 全栈班结课学员）| ⭐⭐⭐⭐⭐ | 这是本课程独有的优势，Type 1-8 里没有一个类型专门讲"老学员从姊妹课自然转化"这条路。已经买过一次、对品牌有信任基础的人，获客成本远低于陌生新客。**但要老实说：这条路径目前只是逻辑推理（同品牌复购门槛通常低于陌生获客），`FUNNEL_PLAN.md` §2 已经指出"没人查过 Web 全栈班结课学员里有多少人转化购买了本课"，这是待验证假设，不是已经跑出数据的战术**，§4 第一批任务就是去查这个数字 |
| Stan Luo 讲师真实履历（CTO Jobpin AI）| ⭐⭐⭐⭐ | [来源: `GET /admin-cms/programs/by-training/{id}`，历史 6 期讲师字段均为 Stan Luo，PERSONAS.md §0 已记录] 只有 1 位讲师，不是 Type 1 那种"Faculty 天团"打法，但讲师身份是真实可查的，不需要靠虚构人设撑门面 |
| 06 期真实报名趋势（04 期 2 人 → 05 期 12 人）| ⭐⭐⭐ | 可以老实说"这门课不是从没人报过"，但这是内部判断依据，**不建议直接写进对外文案**（"上期只有 12 人报名"这种表述对外传播容易显得"这课不火"，反而是反效果），主要用于内部判断"这门课值不值得投入"，不是营销素材 |
| ❌ 校友 OFFER 墙 / "拿 offer" 承诺 | 不用 | 两个原因：① 公司红线（`feedback_no_revenue_promise`）明确禁止课程承诺入职/offer；② 更现实的原因是**这门课根本没有真实 offer 截图可用**——没有任何学员反馈/结课数据能证明"上完这课拿到了 offer"，编不出来就不编，Type 1 的核心武器在这里天生缺失，只能靠内容体量+真实履历撑信任，不能靠社会证明 |

**关键差异化**（对比同样面向求职者的其他课程）：
1. 不是"从零学编程"——课程名容易被误读成全栈项目班，实际前提是"已经有编程/项目基础"（PERSONAS §4 已排除零基础人群），这一点要在所有推广文案开头讲清楚，避免招错人退款
2. 5 个真实付费 SKU 里有真人 1v1（Assignment 讲解 $639）和真流程模拟面试（$189/$390 套餐），不是纯录播刷题
3. 双轨——有想跟直播 cohort 一起冲刺的人（06 期），也有想按自己节奏刷的人（07 期自学），两种购买动机都要覆盖，不能只推一种

**承诺红线**（不可写进任何推广文案）：
- ❌ 拿 offer / 包就业 / 保证通过面试
- ❌ 具体薪资数字承诺
- ✅ 只承诺：过一遍高频考点、有真人反馈的模拟面试机会、讲得清楚项目

## 2. 目标与漏斗反推

> 标准反推公式假设"有一个已确认的引流课"，这门课的引流课方案还没选定（`FUNNEL_PLAN.md` §4 两个方案均未拍板），所以下面这层反推比标准模板简单一档，等引流课定了再插入中间层。

```
06 期报名目标：⚠️ 待补（无官方数字，见 §0），下面暂用符号 N 占位
  ↓ 假设销售页/内容 → 咨询转化率 ~10%（AI 参考基线，非本课实测，客单价 $299-639 属于中低价、决策相对快，比 Type 1 高价 bootcamp 通常假设的 5% 转化略高，但没有本课历史数据验证）
咨询量目标：~10N 人
  ↓ 各渠道流量分摊（见 §3，PERSONAS.md §3 渠道权重表明确写"暂无法计算"，下面比例全部是兜底判断，不是从 persona 数据反推）
  - 私域内部转化（Web 全栈班结课学员）：待查真实分母，暂不定百分比（见 §3 备注）
  - 小红书轻量种草：~40%
  - 06 期直播讲座/公众号：~30%
  - 07 期常青 SEO/公众号：~30%（这条不追 06 期日期，效果周期是月级不是周级）
```

**这张表比 `ai-marketing` 版本的置信度还要再低一档**：那门课至少有清晰的三档定价+引流课结构可以套模板；这门课连"要不要做引流课"都还没定，报名目标也完全没有官方数字，上面所有百分比都是为了给 §4 的任务矩阵一个粗略排序依据，**不能当成 KPI 考核基线使用**。06 期结课（2026-08-09）后第一件事就是把真实数据填回来替换这张表（见 §8 postmortem 待办）。
