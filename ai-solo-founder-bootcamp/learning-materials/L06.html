让 Agent 跑第一批调研：从公开小样本到可追溯证据

这一节不要求“一小时抓 200 条 Reddit”或“批量抓 1000 条评论”。抓得多不等于研究可靠，评论多也不等于用户愿意付费。你要完成的是一份能点回原始来源、能说明抽样边界、能被人工纠错，并能为下周真人访谈提供问题清单的第一批调研报告。

Agent 在这里是研究助理，不是市场裁判。它可以整理公开信息、提取原话、比较竞品和生成待验证假设；它不能绕过登录、验证码、反爬措施、访问限制或平台规则，也不能把在线评论推断成真实购买承诺。

本节完成后你会得到什么

  1. 一页 Research Brief：研究对象、问题、范围、时间窗与停止条件清楚；
  2. 一份 Source Log：每条材料保留原始 URL、访问日期、引用片段和来源层级；
  3. 一张 Pain Matrix：把观察到的痛点、场景、替代方案与未知分开；
  4. 一张 Competition Comparison：只比较可核验的定位、功能、价格与边界；
  5. 一个自下而上的市场规模假设，计算过程可解释且标记为待验证；
  6. 一次由你手动触发、检查并纠错的 Agent 调研任务；
  7. 一个“可考虑每周重复”的任务说明，但今天不直接放任无人值守运行；
  8. 五位下周需要亲自联系的目标用户。

时间建议：Brief 15 分钟，来源采样 35 分钟，整理与纠错 35 分钟，市场估算和周度任务 25 分钟，证据登记 10 分钟。

先纠正四个研究误区

误区为什么不成立本节正确做法
评论越多，痛点越真实平台推荐、重复转述、活跃用户偏差会放大某些声音记录样本来源与筛选规则，只说“本样本中观察到”
提到次数等于发生频率一条高热度帖子不代表目标群体中的发生比例频次写“样本提及数”，真实发生率留给访谈或行为数据
抱怨强烈等于愿意付费表达不满不等于有预算、决策权或购买行动寻找现有付费替代、过去支出、采购动作和真实承诺
Agent 给出 TAM 就是市场规模模型可能混用地区、年份、口径和不可核验数字用可触达客户数 × 采用假设 × 客单价自下而上计算

本节只产生“访谈前假设”。真正的客户证据来自下周你亲自进行的真实对话，而不是 AI 模拟用户、评论聚类或漂亮的报告。

第一步：写 Research Brief

先在 Founder Workspace 新建 RESEARCH-BRIEF.md。如果 Business SoT 里的客户仍然是“所有中小企业”“所有留学生”这种大类，先缩小范围，否则 Agent 会收集大量彼此无关的材料。

# Research Brief

业务假设：
目标客户：具体到行业、角色、规模、地区或触发场景
研究问题：这类人上个月如何处理 ______？
我们要观察：发生场景、当前替代、可观察代价、采购或承诺信号
明确不研究：解决方案喜好、泛泛趋势、与当前客户无关的相邻市场
时间窗：例如最近 12 个月；历史材料另行标注
语言/地区：中文与英文市场分开记录，不直接合并
样本上限：第一轮 12–20 条高相关公开材料
停止条件：达到上限，或连续 5 条没有出现新场景
安全边界：只访问公开且允许访问的页面，不登录抓取，不保存用户名
输出：来源日志、痛点矩阵、竞品对照、市场假设、5 位访谈对象

好 Brief 的判断：另一个同学能按同一规则找到相近的一批材料。如果规则只是“在网上搜痛点”，结果不可重复，也无法解释为什么某条被纳入。

案例：物业维修工单助手（课堂模拟）

以下数据和公司情境均为课堂模拟，不代表真实市场表现。Research Brief 可以写成：研究澳洲独立物业管理机构中，物业经理处理租客报修资料不全时的当前流程；第一轮查看 4 个公开竞品页面、8–12 条公开讨论或公开帮助文档，分别记录“缺少什么信息、如何追问、谁决定紧急等级、目前用什么替代”。不研究租客是否“喜欢 AI”，也不推断安全事故责任。

第二步：建立来源层级与 Source Log

不同来源能回答的问题不同。把它们放在同一张表里时必须保留层级，不能让一条匿名评论和一份官方定价页拥有相同权重。

层级来源例子适合回答不能单独证明
A：第一方事实竞品官网定价、产品文档、政府或行业机构原始资料当前功能、公开价格、定义、规则用户是否真的采用、体验是否良好
B：可定位用户表达公开论坛帖、公开评价、公开社区讨论用户语言、具体场景、当前替代线索总体发生率、身份真实性、付费意愿
C：二手总结媒体、博客、市场报告摘要发现待核查线索原始数字、当前产品事实
D：AI 生成模型摘要、聚类、搜索答案整理、提出检索方向任何未经回查的事实

建立 SOURCE-LOG.md：

| ID | 层级 | 来源标题 | 原始 URL | 发布/更新日期 | 访问日期 | 引用片段 | 支持什么 | 限制 |
| S01 | A | 竞品定价页 | https://... | unavailable | YYYY-MM-DD | “...” | 公开价格 | 不代表成交价 |
| S02 | B | 公开讨论帖 | https://... | YYYY-MM-DD | YYYY-MM-DD | “...” | 追问资料很耗时 | 单一匿名样本 |

引用片段只保留理解证据所需的短句，并用自己的话记录上下文。不保存用户名、头像、联系方式或无关个人信息。页面无法访问、需要登录、robots 或平台界面明确限制自动访问时，记录 access unavailable 并跳过，不改用代理、Cookie、浏览器指纹或其他手段绕过。

平台访问红线

  • Reddit 的数据访问受其官方 Data API Terms 和相关政策约束。只有在你具备相应访问权并遵守当前限制时才使用 API；否则只人工阅读少量公开页面。
  • X 的程序化访问应遵守其官方 Developer Agreement and Policy。没有合规 API 访问时，不用自动化工具批量抓取。
  • 小红书、牛客及其他社区若没有你可用的官方数据接口，本节只允许人工查看少量公开内容并记录链接；不绕登录、不破解验证码、不突破频率限制。
  • 公开可见不等于可以无限复制、永久保存或重新发布。作业保留证据引用与短片段，不建立用户画像，不做用户名级跟踪。

平台条款、接口和限额可能变化。每次把任务升级为自动化前，都要重新查看平台当前官方页面；旧教案、第三方博客和 Agent 自己的解释不能替代当前规则。

第三步：先手动采样，再交给 Agent 整理

第一轮建议 12–20 条材料，覆盖三种来源：3–5 个第一方竞品页面或文档、6–10 条高相关公开用户表达、2–5 份行业或政府原始资料。样本不够时写不够，不用低相关内容凑数。

  1. 根据 Brief 写 4–6 个检索式，分别覆盖场景、替代方案和结果，而不是只搜“痛点”；
  2. 人工打开每个页面，确认它真的与目标客户和触发场景相关；
  3. 把 URL、日期、短引用和限制写进 Source Log；
  4. 删除重复转载、营销软文、无原始链接的聚合页和无法确认语境的截句；
  5. 达到样本上限或连续五条没有新场景时停止；
  6. 只把 Source Log 中的内容交给 Agent，禁止它在未获许可时继续外部抓取。

运行学生 Skill：

使用 $opc-agent-team，读取我的 BUSINESS-SOT.md 和 RESEARCH-BRIEF.md。
只设计一个低风险的研究助理任务，不增加额外 agent。
输入仅限 SOURCE-LOG.md，不自行登录网站或扩展抓取。
先检查来源是否可追溯、样本是否重复、是否混合了不同市场；
再生成痛点矩阵、竞品对照和待验证问题。
所有结论必须引用 Source ID；没有证据的内容写 unavailable。
不得把评论数量解释成市场频率或付费意愿。
完成后列出你最可能犯错的三处，等我人工复核。

研究助理的工作说明书

角色：公开资料研究助理
任务：每周整理本 Research Brief 范围内的新证据
输入：BUSINESS-SOT.md、RESEARCH-BRIEF.md、人工确认的 SOURCE-LOG.md

复核人：创始人本人
成本上限：____
停止条件：来源不可访问、权限扩大、连续错误、成本超限、发现敏感数据

第四步：制作 Pain Matrix，但不要伪造频次和付费意愿

让 Agent 输出下面的字段。矩阵中的“样本提及数”只描述这批材料，不能写成“30% 用户都有这个问题”。

痛点假设发生场景样本提及当前替代可观察代价付费证据来源下一步
报修信息不完整导致反复追问（模拟）租客首次报修本样本 3/12电话、短信、表格重复追问；具体时间 unavailable只看到现有软件订阅，购买动机待验证S02、S05、S09访谈 3 位物业经理过去一次工单
紧急等级难判断（模拟）信息含糊或非工作时间本样本 2/12人工值班判断延迟或误派风险；比例 unavailable无S04、S08不自动化，访谈责任边界

付费证据从弱到强：公开抱怨 → 使用免费替代 → 为人工或软件支付过 → 主动比较方案 → 同意试点 → 提供数据或引荐 → 支付订金或购买。前两项只是线索。没有真实行为时，付费意愿写 awaiting-evidence，不能让 Agent 打一个看似精确的 8/10 分。

中文和英文来源分开建表。即使文字描述相似，地区、法规、工作流程、价格、渠道和替代方案也可能不同；没有证据时不能合并成一个全球市场结论。

第五步：制作 Competition Comparison

竞品研究不是找三条“他们没做的功能”来证明自己更好。比较直接竞品、间接替代和“不处理”三类，保留原始页和访问日期。

| 方案 | 类型 | 服务谁 | 核心任务 | 公开价格 | 交付方式 | 人工责任 | 来源/日期 | 未知 |
| 竞品 A | 直接 | ... | ... | ... | ... | ... | C01 | 成交折扣 |
| Excel + 邮件 | 间接 | ... | ... | unavailable | 手工 | ... | U03 | 实际工时 |
| 忍着不做 | 非消费 | ... | ... | 0 购买支出，不等于 0 代价 | 无 | ... | U05 | 后果 |

价格页没有标明货币、税费、地区或计费周期时，不自行换算。页面写“Contact sales”就记录原文，不猜价格。评价数、社交粉丝数和网站访问量不能直接当客户数。

人工检查三件事：

  1. Agent 是否把功能描述改写成更强的承诺；
  2. 是否把不同日期、地区或版本的数据放在同一列直接比较；
  3. 是否因为没找到某项功能就断言“竞品没有”。正确写法是“在本次查阅的公开页面中未找到”。

第六步：自下而上写市场规模假设

本节不用一张巨大的全球 TAM 图。先估算你在一个地区、一个细分市场、一个渠道里可以实际触达和服务的客户数量：

可服务账户数 = 可找到的目标账户数 × 符合触发条件比例 × 可交付比例
年度收入假设 = 可服务账户数 × 采用比例假设 × 年客单价假设

课堂模拟：你通过一个可核验目录找到 240 家目标机构；人工抽查 30 家，其中 12 家符合规模与地区条件。暂以 40% 作为样本内符合比例，但不能声称总体一定如此。若一人当前最多服务 10 家，近期可服务账户数受产能限制为 10，而不是 96。假设年客单价 A$3,600，则近期年度容量上限假设为 A$36,000。这里的采用率和价格均未验证，必须通过访谈、试点和报价反应更新。

变量当前值来源状态如何验证
目标账户数240（模拟）官方或行业目录 URLdrafted去重并抽查仍在经营
符合比例12/30（模拟样本）抽样日志drafted扩大随机抽查
采用比例unavailable无awaiting-evidence访谈、试点、真实报价
年客单价A$3,600（假设）内部价格假设drafted真实报价与付款

必须写出低、中、高三个情景，并说明改变哪个假设会让项目停止。不要使用 Agent 自动生成的行业规模数字，除非你能打开原始资料、确认年份、地区、定义、样本和计算口径。

第七步：人工纠错并进行第二次运行

第一次报告必须找出至少一处错误。没有发现错误时，不能直接写“零错误”；抽查至少五个 Source ID，再说明检查范围。

常见错误发现方式修正
引用不存在或 URL 不支持结论逐个打开来源回查原句删除结论或换成真实支持的表述
把样本提及数写成市场频率检查百分比的分母改为“本样本 x/n”，总体频率 unavailable
把抱怨写成付费意愿寻找过去支出或承诺改为 awaiting-evidence，并生成访谈问题
重复帖子被聚类成多个证据比对 URL、引文和转载来源保留原始来源，重复项只记一次
混合中文和英文市场检查地区、语言与现有替代拆成两个矩阵，不直接比较频率
竞品页面已过期查看访问日期和页面状态标记日期，找当前官方页面；找不到写 unavailable

修正后，用 3–5 条新材料做第二次运行。输出结构应该一致，但结论可以变化。记录“哪条新证据改变了哪个假设”；如果没有改变，也写清原因。

第八步：设计周度任务，先手动运行再排程

今天只批准一个低风险的周度调研任务。先手动运行成功，再决定是否排程。初次配置完成不等于任务已经执行。

任务名：Weekly Research Delta
触发：每周 ____，时区 Australia/____
输入：上周已人工确认的来源清单 + 本周新确认 URL
动作：检查页面是否变化，提取新增信息，更新 Source Log 草稿
输出：新增来源 / 竞品变化 / 新痛点线索 / 冲突 / unavailable
上限：最多处理 ____ 个 URL，最多运行 ____ 分钟，成本上限 ____
必须停止：登录墙、验证码、拒绝访问、权限扩大、来源出现个人敏感数据
人工批准：创始人检查后才合并进正式报告；不自动外联或发布
失败通知：写入 AUTOMATION-LOG.md，不静默重试超过一次
  1. 点击或运行“现在执行”，不要等待下周才发现配置是哑弹；
  2. 确认 Agent 只访问批准的来源，时间、成本和输出路径符合说明书；
  3. 抽查至少五个结果，并记录一处纠错或“未发现错误的抽查范围”；
  4. 模拟一个失败：把一个 URL 改成 404 或登录页，确认任务停止并报告；
  5. 确认你的设备关机后任务是否仍会运行；不知道就写 unavailable，不承诺无人值守；
  6. 只有前五项通过，才批准安全的每周重复计划。

如果任务依赖本机、浏览器登录态或临时权限，本周先保持手动触发。自动化的价值来自稳定、可检查地重复，不来自“创始人没动一根手指”的表演。

失败处理

  • 来源不足：缩小结论，不扩大到低质量样本；写 insufficient evidence。
  • 平台拒绝访问：停止该来源，改用官方 API、官方文档、公开替代来源或人工访谈，不绕过限制。
  • 样本全来自同一社区：标记渠道偏差，再补一个不同来源层级，不把结果外推。
  • Agent 生成假 URL：删除所有无法打开的条目，并要求只使用 Source Log ID。
  • 报告太长：保留证据表、关键冲突和下一步；删除没有来源的趋势描述。
  • 定时任务超时或超成本：停止排程，减少 URL 和输出字段，设置硬上限后手动重跑。
  • 发现个人或客户敏感信息：立即停止处理、删除副本、收窄来源并通知讲师；不把事故截图放进作业。
  • 新证据与 SoT 冲突：保留冲突，不让 Agent投票决定；写入 Assumptions to Test，带到真人访谈。

证据状态与提交包

在 AUTOMATION-LOG.md 记录：

| Date | Task | Input scope | Output | Human correction | Runtime/cost | Repeat decision | State |
| YYYY-MM-DD | Weekly Research Delta | S01–S15 | RESEARCH-REPORT-v0.1 | 修正了频次推断 | ____ | approve / revise / stop | executed |
  • drafted：Brief、Prompt、报告或 Schedule 只是草稿；
  • executed：你真实手动运行了一次，保存输出并完成回查；
  • verified：来源可检查，你完成纠错，安全重复方案经规定 reviewer 接受；
  • 付费意愿、市场发生率、采用率或客户承诺仍缺证据时，保留为“待验证假设”，不要新增第四种交付状态。

最终提交文件：

  1. RESEARCH-BRIEF.md；
  2. SOURCE-LOG.md，至少包含 12 条高相关、去重、可回查记录；
  3. RESEARCH-REPORT-v0.1.md，含 Pain Matrix、Competition Comparison 和市场规模假设；
  4. AUTOMATION-LOG.md，含首次运行、失败测试和人工纠错；
  5. 五位可真实联系的目标用户，只在私有工作区保存必要联系线索，不提交个人资料。

过关标准

  1. Research Brief 能限定客户、问题、时间窗、样本上限和停止条件；
  2. 所有结论都能回指 Source ID，原始 URL、访问日期和短引用齐全；
  3. 没有绕登录、反爬、验证码、访问限制或平台规则；
  4. 痛点矩阵把样本提及、真实频率、付费证据和未知分开；
  5. 竞品表包含直接竞品、间接替代和“不处理”，没有把“未找到”写成“不存在”；
  6. 市场规模采用自下而上计算，每个变量有来源、状态和验证方法；
  7. Agent 任务已手动运行，至少回查五条来源并记录一处纠错；
  8. 失败测试能安全停止，没有静默无限重试；
  9. 周度任务有范围、成本、停止条件和人工批准点，尚未验证时不声称自动化成功；
  10. 已经列出五位需要本人接触的目标用户和下一步访谈问题。

本节结论边界：你完成的是“可用于设计访谈的桌面研究”，不是市场验证。下一步由你联系真人，询问他们最近一次如何处理这个问题、使用什么替代、付出什么代价、谁决定预算，并允许证据推翻当前方向。
