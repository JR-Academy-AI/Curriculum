# 第三节课 Runsheet — 老项目改造工作坊：把 AI 用到一个真实 existing 项目上

> **形态：动手工作坊（不是讲座）。** L1 给自己建 SoT、L2 从零做产品，都是 greenfield。**L3 = brownfield**：把 ADLC + AI OS 用到一个**你没写过、没文档、不敢乱动**的真实老项目上 —— 这才是工作里 99% 的场景，也最值钱。
> **四块能力**：① 让 AI 读懂老项目 → ② 逆向补 SoT（从代码反推 CLAUDE.md）→ ③ 安全改造网（不破坏现有功能）→ ④ 在老项目上用 ADLC 跑一个真实改造需求。
> **接大纲**：对应 Phase 1 的 Quest「给你的真实项目写 .cursorrules + CLAUDE.md」+ Context Engineering + Debug。
> **slide 少、引导多**：framework slide 见 §7，主体是阶段引导 + 老师巡场检查点。

---

## 0. 课前确认（开课前 5 分钟）

每人必须带：
1. **一个真实老项目**：自己工作里的 repo / 一个开源项目 / 一个自己半年前写的老代码。**关键是「不熟、没文档」**。
2. **统一兜底 demo 老项目**（老师准备一个中等复杂、没文档的 repo），给没带的人用，保证全场有得做。
3. 工具链装好（L1）。

> ⚠️ 红线钉死：**今天不许在不理解的情况下让 AI 大改**。brownfield 的第一原则是「先看懂，再动手」。

---

## 1. 开场：为什么 brownfield 最难也最真实（~10min）

**讲（念）**：「前两节你都是从零开始 —— 自己的简历、自己的新产品，没有历史包袱。但你回去上班，面对的不是白纸：是一个几万行、你没写过、原作者跑路了、没文档、一改就怕崩的老项目。今天我们就练这个 —— 怎么让 AI 帮你**先看懂、再安全改**一个真实老项目。这套能力，直接decide你在公司里能不能扛事。」

**今天你的角色**：你是这个老项目的「接手人」，AI 是帮你快速 onboarding + 安全施工的搭档。

---

## 2. 阶段 ① 让 AI 读懂老项目（~25min · 动手）

把陌生 codebase 喂给 agent，让它替你几小时干完以前几周的 onboarding。**每人对自己的老项目做**：

**让 agent 依次产出**（投屏指令模板）：
- `读这个项目，给我画一张架构图：有哪些模块、谁调谁、数据怎么流`
- `这个项目的入口在哪？一个请求 / 一次操作从进来到结束走过哪些文件？`
- `哪些地方是"高风险、改了容易连锁崩"的核心？哪些是边角安全区？`
- `有哪些隐性约定 / 坑（命名、错误处理、数据格式）是新人最容易踩的？`

**老师检查点**：你能拿着 agent 的总结，**给旁边同学讲清楚这项目是干嘛的、核心在哪、你要改的那块在哪**。讲不清 = 还没读懂，别往下。
**常见卡点**：① 项目太大 agent 泛泛而谈 → **聚焦到你今天要改的那一块**，让它只深读相关路径；② agent 瞎猜 → 要求它**每个结论引用具体文件/行**，不许脑补（接 L1 的「不准编造」）。

---

## 3. 阶段 ② 逆向补 SoT：从代码反推 CLAUDE.md（~25min · 动手）

老项目没有 `CLAUDE.md`，规则都散在代码里、在原作者脑子里。让 AI **从现有代码反推出来，写成项目级 SoT**（接 L1 的记忆系统，方向反过来：code → SoT）。

**指令**：`基于你刚读到的真实代码，帮我起草这个项目的 CLAUDE.md：技术栈、目录结构含义、命名/错误处理/数据格式的约定、已知的坑、改动时的红线。每一条都要引用代码里的真实例子，不许写通用废话。`

**老师检查点**：CLAUDE.md 里是**从这个项目代码里真挖出来的约定**（"这个 repo 所有 service 不超过 600 行""ID 用 ObjectId 不用 slug"这种具体的），不是"要写注释、要测试"这种放之四海皆准的废话。
**常见卡点**：写成通用模板 → 逼它**每条规则配一个代码佐证**；约定互相矛盾（老代码本身不一致）→ 让它**标出矛盾点**，这本身就是改造的价值发现。

> 收口（念）：「你刚做的，就是把一个'只有原作者懂'的项目，变成'任何 AI / 任何新人 5 分钟能上手'的项目。这份 CLAUDE.md 就是这个老项目的第二大脑。」

---

## 4. 阶段 ③ 安全改造网：不破坏现有功能（~15min 讲 + 贯穿后面）

brownfield 最大风险 = **改坏别人正在用的东西**。改之前先架好安全网：

- **小步**：一次只改一件事，别让 agent 一把大重构。
- **先加测试护栏**：改之前，让 agent 给你要动的那块**补上现有行为的测试**（锁住"现在是对的"），改完测试还过 = 没破坏。
- **worktree 隔离**：用 git worktree 让改造在独立副本上进行，不污染主分支；多个改造可并行（接 L1/北极星的「多 agent 并行」）。
- **可回滚**：每步 commit，随时 `git` 退回。
- **改完跑全量回归**：不只看新功能，要看**老功能没坏**。

**老师讲透一句**：「greenfield 错了重写就行；brownfield 错了是**线上事故**。所以这一节的纪律比 L2 严得多 —— 先架网，再施工。」

---

## 5. 阶段 ④ 在老项目上跑一个真实改造需求（~40min · 主战场）

用 ADLC 闭环，在老项目上真做一次改造。**每人挑一个真实需求**：加一个小功能 / 修一个真 bug / 重构一块烂代码。

- **需求 → PRD**：基于**项目现状**写改造 PRD（要改哪些文件、不能动哪些、验收 = 新功能 work + 老功能不回归）。
- **交给 agent 改**：`按这份 PRD 改，先补测试锁住现有行为，再小步改，每步告诉我你动了什么`。
- **回归验证**：跑全量测试 / 手测关键老路径，确认没破坏。

**老师检查点**：改完 **① 新需求实现了 ② 原有功能没坏（回归过）**。两个都满足才算过。
**🔥 brownfield 特有卡点**：
- **AI 改出回归（老功能坏了）** → 立刻回滚到改前 commit；缩小改动范围；**先补测试再改**（没测试网就别让它改核心）。
- **看不懂的依赖 / 黑盒** → 让 agent 先解释「这个依赖/这段代码在干嘛、删了会怎样」，**理解了再决定动不动**，别盲删。
- **agent 想顺手"优化"无关代码** → 拦住，红线：**只改 PRD 范围内的，别动别的**（接 L1 的红线纪律）。

---

## 6. 阶段 ⑤ Review + feedback + 收尾（~10min）

- 看 agent 的改动 diff，**像 review 同事 PR 一样审 AI 的改动**（接 Phase 4 Code Review）：改对了吗？有没有顺手改坏的？
- 把改动写成一个**干净的 commit / PR**（让 agent 写 commit message + PR 描述）。
- **点破**：「你今天做的事 = 接手一个陌生老项目 → 几小时读懂 → 补上文档/SoT → 安全改了一块 → 留下干净 PR。这是公司里**最值钱的工程能力**，以前要资深工程师几周，你 + AI 一晚上。」

---

## 7. 收尾 + 作业 + L4 预告（~10min）

- **每人 30 秒**：你改的老项目是什么、改了什么、回归过没。
- **作业**：把你工作里一个真实老项目，补一份 CLAUDE.md + 安全改一个真需求，写成 PR。
- **L4 预告**：「目前你都是一个 agent 在做。下节课开始进 **Skills / Agent**：怎么把你反复做的事固化成可复用的能力，让 agent 更强、更自动 —— 一步步走向'同时指挥 10 个 agent'那个毕业标准。」

---

## 8. 配套 framework slide（少而精，~5 张）

1. **brownfield vs greenfield**：从零做 vs 改老项目（难点：先看懂、不能破坏）
2. **AI 读老项目四问**：架构图 / 入口与数据流 / 高风险区 / 隐性约定（§2）
3. **从 code 反推 SoT**：散在代码里的规则 → CLAUDE.md（每条配代码佐证）（§3）
4. **安全改造网**：小步 / 先补测试 / worktree 隔离 / 可回滚 / 跑回归（§4）
5. **brownfield 破局清单**：改出回归→回滚+先补测试；黑盒依赖→先让 AI 解释再动（§5）

> 要我把这 5 张做成 deck 就说一声（可和 L2 的框架 slide 放同一套 L2/L3 deck）。

## 老师巡场总表（一页速查）

| 阶段 | 学员产出 | 检查点（过关标准） | 高频卡点 → 怎么救 |
|------|---------|------------------|------------------|
| ① 读懂项目 | 架构/入口/风险总结 | 能给同学讲清项目是干嘛的、核心在哪 | 太大泛泛 → 聚焦要改的块；瞎猜 → 要求引用真实文件 |
| ② 逆向补 SoT | 一份 CLAUDE.md | 有从代码挖出的具体约定（非废话） | 通用模板 → 每条配代码佐证 |
| ③ 安全网 | 测试护栏 + worktree | 改前锁住了现有行为 | 没测试就想改核心 → 先补测试 |
| ④ 改造 | 新功能 work + 老功能不回归 | 两个都满足 | 改出回归 → 回滚+缩范围+先补测试 |
| ⑤ Review | 干净 PR | 审过 AI 改动、commit 清晰 | AI 顺手改无关代码 → 拦回 PRD 范围 |

**全程红线**：不在不理解的情况下让 AI 大改；公司真实代码 / 数据 / 密钥不外发、不进公开 deck；只看「流程走通 + 没破坏」不评项目好坏。
