### 三条需要先跟课程负责人对齐的矛盾

1. **"线下沉浸式"宣传 vs 生产环境 `city: "Online"`**——`DESIGN.md` 和 `outline.json` 反复强调"4 周线下沉浸式·不录播·不开线上"，但 Bootcamp 和 Workshop 两条真实 Program 记录在系统里的城市字段都是 "Online"。可能只是运营还没把默认值改成具体城市，也可能线下/线上的产品形态本身还没最终拍板。**这条我判断不了哪个是对的，需要问课程负责人**——在没确认之前，不要在 PROMOTION_PLAN 里写死"某城市场地预算"或者反过来写"纯线上投流"，两边都可能白做。
2. **销售页 `https://jiangren.com.au/program-course/openclaw-bootcamp` 真实存在但开课日期显示 "Invalid Date"**——这跟 `courseArrangement: []`（生产环境没排课）是同一个根因，不是两个孤立问题。页面上也没有任何学费数字、没有学员案例——这些都对得上 `studentCount: 0` 和 `pricingOptions: []` 的事实，不是页面本身坏了，是它如实反映了"这门课还没准备好接单"这个状态。**在这个 bug 修之前，任何投流引导到这个页面都会在"看到 Invalid Date"这一步直接流失**，这是 PROMOTION_PLAN 动笔前的硬阻塞，不是这份 persona 文档能解决的，但必须写在这里让下游看到。
3. **主题色冲突（次要）**——`DESIGN.md` 定的主色是 `#E84142`（OpenClaw 红），但生产环境 Training 文档里 `bootcampTheme.primaryColor` 实际是 `#ff5757`（跟 AI Engineer Bootcamp 撞色，正好是 `DESIGN.md` 自己写的"要避开"的颜色）。不影响这份文档的内容，但海报/落地页视觉执行前要先同步。

## 4. Persona 不会买的人

这一节相对扎实一点，因为直接来自课程自己写明的排除条件（`outline.json` "🚫 谁不适合来"），不是猜的，是产品自己划的边界：

1. **只想看个意思、偶尔玩玩的人**——4 小时 Workshop 已经够用，来了也是浪费钱。`[来源: outline.json suitable 字段原文]`
2. **想学 AI 工程化、想自己写 Skill、想接 MCP 的人**——这门课只教到"接好用好"，不教怎么开发扩展，这批人应该去 AI Engineer Bootcamp。`[来源: 同上]`
3. **每周抽不出 4 小时现场 + 2-3 小时课后自学的人**——课程自己承认"dropout 80% 来自周中没时间消化"，这是产品经验教训写进大纲的，不是随口一说。`[来源: 同上]`
4. **电脑跑不起 Node 22 / 装不上 WSL2 的人**——纯技术门槛，报名前要先升级硬件。`[来源: 同上]`

这四条的可信度比第 2 节的 persona 高，因为它们是课程团队基于产品设计直接排除的，不需要额外的用户调研来验证"这类人不该报"这件事本身——但"实际报名的人里有没有踩中这几条却依然报了名"，目前同样没有数据（因为还没人报名）。

## 7. Ground truth 覆盖率诚实评估

按 `PERSONA_SCHEMA.md` 的标准算法：3 个 persona × 10 个字段 = 30 个标注位。

- 有真实数据支撑（生产环境 API / 公开网页实测）的标注位：约 3-4 个（主要集中在 §0 Meta 的商业状态数据，以及 Persona A/B 各一条异议/不信什么字段部分借力于真实 API 数据或第三方研究）
- `ai_inference` 或 `⚠️ 待补`的标注位：约 26-27 个

粗算下来 **覆盖率在 10-15% 左右**，明显低于 `target-user-persona-mapper` 要求的 50% 及格线，按 Mode B 的判定标准属于 **❌ 不合格——本质上目前还是"骨架 + 待补清单"，不能直接拿去支撑定价/渠道/文案决策**。

这个低分不是这次调研没做够，是**诚实反映了这门课的真实所处阶段**：生产环境层面（有没有在招生、多少钱、有没有学员）这次做到了 100% 查证，不再是本地文件拍脑袋——这部分之前完全空白，现在是扎实的。但 persona 真正需要的核心内容——真实用户的痛点原话、决策周期、异议、信任来源——因为课程还没开班、没有真实学员、又不能自动爬取小红书/Boss 直聘这类最可能有相关讨论的平台，这次一条都没拿到。

**下一步不是继续往这份文档里加内容，是先让销售/客服/新媒体去做第 6 节列的人工任务**，拿到哪怕 5-10 条真实咨询记录或用户原话，再回来把 ⚠️ 待补 的格子一个个填实。在那之前，硬写满 10 个字段只会制造一份看起来完整、实际是编出来的假画像，比留白更危险。
