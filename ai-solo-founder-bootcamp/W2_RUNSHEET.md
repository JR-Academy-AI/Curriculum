## 0. 这节课到底要达成什么

**一句话**:W1 给了他一个**懂他的秘书**,W2 要给他一个**按排程主动交活的员工**——他睡觉的时候它在干活。

### 本周三件套(取自 `L05` description,不要改口径)

| | 内容 |
|---|---|
| **本周真实动作** | 给 agent 接权限、写工作内容、排定时任务,然后**你自己**去约 5 个真实用户 |
| **本周产出** | 至少 1 个持证上岗的 agent + 3 条以上跑过一次的 Agent Schedule + 第一批调研报告 + 5 场访谈记录 |
| **卧槽点** | 周中你没动一根手指,竞品和痛点报告自己推到了你手机上 |

### 三个必须当天带走的东西(过关线,缺一不可)

| # | 产出 | 验收标准 |
|---|---|---|
| 1 | **一个持证上岗的 agent** | 四条路线里选定一条 + 装好 + 接完权限 + 写完工作说明书;**当场跑一个它 JD 里写的任务,交付物格式对得上说明书** |
| 2 | **2 条现场配通的 Agent Schedule** | 每条有 cron 表达式 + 手动触发一次的**真实输出截图**(不是"配好了没跑") |
| 3 | **一个组队结论** | 成团(谁+谁+哪个项目)或明确写下"我单干";两种都要在平台登记,**不允许悬着** |

**这节课的"卧槽点"必须发生在周中,不是课上。** 课上只是把发条上紧,真正的震撼是周三早上手机响、一份他没动手的竞品报告推过来。所以现场纪律是:**宁可少配一条 schedule,也要保证配的那条真的会在周中跑起来。**

**这节课最容易失败的方式**:
1. 30 分钟 networking 一开心就超时,后面动手环节全线塌方
2. 配了 5 条 schedule,一条都没真跑过,周中全是哑弹
3. agent 装上了但没写工作说明书 → 学员回去发现"它啥也不会干",下周直接不用了

## 3. 逐环节详案

### 13:45–14:00|签到 + Pre-work 抢救(15min)

**助教主导。** 逐人问四句:

1. AI OS 这周在跑吗?(没跑 → 标红,今天他要双线补)
2. 你的自动任务跑出东西了吗?**给我看一眼**(这是 ⓪ 分享的素材池)
3. 你的电脑能装终端工具吗?(不能 → 立刻问有没有私人电脑,没有 → 分到"浏览器可跑"的路线)
4. 你是 A / B / C?(核对名单,发对应的桌牌或能力标签)

**签到时顺手做一件事**:问每个人"这周有没有什么进展是值得上台讲 3 分钟的"。挑出来的名字给讲师,**⓪ 上台的人在签到阶段就定好,不要到 14:00 才现场找**。

---

### 14:00–14:30|⓪ 学员分享 + networking + 组队集市(30min)🔴 断流段

> **这是 W2 起的固定开场**,也是本期唯一的正式组队时刻。
> **不是暖场闲聊。** 这 30 分钟要产出两样硬东西:**上周 AI OS 到底跑出了什么(全班互相看到)** + **成团名单**。

#### 14:00–14:03|规则 + 亮本期结构(3min)

投一屏(**不点名、不显示项目内容**):

```
本期 50 人:A 类 __ 人 / B 类 __ 人 / C 类 __ 人
城市分布:墨 __ · 悉 __ · 布 __
A 类正在找的角色 Top 3:______ / ______ / ______
```

讲师说三句话:
> 1. 今天上台的两位不是"讲得最好的",是**这周动作最实的**。
> 2. 接下来 12 分钟是组队集市,**A 类摆摊,B/C 类挑人**。今天不组也行,但要写下"我单干"——**不允许悬着**。
> 3. 这 30 分钟直播是关的。你在这屋里说的项目,不会出这屋。

#### 14:03–14:13|两人上台(10min)

**固定配比:1 位 A 类 + 1 位 B/C 类。** 每人 3min 讲 + 2min 提问。

每个上台的人**必须先回答这一句**(这是把 `COURSE_REDESIGN` 里"开场 15min review AI OS 跑了啥"折进来的做法):

> **「我给 AI OS 派的那个自动任务,这周跑出了什么?给我看一眼输出。」**

然后再讲:
- **A 类**:我的方向是什么 / 这周撞到的最硬的一堵墙 / **我需要什么角色加入**
- **B/C 类**:我这周跑通了什么 / **我能带什么进来**(技术 / 行业资源 / 销售 / 设计 …)

> ⚠️ **上台前必须核对 `projectVisibility`**:`stealth` 档的学员**不上台**;`match-only` 档的上台前当面问一句"你今天愿意讲到什么程度"。这是 `FOUNDER_MATCHING_PRD` §5.5 的硬约束,不是客气话。

#### 14:13–14:25|组队集市(12min)

**摆摊制,不是自由社交。**

| 角色 | 动作 |
|---|---|
| **A 类(愿意收人的)** | 坐在自己位置上不动,桌牌写两行:**一句话项目** + **我缺的角色**。`stealth` 档只写"我在找 [角色]",不写项目 |
| **A 类(不收人的)** | 桌牌写"本期单干",照常参加 networking,**不算失败** |
| **B / C 类** | 胸口贴能力标签(技术 / 产品 / 营销 / 销售 / 设计 / 财法 / 行业资源),**起立走动**,挑 1-2 个 A 谈 |

**三条硬规则**:
1. **一个 A 最多收 2 人。** 防止明星项目把人全吸走、其他 A 空手。
2. **每场谈话不超过 4 分钟**,助教按铃赶人。目的是"多见几个",不是"当场定终身"。
3. **谈的是"这四周先合作看看"**,不是股权。股权/协议的事一律推到 W7 的法律文件环节,现场不许谈分成比例。

#### 14:25–14:30|回座 + 登记(5min)

助教拿成团登记表逐组登记:**谁 + 谁 + 挂在哪个项目 + 各自角色**。
- 没配上的 B/C:登记"待撮合",**课后 48h 内人工撮合**(接 `FOUNDER_MATCHING_PRD` P0 admin 看板)
- 明确单干的:也要登记,写一句"我单干,原因是 ___"

讲师收口一句:
> 组不组队不影响你能不能毕业。但接下来 13 周,**有人每周问你一句"你那事怎么样了"**,和没人问,完全是两种课。

### 14:30–14:50|① 四条 agent 路线现场选型(20min)

> 取自 `L05` step 1(原 30min → 压到 20min,深度对照表移到课前预习材料)。

#### 14:30–14:44|四条路怎么选(14min)

**判断依据只有一条:你要它干什么活。不是哪个最火。**

| 路线 | 它的特点(照 outline 口径) | 谁该选它 |
|---|---|---|
| **Hermes** | 跨设备 + 手机 IM 里派活 + 常驻 daemon | 想随时随地扔任务的人 |
| **龙虾(OpenClaw)** | 开源 CLI + 本地 markdown memory + 不依赖单一模型商 | **数据敏感行业**(律师 / 会计 / 医疗) |
| **Codex** | 跟 ChatGPT 订阅打通,写代码类任务顺手 | 已经买了 ChatGPT、任务偏代码 |
| **Claude Code** | agentic 能力最强,适合连续改一个真实项目 | 要它长期维护一个真实项目的人 |

**必须当场讲清的三件事**(学员最常问、也最容易踩):
1. **要不要终端** —— 三条要开终端。公司电脑装不了的现在就说,换路线或换机器
2. **关机还跑不跑** —— 这条留到 ④ 的跨平台对照表统一讲,这里只提一句"待会儿讲,别急着定"
3. **一个月大概多少钱** —— ⚠️ 四条路线的实际费用与当期可用性**待补**(见 §8),讲师课前必须自己确认后填进对照表,**不许现场估一个数**

#### 14:44–14:50|当场定(6min)

**举手定路线,助教按路线分组(④ 的 1:8 陪跑按这个分组坐)。**

> **给犹豫的人一个默认答案**:不确定就选 [默认路线,待拍板]。**今天跑起来 > 选得完美**。你 W6 还有一节课专门讲"切换 / 双 agent 配合"(`L25`),现在选错了不是死刑。

### 14:50–15:20|② 装上 + 接权限(30min)

> 取自 `L05` step 2,**时长一分钟不砍**——这是全课最容易全线卡死的环节,W1 已经在授权上吃过一次亏。

#### 14:50–15:05|跟着装(15min)

按路线分组,**每组一个 TA**。讲师投屏演示自己那条主线,其他组跟 TA 走。

**纪律**:15:05 到点,不管装到哪一步,全场停下来听权限那一段。装不完的课后补——**权限讲错了比装不完危险得多。**

#### 15:05–15:20|接权限 + 授权边界(15min)

**这一段是本节课的安全底线,一个字都不能省。** 照 outline 逐项讲:

| 权限 | 给到什么程度 | 为什么 |
|---|---|---|
| **邮箱** | **只给读 + 起草,不给直接发** | agent 直接发信 = 你的名义、你的责任 |
| **日历** | 给读写 | 它要替你排工作块 |
| **云盘** | **按目录授权,敏感目录排除** | 别把整个 Drive 一次性交出去 |
| **代码仓库** | **给分支写权限,不给主干** | 出事有回滚余地 |
| **浏览器自动化** | **独立 profile,不用你的主账号** | 别让它带着你登录态到处点 |

**讲完必须落一句**:
> 哪些权限一旦给了就**要有审计日志**——你要能回答"上周三下午 3 点它到底动了什么"。答不上来的权限,现在就别给。

⚠️ **企业邮箱大概率接不上**(公司 IT 锁策略)。**不要在现场跟 IT 政策较劲**,直接让他用个人 Gmail,和 W1 一样的处理。

### 15:20–15:30|☕ 休息(10min)

- 助教把 ② 卡住的人拉到一边解决,**不要占用 ③ 的时间**
- 讲师检查直播状态(此时已恢复推流)、回线上提问
- **顺手做一件事**:把 ⓪ 没配上的 B/C 和还没收满人的 A 再撮一次,休息时间成功率最高

### 15:30–15:50|③ 给 agent 写工作说明书(20min)

> 取自 `L05` step 3(原 30min → 20min,讲 8min + 写 12min,靠填空模板提速)。
> **这是全节课教学价值最高的 20 分钟。** outline 原话:大多数人 agent 用不起来的真正原因不是模型不行,**是没人告诉它什么叫做完**。

#### 15:30–15:38|五个字段怎么写(8min)

| # | 字段 | ❌ 坏写法 | ✅ 好写法 |
|---|---|---|---|
| 1 | **负责哪几类任务** | 帮我处理杂事 | 只做三类:竞品监控 / 周报汇总 / 邮件起草 |
| 2 | **输入从哪来** | 网上 | 这 5 个竞品的 pricing page URL + 我的 SoT |
| 3 | **交付物长什么样** | 一份报告 | Markdown,300 字以内,必含「变了什么 / 没变 / 我该不该反应」三段 |
| 4 | **什么情况必须停下来找人** | (空着) | 要花钱 / 要对外发送 / 结论跟上周相反时,先问我 |
| 5 | **输出送到哪** | 给我 | 邮件到 ___,同时存 Drive `/agent-out/` |

**第 3 和第 4 条是分水岭。**
- 没写第 3 条 → 它每次交出来的东西格式都不一样,你还得自己整理,等于白干
- 没写第 4 条 → 它哪天自作主张替你回了一封客户邮件

#### 15:38–15:50|每人写(12min)

- 用填空模板,**不要从空白页开始**
- **A/B/C 差异化**:B/C 类还没自己的项目 → **给他刚加入的那个 A 的项目写一份 agent JD**,这就是他这周的实际贡献;彻底单干且没方向的 C → 给"帮我持续挖 [某行业] 痛点"写一份
- 写完**当场存进 agent 的 memory**,不是存本地某个文件
- **讲师和 TA 全场走动,只抓一件事**:第 4 条("什么情况必须停下来找人")空着的,当场追问"它要花你 200 刀你让不让它自己决定?"

---

### 15:50–16:35|④ Agent Schedule 工作坊(45min)⭐ 本节最硬的环节

> 合并 `L05` step 4 + step 5(原 40 + 30 = 70min → 45min)。
> **现场只讲透 2 个案例,另外 3 个走录播。** 选哪 2 个、为什么、另外 3 个怎么办 → **见 §4.4**。

#### 15:50–16:05|案例 ①:竞品监控(15min)—— 全场一起配

```
每天 7:00 → 抓竞品 pricing page → AI 总结变化 →
邮件推给你:「今天 X 涨了 $5、Y 推了新 plan」
```

**带练方式**:讲师投屏一步步配 → 学员跟着配 → **当场把执行时间改成"3 分钟后"** → **全场等它真的跑一次,举手确认收到邮件**。

> **为什么必须当场跑一次**:配好但没跑过 = 哑弹。学员回家等到第二天早上没收到邮件,这周的卧槽点就没了。**举手确认到 90% 才往下走。**

**这条 schedule 的输出直接喂 W3** —— 竞品定价对照表是下周做价格 anchor 的输入。讲师要说这句,让学员知道它不是玩具。

#### 16:05–16:20|案例 ②:周报(15min)—— 自己配,TA 巡场

```
每周日 18:00 → 邮件 + 日历 + agent memory → 出一份本周进展周报 → 存档
(有 repo 的人加一条 git log)
```

**为什么选这条**:它只用 W1 已经接好的 Gmail + Calendar,**今天在座每个人都有数据**。而且它是整门课的节奏发动机——W6 讲项目管理时,直接接着这份周报往下做。

**TA 按 ① 的分组 1:8 巡场**,重点抓:cron 写错(时区!澳洲不是 UTC)、输出没有收件人、memory 没接上。

#### 16:20–16:35|跨平台定时机制对照(15min)

> **这 15 分钟绝对不能砍。** outline 原话:讲清再选,**别用了一半才发现关机就不跑**。

| 机制 | 关机 / 睡眠还跑吗 | 代价 |
|---|---|---|
| Cowork `/schedule` | ❌ 要 Mac 醒着 + App 开着 | UI 最简单 |
| Claude Code cron skill | 看 wrapper + launchd 配置 | 要写一层 wrapper |
| Codex CLI 定时 | 看本机是否醒着 | — |
| OpenClaw cron | ✅ daemon 常驻,不依赖你的 Mac | 要有常驻环境 |
| n8n / Zapier scheduled trigger | ✅ 云端 | 有月费 |
| 系统 cron / GitHub Actions cron | ✅(GH Actions 云端) | 兜底方案,要动手 |

**讲完让每人回答一句**:「你选的那条,**你今晚合上笔记本它还跑吗?**」——答"不跑"的,当场决定:要么换机制,要么接受它只在你开机时跑,并把执行时间挪到你确定在用电脑的时段。

### 16:35–16:55|⑤ 验收 + 失败模式排错(20min)⚠️ 摄像机只对讲师

> 取自 `L05` step 6。

#### 16:35–16:45|同桌互验(10min)

**两人一组,互相验收对方的两条 schedule**,验三样:
1. cron 表达式(**念出来**:"每天早上 7 点"——念不出来的就是写错了)
2. **第一次跑的真实输出**(截图,不是"我配好了")
3. 工作说明书里的交付物格式,和实际吐出来的对不对得上

**讲师抽 3 人投屏**(自愿 + 提前问过),重点挑一个"输出很烂"的当众修——**修一个烂输出的教学价值,比看三个漂亮结果高**。

#### 16:45–16:55|五个失败模式,每人圈两个(10min)

| # | 失败模式 | 兜底 |
|---|---|---|
| 1 | **Mac 睡眠没跑** | 换云端机制 / 挪时间到开机时段 / 加一条"没收到就报警" |
| 2 | **API rate limit** | 降频次、加重试、错开时间点 |
| 3 | **输出爆 token** | 在说明书里写死字数上限 + 先摘要再总结 |
| 4 | **push 出来没人看** | 送到你**每天真的会看**的地方(不是一个没人开的频道) |
| 5 | **AI 答错没人发现** | 强制每条结论带**原始链接**,你抽查一条就能发现它在编 |

**每人挑自己最可能踩的两个,当场加兜底。** 不加兜底不算过关。

> 第 5 条要重点说:`L06` 的验收标准就是"每条痛点都要能点回原始帖子链接,**没有出处的痛点一律划掉**"。同一条纪律。

## 4. 关键内容展开

### 4.1 那 30 分钟是从哪挤出来的(取舍方案)

`L05` 六个 steps 原始时长合计 **180min**,而现场也只有 180min。加进 30min 分享 + 10min 休息 + 5min 派活,**必须砍掉 45min**。

| 环节 | 原 | 现 | 砍了多少 | 理由 |
|---|---|---|---|---|
| ① 四路线选型 | 30 | **20** | −10 | 深度对照是**读物**不是讲授。四路线对照表 + 一段预习材料放课前,现场只做"决策 + 举手" |
| ② 装上 + 接权限 | 30 | **30** | 0 | **一分钟不砍。** W1 已经在授权上吃过亏;权限边界讲漏一条是安全事故 |
| ③ 工作说明书 | 30 | **20** | −10 | 讲 8min + 填空模板写 12min。省下的 10min 是"从空白页开始"的时间,模板解决 |
| ④⑤ Schedule 工作坊 | 70 | **45** | −25 | **现场只讲透 2 个案例,另外 3 个录播**。理由见 §4.4——不是时间不够,是那 3 个案例的前置资产学员现在还没有 |
| ⑥ 验收 + 失败模式 | 20 | **20** | 0 | 不砍。验收环节一砍,前面全变成"配好了没跑过" |
| **合计** | **180** | **135** | **−45** | 换来 30(分享)+ 10(休息)+ 5(派活) |

**为什么砍在这三处而不是别处**:
1. **动手环节的时长不能砍到"跑不通"**——这门课的失败方式是学员回家发现啥也没跑起来,不是听得不够多
2. **能变成读物的一律变读物**(①),能变成模板的一律变模板(③),能延后到资产就位再做的一律延后(④)
3. **安全相关的一律不砍**(②的权限边界、⑤的失败模式兜底)

**⚠️ 这个砍法带来一处和 outline 的口径冲突**:`L05` 的「现场过关」写的是"每人当场跑通 **5 条** Agent Schedule 的配置"。按本方案是**现场 2 条真跑通 + 周中靠录播补 3 条**。
**本周产出口径不变**(仍是"3 条以上跑过一次并有输出")。要不要改 outline 那句话 → **待 Lightman 拍板(§8)**。本教案不动 outline。

### 4.2 组队集市为什么这么设计

**要解决的三个真问题**:

| 问题 | 设计上的解法 |
|---|---|
| A 类里有人不想公开 idea | 按 `projectVisibility` 分档:`stealth` 不上台、桌牌只写要什么角色;`match-only` 上台前当面确认尺度 |
| 明星项目把人全吸走 | **一个 A 最多收 2 人**,硬规则,助教执行 |
| 有人没人要,当场很难堪 | 三条退路:①"本期单干"是**正当选项**,写进登记表;② 没配上的进"待撮合",课后 48h 人工撮合;③ C 类可以"跟练"不入队 |

**不做的事**:
- ❌ 不做算法匹配(`FOUNDER_MATCHING_PRD` §3 明写 MVP 不做自动匹配)
- ❌ 现场不谈股权分成(推到 W7 法律文件环节)
- ❌ 不强制组队(强制来的队两周就散)

### 4.3 四条路线怎么讲(含未落实项)

**能讲的**(有 outline 明确口径,照讲):每条路线的定位、适合谁、要不要终端。

**⚠️ 现在讲不了、必须课前补的**:

| 缺什么 | 为什么不能现编 |
|---|---|
| **四条路线的当期实际费用**(月费 + API 消耗,澳币) | 这群人 senior,报一个错数字当场就被拆穿;而且直接影响他们的选择 |
| **Hermes / 龙虾(OpenClaw)当期是否真的可用、怎么拿到** | outline 只写了定位,**没有落实获取路径**。讲师课前必须自己走一遍全流程 |
| **Windows 学员怎么办** | 四条路线里哪几条 Windows 能跑、要不要 WSL2,现在没有结论 |
| **默认推荐路线** | 犹豫的人需要一个答案。没有默认答案 = ④ 有人跑不起来 |

**处理原则**:讲师课前把这四格填掉再上课。**填不掉的当场直说"这条我还没验证过,今天不推荐你选"**,不要编。

### 4.4 五个 Schedule 案例:现场讲哪 2 个,另外 3 个怎么办

**选择依据不是"哪个最酷",是"学员今天手上有没有这条 schedule 需要的数据"。**

| 案例 | 需要什么前置资产 | 学员现在有吗 | 处理 |
|---|---|---|---|
| ① 竞品监控 | 竞品清单 + SoT | ✅ W1 就有 | **现场讲透,全场一起配** |
| ④ 周报 | 邮件 + 日历 + memory | ✅ W1 已接 | **现场讲透,自己配 + TA 巡场** |
| ② SEO 周报 | GSC 数据 → **要先有官网** | ❌ 官网 W5 才做 | 录播 + 配置模板,**W5 之后再配** |
| ③ 财务月报 | Stripe + Xero | ❌ Stripe W7 才接,Xero W12 | 录播 + 配置模板,**W7/W12 再配** |
| ⑤ git 日报 | 一个真实 repo | ❌ MVP W4 才开工;不写代码的人永远没有 | 录播 + 配置模板,**W4 之后再配** |

**这个排法额外的好处**:另外 3 个案例天然在后面的周被重新触发——W4 讲完 MVP 回来配 git 日报、W5 官网上线回来配 SEO 周报、W7 收到钱回来配财务月报。**Agent Schedule 变成一条贯穿全课的线,而不是 W2 讲完就扔。** 讲师要在 ④ 结尾把这句话说出来。

**⚠️ 录播 3 个案例目前不存在**(待录,见 §8)。**在录播就位之前,这个方案不成立**——只能退回"现场硬讲 5 个,砍掉别的地方"。这是本周定稿前最需要 Lightman 决策的一项。

## 6. 讲师要盯的坑(按发生概率排)

| 坑 | 后果 | 怎么防 |
|---|---|---|
| **⓪ 30 分钟超时** | 直接吃掉 ③ 或 ④,当天跑不通 | 助教硬计时,14:25 无条件回座;上台名单**签到时就定好**,不现场找人 |
| **公司电脑装不了 CLI** | 这个人今天全程旁观 | 课前要求自测;现场备"浏览器可跑"的路线;实在不行**先跟同桌共用一台把说明书写完** |
| **schedule 配好但没当场跑** | 周中全是哑弹,卧槽点不发生 | ④ 案例①**强制当场改成 3 分钟后跑一次**,举手确认到 90% 才往下走 |
| **cron 时区写错** | 半夜三点跑 / 根本不跑 | TA 巡场第一件事就是核时区(澳洲不是 UTC),让学员**念出来**"每天早上 7 点" |
| **权限给太宽** | 出真事故(替你发信 / 动主干) | ② 的边界卡逐条过;第 4 条("什么时候停下来找人")空着不放行 |

| **组队冷场 / 有人没人要** | 当场难堪,可能流失 | "单干"是正当选项;没配上的进待撮合,**课后 48h 人工撮合** |
| **写完说明书没存进 memory** | 下次对话它啥也不记得 | ③ 收尾时逐组确认"存进去了吗",不是"写完了吗" |
| **L08 五场访谈拖到周日** | W3 手上没弹药,被 Stan 拆的时候是空的 | ⑥ 排死时间:周二晚前约到,周日晚前做完;周三班级群查一次进度 |
| **stealth 学员 idea 被上直播** | 信任崩塌,不可挽回 | 断流写进直播运营 checklist,**由专人按按钮,不是讲师兼职** |
