# 第七节课 Runsheet《Subagent》· 直接照讲

> 主题：**给 context 分家 —— 该派什么、不该派什么**
> 时长：**120 分钟**动手工作坊（两次实验：一次正收益，一次红灯）
> 全程口径：**Vibe Coding —— 教怎么判断、怎么写、怎么收，不教任何参数和配置。**
> 工具：老师投屏 + **学员需要能跑的环境**（这是相对 L6 最大的变化，L6 学员可以不带电脑，本节不行）。deck 22 页。
> 红线：过关标准不是「我成功派出去了」，是**学员亲手测到了派错的代价，从此默认不派**。
> 页码对照：本文 `(P09)` 指 deck 的 `L7P09`，即第 10 页（page N = P(N−1)）。

> **这节课和 L6 的根本差别**
> L6 是诊断课，学员看投屏就行。**本节两次实验都要学员自己跑**，所以课堂管理的分量远大于讲稿分量。
> 这份 runsheet 里，§5 和 §8 两段实验手册比任何一段讲稿都重要——**那两段砸了，这节课就白上了。**

## 2. 开场（10 分钟，P00–P02）

### P00 封面（30 秒）

> 「今天这节课只有一句话。你要是只带走一句，就带这句：**子 Agent 不是多一个人手，是多一个独立的 context。**
> 现在听不懂没关系，第 3 页我会讲透。」

### P01 L6 的病（3 分钟）

投那一坨「不是这里」，问两句（**等学员答，不要自己接**）：

> 「哪些信息是下最终结论真正需要的？」
> 「哪些信息只在探索当时有用，却永久占着主 context？」

学员会答第二个多。收口：

> 「所以问题不是它笨，是**它读到的东西里，绝大部分是垃圾**。」

### P02 问题在结构（5 分钟）

这一页是 L6 到 L7 的桥，别快过。

> 「先看左边——按 L6 那四格，你交得很好：目标清楚、边界划了、验证点给了、里程碑也留了。四项全对。
> 然后它还是跑歪了。
>
> 为什么？看右边。它得干两件事：**到处翻** 和 **下结论**。
> 到处翻会产生大量噪音，下结论需要干净的判断。
> 你把这两件事塞进了同一个 context——等于让『下结论』那一轮，读到『到处翻』留下的全部垃圾。」

**收口那句要顿一下**：

> 「**问题不在你交得不好，在结构。** 指令再调也治不了。今天换的是结构。」

## 3. 立论（14 分钟，P03–P04）· 全课最重要的一段

### P03（10 分钟，慢讲）

**这一页占 10 分钟不是浪费，讲不透这一句，后面全是零散技巧。**

先念标题，然后停：

> 「不是多一个人手。是多一个**独立的 context**。
> 这两个说法听起来差不多，实际差很远。」

对比图左右各讲一遍：

> 「左边是 L6：主 Agent 读 50 个文件，context 里堆了 39 份『不是这里』。那 39 份垃圾会一路影响它后面每一轮判断。
> 右边是分家：每个子 Agent 有**自己的** context，各自翻各自的模块，回来的只有结论。
> **主 context 只多了三条结论，没多 39 份垃圾。**」

然后是这页真正的价值——四条推论。逐条点，每条问一句「你们看这是不是自然的」：

| 推论 | 怎么讲 |
|---|---|
| **收益** | 「脏活在它的 context 里发生」——这是「独立」两个字直接推出来的 |
| **代价** | 「独立 context 要从零建，而且它看不见你的对话」——**独立是双向的** |
| **铁律** | 「要它知道的必须写进指令」——因为它读不到你的对话 |
| **冲突** | 「context 隔离了，文件系统没隔离」——独立的只有 context，不是别的 |

收口：

> 「所以今天后面所有内容，都不是新知识点，是**这一句的推论**。你要是这句听懂了，剩下的应该都能自己想出来。」

### P04 Hub-and-spoke（4 分钟）

重点在「它们之间没有连线」这一句要**同时讲能力和边界**：

> 「能力：每个子 Agent 的噪音留在自己那边，主 context 不被污染。
> 边界：**A 的发现不会自动传给 B。** 要传，只能经过你或主 Agent。」

**一定会有人问「那要是它们需要互相说话呢」。标准答复**：

> 「那是下节课的结构。今天先把这一种用透——而且我告诉你，**大部分任务根本不需要它们说话**，下节课你会看到组队的门槛比这个高得多。」

## 4. 收益代价 + 两层门 + 预检 + 选档 + brief + 落盘（34 分钟，P05–P12）

这一段是「工具化」段落，节奏可以快，但有五个地方必须停：

### P05（4 分钟）· 停在「独立视角」

> 「三项强收益里，标了红的那一项——**独立视角，是唯一一个 1 个子 Agent 就能拿满的**。隔离和并行都要量。
> 记住这条，最后一页有用。」

### P06（6 分钟）· 6 张任务卡第一次投票

**先投票，再讲两层门，然后再投一次。** 不要反过来。

> 「先凭直觉投，别想太多。投完我给你尺子，再投一遍——**我要的不是你投对，是你看到自己前后变了没有**。」

第二次投完，问 2–3 个改了票的学员：「你为什么改？」——**这就是他们自己长出来的第一段判断线**。

### P07（4 分钟）· 预检卡

把你课前实测的结果投出来，逐行念。然后停在两件必须明示的事：

> 「第一，**继承是有选择的**：项目规则会自动到位，**对话历史不会**。你在聊天里排除掉的那三个方向，它一个都不知道。
> 第二，**能开几个不是问题**。上限远大于我们今天要用的三路。**限制从来不是瓶颈，判断力才是。**」

### P08（4 分钟）· 两个旋钮

> 「模型档和思考力度是两个旋钮，同一条判断线：**跟判断密度走，不跟重要性走。**
> 『这个角色重不重要』是错的问法。要问的是：它是在做判断，还是在做检索？」

底下那条一定要说：

> 「**低力度会想当然。** 工具调用变少的直接后果就是少查一次。所以给低档那几路的 brief 里，『附文件:行号』更不能省——那是逼它真的去查的唯一手段。」

### P09（4 分钟）· 构成

这一页的作用是给下一页铺路，讲法就一条线：

> 「你能写的只有左边那一点点——name、description、正文。
> 右边全是运行时自动组装的，**你控制不了**。项目规则和 git 快照自动到位，**你的对话历史拿不到**。
> 而它只还回来最后那段文字，中间读的每个文件都留在它自己那边。」

指 transcript 那块：

> 「『独立 context』不是比喻——它真的落在**另一个文件**里，一个子 Agent 一个文件。主对话被压缩都动不了它。」

（**有时间就当场 `ls` 一下那个目录**，比讲十遍有说服力。）

收口接下一页：

> 「所以下一页那六格，不是我定的规矩，是**必然**。」

### P10 六格 brief（6 分钟）· 拿坏 brief 现场改

**不要逐格念。** 投坏的那句，问：「这句话派出去，它会干什么？」

学员会说「不知道从哪开始」「可能乱改文件」。然后逐句补：

> 「加边界 → 加证据要求 → 加禁止项 → 加『不知道』的出口。」

### P11 怎么派（4 分钟）

三档讲完，停在①和②的差别：

> 「①和②的差别本身就是今天的一个教学点：**『我说了』不等于『它照做了』。**」

然后逐句拆解那条好指令。**最后一条要重读**：

> 「『若证据不足，返回无法判断 + 缺什么证据』——这条最容易漏。
> **不给出口，等于逼它猜。** 它猜出来的东西，读起来跟真的一模一样。」

### P12 怎么落盘（3 分钟）· 全课唯一给命令的一页

**先说清楚这一页为什么特殊**：

> 「今天全程我不教参数、不教配置。**这一页是唯一的例外。**
> 因为你不知道文件放哪、不知道怎么触发，回去就落不了地——判断线再对也没用。」

三种建法扫一遍，重点在**放哪决定谁能用**：

> 「项目级能 commit，全班共用同一份角色；个人级跟着你走，所有项目都能用。同名时项目级赢。」

然后给命令，**@ 提及那条要停一下**：

> 「记住 ② 这个。①是点名，它自己决定派不派——会漏。**② 是保证这个角色跑。**
> 上课演示、你回去做作业，都用 ②。」

那个坑必须念，**否则学员回去会浪费十分钟**：

> 「`/agents` 已经不是创建向导了。跑它只会提示你去问 Claude 或直接编辑目录。
> 网上不少教程还在教那个向导——那个已经没了。」

收口回到判断：

> 「什么时候值得落盘？文件里装的是**每次都一样**的部分：职责、工具边界、输出格式、判据。
> **每次不一样的还是得当场说**——这次查哪个目录、这次已排除了什么。」

> 💡 **有时间可以加**：附录 D 里三份现成的角色文件（调查员 / 实现者 / 验收员），课后发。三份都做到同一件事——**范围不是靠正文嘱咐，是靠 `tools` 字段物理限制**。

## 5. 🔴 动手 A（17 分钟，P13）· 实验手册

### 发题（2 分钟）

发附录 A。**投屏念一遍统一问题和三路边界，确认所有人在同一页上。**

> 「三件事：① 三路必须只读，谁都不许改文件。② 用统一返回格式，不然待会儿汇总不了。③ **观察卡边跑边填**，别等结束再回忆。」

### 跑（12 分钟）· 你在干什么

**不要站着看。** 巡场，重点抓四种人：

| 现象 | 你说什么 |
|---|---|
| brief 写得太短（一句话就派了） | 「你这个 brief 它读得懂吗？第 3 格呢——它知道你已经排除了什么吗？」 |
| 三路边界重叠了 | 「你 A 和 B 都会读 src/ 下的东西，等下你怎么知道哪条结论是谁的？」 |
| 忘了填观察卡 | 「时间记了吗？没记的话待会儿判断线你拿什么写。」 |
| 已经跑完了 | 「去看它的 not_checked。它说没检查的那部分，会不会正好是关键？」 |

### 🚨 到 71 分钟统一停（不管跑没跑完）

> 「停。没跑完的**不要重跑**——拿你手上的 partial 回执，它照样能进汇总。
> 而且我跟你说，**partial 回执反而是好教材**：它明确告诉你哪块没查，这比一份假装查完的报告有用得多。」

## 6. ☕ 休息（5 分钟）

巡场时确认两件事：① 有没有人环境彻底跑不动（有的话让他和邻座并组，用别人的数据做后面的部分）；② 有没有人三路结果完全一样（说明边界没划开，讲评时可以当反例）。

## 7. A 讲评 + 汇总矩阵（8 分钟，P14）

抽 2 个人投屏。**问的不是「你查到什么」，是「你怎么知道它没漏」。**

投 P14，走四个必答问题。重点砸第 2 和第 4：

> 「第 2 个——**两条结论互相矛盾了吗？** 你要是三份报告拼一起没发现矛盾，八成是你没对着看。
> 第 4 个——**哪些地方没检查？** 这一栏空着的，等于你不知道自己不知道什么。」

收口：

> 「**不许把三份报告拼起来。** 拼接不会暴露冲突和缺口，矩阵才会。最后一列『主 Agent 决定』是你的活——矩阵填满不等于收口。」

## 8. 🔴 动手 B 红灯（12 分钟，P15）· 实验手册

> **这一段是全课最容易砸的地方。** 砸的方式只有一种：**差距不明显**。
> 如果学员派出去也就多花 30 秒，这一页的全部说服力就没了，而且他们会得出反结论——「派出去也没多贵嘛」。
> **所以微任务必须课前实测过（附录 B 有验收标准）。**

### 发题（1 分钟）

> 「这次的任务：**定位某个常量定义在哪个文件**。就这么简单。
> 你要做两件事：**真的派出去一次**，同时**自己也顺手做一遍**。两边都计时。」

**强调「真的派」**：

> 「别偷工。写 brief、等它回来、读回执——按你平时的做法完整走一遍。
> 我知道你现在就想说『这不用派』——**对，但我要你亲手测到那个数字**，不然回去你还是会派。」

### 跑（8 分钟）

巡场就问一句：**「两边各花了多久？」** 让他们说出数字，说出来的数字比自己心算的印象深。

### 收（3 分钟）

抽 3 个人报数字。然后投 P15 右边：

> 「你们报的和我课前测的差不多。左边两步，右边五步。
>
> 现在关键问题——**过关答案不是『派出去也能做』**。
> 是：它**没有强收益**。噪音量不够、没有并行分支、不需要独立视角。**三项一项都没命中，第一层门就没过。**」

收口重读：

> 「**能派出去完成，不代表应该派出去。**」

## 9. 判断线（9 分钟，P16）· 引导，不给答案

**这一页你的任务是闭嘴。**

> 「翻出你那两张观察卡。现在写六条——我会派的三条，我不会派的三条。
> **不许抄我的**，抄了这页就白上了。写你刚才两次实际测到的东西。」

给 5 分钟静默填写。然后抽 3–4 人念，**你只做一件事：追问依据**。

| 学员说 | 你追问 |
|---|---|
| 「任务大的时候派」 | 「多大？你刚才两次分别是多大？」 |
| 「简单的不派」 | 「简单是什么意思？用你观察卡上的哪个数字判断？」 |
| 「要读很多文件的时候派」 | 「多少算很多？动手 A 那次读了几个？」 |

**目标不是让他们写对，是让每一条都能追溯到自己的数字。**

最后 2 分钟讲工具倾向校准：

> 「还有一条：**观察你手上这个工具偏哪边。**
> 有的偏保守，该派不派；有的过度热情，一点小事也开一堆。
> 我教的不是多派或少派，是**掌握判断线，然后往你的工具的反方向校准**。
> 这个教法不会过期——工具换了、模型升级了，判断线还成立，你只需要重新观察一次它的默认倾向。」

## 10. 底线（9 分钟，P17–P20）· 四页快讲

**这一段每页 2.5 分钟，别恋战。** 学员这时候已经累了，给判断不给细节。

- **P17** — 四层矩阵扫一眼，重点只说口诀三条 + 那句「最坏的一种翻车：**context 隔离了，workspace 却在打架**」。
- **P18** — 坏回执三行反例念一遍。收口：「回执的作用不是让它交作业，是**逼它把『没做什么』也说出来**。」
- **P19** — 三件事对照表。重点：「『再找一个 Agent 看看』**不是 verifier**——它不知道要查什么，回来一句『看起来没问题』，你付了成本买了个安慰。」
- **P20** — 最小配置阶梯。收口回扣 P05：「还记得吗？**独立视角是唯一一个 1 个成员就能拿满的**。所以回去先做那一个。」

## 13. 讲这节课的三个注意

**① 别在开场就给判断线。**
这节课的结构是「先撞墙，再给尺子」。你在第 20 分钟就把「什么时候该派」讲完了，那两次实验就只是验证，不是发现。学员自己测出来的判断线，和你给的判断线，回去之后的留存率差一个量级。

**② 红灯那段别心软。**
一定会有学员在第 84 分钟说「老师这个明显不用派啊」。**你要说：对，但我要你亲手测。** 因为「知道不该派」和「测过不该派的代价」是两回事——只有后者能在他下周真的想派的时候拦住他。

**③ 「不假设继承」要讲三遍，而且是三个不同的面。**
- P07：**项目规则会到位，对话历史不会**
- P09：**它只还回来最后那段文字**，中间什么都不带回来
- 蓝图 §18.5（口头补充）：**每次调用都是新实例**——你说「继续刚才那个」，它其实是第二个全新的，什么都不知道

第三条不上 slide，但值得在 P09 讲完口头加一句——它是最反直觉的一个面。

# 附录 D · 三个可直接抄的角色文件

> 建好放 `.claude/agents/`（项目级，可 commit 全班共享）或 `~/.claude/agents/`（个人级）。
> **课后作业和延伸模块（蓝图 §15.1 角色化接回 L5）都用这三份当起点。**
>
> 三份正好覆盖 deck P08 的判断密度表和 P20 的最小配置阶梯：
> 调查员 = 执行密集（中间档 / 低力度）· 实现者与验收员 = 判断密集（最强档 / 高力度）。
> **回去先建第三个**（验收员）——它是 1 个成员就能拿满「独立视角」的那一个。

## D.1 研究 / 调查 Agent

用在动手 A 那种「要读很多地方、只要结论」的场景。**执行密集，给便宜档 + 低力度。**

```markdown
---
name: readonly-investigator
description: 只读调查员。需要在一个明确边界内翻大量文件、找证据、给结论时使用。不修改任何文件。
tools: Read, Grep, Glob
model: sonnet
effort: low
---

你是只读调查员。你的产出是**证据**，不是意见。

## 范围
- 只在委派消息给定的目录 / 模块内工作。
- **不修改任何文件。** 不要顺手优化、不要补测试、不要改配置。
- 边界外的东西即使看起来相关，也只记录、不深入。

## 产出合同
用下面的格式返回，不要自由发挥：

status: complete | partial | blocked

## findings
- 结论：______
  evidence: `path/to/file:line` + 一句解释
  impact: ______

## checked
- 列出你实际看过的路径

## not_checked
- 列出你**没有**看的、但可能相关的范围

## assumptions_or_risks
- 你做了哪些假设

## 硬规则
1. **每条结论必须有 `文件:行号`。** 没有出处的判断不要写进 findings，写进 assumptions。
2. **`not_checked` 不许空着。** 你一定有没看的地方，把它列出来。
3. 证据不足时返回「无法判断 + 缺什么证据」，**不要猜**。
4. 没做完就返回 `partial`，不要装成 `complete`。

## 停止条件
- 需要修改文件 → 停下来报告，不要动手。
- 需要越过边界才能继续 → 停下来说明为什么。
```

> **为什么给低力度**：它的活是「找到并复述」，不需要反复权衡。但低力度的副作用是**少查一次**——所以上面第 1 条硬规则（必须附行号）不能省，那是逼它真的去查的唯一手段。

## D.2 开发 / 实现 Agent

用在「边界明确、验收命令已知」的改动。**判断密集，给最强档 + 偏高力度；并且必须做写入隔离。**

```markdown
---
name: scoped-implementer
description: 限定范围的实现者。用于边界清楚、验收命令已知的改动。会写文件，所以只在划清所有权后使用。
tools: Read, Grep, Glob, Edit, Write, Bash
model: opus
effort: high
isolation: worktree
maxTurns: 40
---

你是限定范围的实现者。你的成功标准不是「写完了」，是**验收命令跑绿**。

## 范围与所有权
- 只动委派消息里明确列出的文件或目录。
- **明确不要碰**：配置、CI、依赖清单、以及任何没被点名的模块。
- 不要顺手重构、不要加抽象、不要为不可能发生的情况加防御。

## 工作方式
1. **先给计划再动手**：改哪些文件、什么顺序、每步怎么验证。等确认。
2. 每完成一个文件，跑一次委派消息里给的验证命令。
3. 验证不过就停下来报告，**不要连着改第二个文件**。

## 产出合同
完成时按完成回执格式返回，必须包含：
- `changes`：改过的每一个文件
- `validation`：实际跑了什么命令、结果 pass / fail / not_run（附原因）
- `not_checked`：你没验证到的部分

## 硬规则
1. **不许把没跑过的验证写成「应该通过」。** 没跑就写 `not_run` 加原因。
2. 遇到需要改边界外文件才能完成 → 停下来问，不要自己扩大范围。
3. 计划被拒绝就改计划，不要绕过。

## 停止条件
- 同一个错误改第三遍 → 停，报告你试过什么。
- 需要动边界外的东西 → 停，说明为什么。
- 验收命令跑不起来 → 停，不要假设它会过。
```

> **`isolation: worktree` 是这份的关键**：它给这个 Agent 一份独立的工作副本，改动不会和主线或其它 Agent 打架。这正是 deck P18「context 隔离 ≠ workspace 隔离」的解法——**要并行写，就得这样隔**。
>
> `maxTurns` 是兜底止损，对应六格第 6 格「停止与升级条件」。

## D.3 审查 / 验收 Agent

**最小配置就用它一个。** 判断密集，给最强档 + 高力度，而且**必须只读**。

```markdown
---
name: readonly-verifier
description: 只读验收员。实现完成后，按明确的验收判据逐条给红绿。不修改成品，不替作者辩护。
tools: Read, Grep, Glob, Bash
model: opus
effort: high
---

你是只读 verifier。

你的价值来自**独立**——你没参与实现，所以你能看见实现者的盲点。
不要试图理解或体谅实现者的思路，那会污染你的判断。

## 输入
成品 / diff / 需求 / 验收规则。

## 你要做的
对**每一条**验收判据，逐条输出：

- criterion: ______
- verdict: pass | fail | cannot_determine
- evidence: ______
- required_fix_or_missing_evidence: ______

## 硬规则
1. **只有所有必选 criterion 都 pass，才能给总体 green。** 有一条 fail 就是红。
2. **`cannot_determine` 是合法答案，而且比猜一个 pass 好得多。** 判据不足以判断时就这么写，并说明缺什么。
3. **每条 verdict 必须有 evidence**：文件行号、命令输出、或测试结果。没有证据的 pass 不算 pass。
4. **能跑就跑。** 判据里提到的测试 / 构建 / 检查命令，你要实际执行，不要读代码推断它会过。
5. 不要修改成品。发现问题写进 `required_fix`，由实现者去改。

## 你不该做的
- 不要重做实现者的探索过程（那是付两次成本）。
- 不要因为「看起来没问题」就给 pass——**你要说的是「按第 N 条判据，证据是 X，所以 pass」**。
- 不要在报告里替实现者解释为什么这样做是合理的。
```

> **为什么这份最值得先建**：三项强收益里「独立视角」是唯一一个 1 个成员就能拿满的，而且它不需要并行、不需要协调、不需要汇总矩阵——**冷启动是唯一成本**。
>
> **进阶（蓝图 §18.8）**：把这一份跑在跟实现者**不同的模型家族**上。同一个模型的两个 context 共享同样的偏好和盲区；换个家族，独立性硬得多。

## D.4 三份放一起看

| | 调查员 | 实现者 | 验收员 |
|---|---|---|---|
| 判断密度 | 执行 | 判断 | 判断 |
| 模型档 | 中间 | 最强 | 最强 |
| 力度 | 低 | 偏高 | 高 |
| 能写文件 | ✗ | ✓（隔离副本） | ✗ |
| 最该先建 | | | **✓** |

**共同点——这三份都做到的一件事**：范围不是靠正文里嘱咐，是靠 `tools` 字段**物理限制**。

调查员和验收员压根没有写文件的能力，实现者的写入被隔离在独立副本里。这是六格 brief 里唯一一格能从「请求」变成「保证」的——**其它五格硬化之后仍然只是更详细的 prompt。**
