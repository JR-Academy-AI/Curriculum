# Vibe Coding 大师课 · 第六节蓝图（草稿·暂定）

> 状态：DRAFT 0.1
> 主题：从静态到动态（原拟第五节，现顺延；L5 改讲 Skills） —— Vercel Functions（`api/`）+ Auth + Database，把产品做"活"
> 课型：120 分钟动手工作坊
> 本文只定义课程，不包含 deck 实现。
> 承接第四节：L4 把产品交付成了「静态、能看」；L5 让它「动态、能用」。

## 1. 课程定位

第四节交付了一个**静态产品**：别人能访问、每次提交自动验证和部署。但它有三个"死"的地方：

1. **没有账号** —— 谁来都一样，记不住你是谁。
2. **存不下东西** —— 刷新就没，换个设备更没。
3. **没有服务端逻辑** —— 凡是涉及密钥、鉴权、写数据库的，都做不了（前端做等于把钥匙贴在门上）。

第五节把这三样补齐，而且**不离开 L4 那条链路**：后端就放在**同一个 Vercel 项目的 `api/` 目录**里（Serverless Functions），同仓、同一次部署、同一个域名。

```text
L4 交付的静态产品（能看 · 不能用）
              ↓  加一层服务端
      Vercel Functions（api/）
        ↙                ↘
     Auth              Database
（它知道你是谁）      （存得下 · 取得回）
              ↓
L4 留下的 authAdapter / readingStore 占位 → 填成真实现
              ↓
动态产品（能登录 · 能存 · 只看得到自己的）
```

一句话定位：

> 第四节让产品"能被访问"；第五节让产品"能被使用"—— 而且后端不另起服务，就长在你已经会部署的那个 Vercel 项目里。

## 2. 学员起点

学员上课前应有：

- 第四节的产物：一个已上线的**静态项目**（GitHub repo + Vercel 部署），代码里留着 `authAdapter` / `readingStore` 这类**占位接口**。
- 一个明确的"要存什么"需求（来自各自 PRD，如"保存我的测算记录"）。
- GitHub / Vercel 账号（L4 已备）。
- 本机可运行 Node、Git、Claude Code。

没带 L4 产物的学员用老师提供的**兜底 starter**（已含占位接口 + 一个待填的 Flow）。

## 3. 学习目标

课程结束后，学员能够：

1. 说清**静态 vs 动态**的分界：哪些必须上服务端（密钥 / 鉴权 / 写库），哪些留前端。
2. 让 Agent 写出第一个 **Vercel Function**（`api/` 端点），本地（`vercel dev`）和线上都能跑。
3. 用**环境变量**管密钥（本地 `.env.local` + Vercel 环境变量），确认前端和 git 里都拿不到。
4. 接一个**托管 Auth**（邮箱登录），在服务端拿到"当前是谁"。
5. 接一个**托管数据库**，建最小 schema，做一条"保存 + 读取"，且**带所有权**（只能读自己的）。
6. 把 L4 的 `authAdapter` / `readingStore` **占位换成真实现，前端零改动** —— 体会 SoT / adapter 边界的威力。
7. 端到端验收：登录 → 保存 → 刷新 / 换设备仍在 → 只看得到自己的数据。
8. 过一遍**安全自查**：密钥没进前端 / git、鉴权在服务端、别人拿不到你的数据。

## 4. 非目标

本节明确不做：

- 不自己手写鉴权 / 密码哈希 / JWT 签发（用托管方案）。
- 不讲复杂 ORM、数据库迁移工程、分库分表、索引调优。
- 不讲支付、实时 / WebSocket、文件上传、消息队列。
- 不讲 Docker / K8s / 自建服务器 / 运维。
- 不追求把业务功能做全，只打通**一条动态 Flow**（登录 + 存一样东西 + 只读自己的）。

## 5. 核心教学决策

### 5.1 后端就是同仓 `api/` Functions，不另起服务
为了不离开 L4 已经跑通的 Vercel 链路，后端统一用 **Vercel Serverless Functions**：项目里加一个 `api/` 目录，每个文件就是一个端点，跟前端同一次部署、同一个域名。不引入独立后端框架 / 独立服务器。

### 5.2 Auth 和 DB 都用托管，不自建
- **Auth**：托管方案（Supabase Auth 或 Auth.js），负责邮箱登录、给出"当前用户"。**不自己写密码体系**。
- **DB**：托管 Postgres（Vercel Postgres 或 Supabase），最小 schema。**不做迁移工程**。
- Functions 只当"薄薄的 API 层"：接住请求 → 校验身份 → 读写库 → 返回。

### 5.3 全程 Vibe Coding 口径（延续 L4）
Functions、auth 接线、建表，都是"**你对 Agent 说人话 → Agent 写 → 你 review + 验证**"。你盯的是 Agent 保证不了的三件事：**密钥在不在服务端、鉴权在不在服务端、别人能不能拿到你的数据**。

### 5.4 从"占位"到"真实现"，接口不变
L4 留下的 `authAdapter` / `readingStore` 接口**不改**，只把背后的实现从 mock 换成"调 Functions"。这是本节最重要的体验：**定好接口（SoT），换实现不动上层**。

### 5.5 安全是第一课，不是附录
本节自带一个"安全直觉"主线：**密钥只在服务端（环境变量）、永远别信前端传来的身份、每条数据都要校验所有权**。用一个"数据隔离实验"（见 §8）让学员亲眼看到隔离生效 —— 对标 L4 的"红灯实验"。

## 6. 课堂最终产物

每位完成者应有：

- 一个**能登录**的线上产品（邮箱登录）。
- 至少一个 **Vercel Function**（`api/` 端点）线上可调。
- 一个**托管数据库** + 一张最小表。
- 一条**"保存 + 只读自己的"闭环**，线上跑通。
- 密钥**全在环境变量**，前端 / git 无泄漏。
- `authAdapter` / `readingStore` 从占位变**真实现**，前端未改。
- 一份**安全自查记录**。

## 7. 120 分钟流程

| 时间 | 阶段 | 课堂动作 | 阶段产物 |
|---|---|---|---|
| 0–10 min | 开场 | 回顾 L4：交付了静态，但"能看不能用"，缺了什么 | 今日动态地图 |
| 10–20 min | 静态 vs 动态 | 分清哪三样必须上服务端（密钥/鉴权/写库） | 一条"上不上服务端"判断线 |
| 20–32 min | 第一个 Function | Agent 写 `api/hello`，`vercel dev` 本地跑，前端 fetch | 一个可调的端点 |
| 32–45 min | 密钥与环境变量 | `.env.local` + Vercel 环境变量；证明前端/ git 拿不到 | 密钥只在服务端 |
| 45–60 min | 接 Auth | Agent 接邮箱登录，服务端拿到 currentUser（填 authAdapter） | 能登录、知道"你是谁" |
| 60–65 min | 休息 | —（口头） | — |
| 65–85 min | 接 DB + 写 | Agent 建最小表 + 写"保存"Function（带 userId） | 存得进去 |
| 85–100 min | 读 + 所有权 | readingStore.list 只返回自己的；数据隔离实验 | 取得回、且隔离 |
| 100–112 min | 占位填真 | authAdapter / readingStore 占位 → 真实现，前端零改动，端到端跑通 | 动态一条龙 |
| 112–120 min | 安全自查 + 收尾 | 过安全清单，对照 PRD 验收；布置作业 | 安全自查记录 |

## 8. 各阶段教学细节（要点）

### 静态 vs 动态（判断线）
一句口诀：**"要藏的、要认人的、要记住的，上服务端；其余留前端。"** 密钥（要藏）、登录态（要认人）、数据库读写（要记住）—— 这三样前端一碰就出事。

### 第一个 Function（投屏指令示意）
```text
在项目里加一个 Vercel Function：api/hello，返回 { ok: true, time }。
告诉我怎么用 vercel dev 在本地跑，前端怎么 fetch 它。
先讲清 api/ 目录为什么就是后端，再动手。
```

### 密钥铁律
- 密钥进 `.env.local`（git 忽略）+ Vercel 项目环境变量；**前端代码里一个都不许有**。
- 现场反例：把 key 写进前端 → 打开浏览器 DevTools 就能看到 → 立刻改回服务端。

### 数据隔离实验（本节"红灯实验"）
1. 用账号 A 登录，保存一条记录。
2. 换账号 B 登录，尝试读 A 的记录 —— **读不到**（服务端按 userId 过滤）。
3. 故意去掉服务端的所有权校验，重试 —— B 能看到 A 的了（漏了）。
4. 把校验加回来 —— 又隔离了。
> 过关标准不是"能存能读"，是**你亲眼看见"别人拿不到你的数据"这件事真的成立**。

### 占位填真
`authAdapter` / `readingStore` 的函数签名不动，实现从"返回假数据"换成"fetch `/api/...`"。前端页面**一行不用改** —— 这就是 L1 讲的 SoT / 接口边界的兑现。

## 9. 安全自查清单

```markdown
## Security Check
- [ ] 前端代码 / 打包产物里没有任何密钥（搜一遍）
- [ ] 密钥只在 Vercel 环境变量 + 本地 .env.local（git 忽略）
- [ ] 所有"写"和"读私有数据"的 Function 都在服务端校验登录态
- [ ] 每条数据按 userId（或等价所有权）过滤，别人拿不到
- [ ] 前端传来的 userId / 身份一律不信，以服务端会话为准
- [ ] 换账号验证过数据隔离
- [ ] 出错信息不泄露内部细节 / 他人数据
```

## 12. 高频风险与课堂降级

| 风险 | 处理 |
|---|---|
| Auth / DB 配置卡住 | 切老师预置项目继续；个人配置课后补 |
| 环境变量没生效 | 检查是否重新部署 / 变量作用域（Preview vs Production）|
| `vercel dev` 本地跑不起来 | 直接用 Vercel 部署预览调试，本地放后 |
| 时间不够 | 保住"登录 + 存一条 + 读回自己的"；数据隔离实验老师演示、学员课后 |
| 学员纠结选型 | 统一用老师指定的一套（见 §15），课上不比较 |
| 想把整个后端做全 | 拉回：本节只做一条动态 Flow，其余下不为例 |

## 13. 作业

1. 给你自己的产品（或 star-mansions）接上**真登录**。
2. 让它能**保存一样真实的东西**（如测算记录），并只让本人看到。
3. 换一个设备 / 账号，验证"记得住"和"看不到别人的"。
4. 过一遍 §9 安全清单。
5. 提交：线上链接 + 登录演示 + 一段"数据隔离"验证（截图或录屏）。

## 15. 待确认项

进入 deck 开发前需要最终决定：

1. Auth + DB 选型统一为哪套：**Supabase（Auth + Postgres 一站）** 还是 **Auth.js + Vercel Postgres**？（建议 Supabase，最少心智负担）
2. 课堂是否统一用 **star-mansions** 当活案例（老师演示），学员用各自 L4 项目跟做？
3. 课程时长固定 120 min 还是可延长（同 L4，倾向可延长）。
4. "数据隔离 / 所有权"讲到什么深度：只讲服务端按 userId 过滤，还是也点一下数据库行级安全（RLS）？
5. `vercel dev` 本地开发是否作为主线，还是直接用 Vercel 云端 Preview 调试？
6. 是否需要老师提供统一兜底 starter + 预置 Auth/DB 参考项目。
