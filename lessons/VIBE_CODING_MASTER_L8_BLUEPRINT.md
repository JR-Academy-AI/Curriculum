> 状态：DRAFT 0.2（2026-08-06 · 做一步讲一步 · 手动 Team 主线版）
> 主题：**Agent Team —— 从分派到协作**
> 课型：**120 分钟「做一步讲一步」工作坊**（12 拍，做 / 讲交替；**主教具是手动 Team**，自动 Team 只在第 9 拍投屏对照）

> **L7 已于本轮开课完成**，所以本节的第 0 拍直接从学员手上那张 L7 汇总矩阵开始——不用讲故事，用他们自己交的东西。

## 0. 本节的来历

### 0.1 拆课（L7 v0.4 → 本节 v0.1）

本节内容原本是 L7「双结构版」（v0.3/v0.4）的后半段。做 deck 时发现三个结构性问题，遂拆课：

1. **两侧无法对称**——Team 侧天然多一层（charter、成员通信、对抗设计、外部验收），塞在同一节里会让学员误以为 Team 更重要，**而核心判断恰恰相反**。
2. **120 分钟装不下两次实验 + 两套开课门槛**——Agent Team 额外需要实验开关、显示模式、权限预批三项预检。
3. **判断线被迫前置**——双结构版必须在实验前讲完决策树，违反系列一贯的「先撞墙，再给尺子」。

拆开后，L7 专注 Subagent 并恢复动手红灯；本节专注协作，并且**有足够时间处理 Agent Team 那些真实的开课门槛**（§12）。

原 L7 deck 中属于本节的页已归档在 `lessons/vibe-coding-master-l7/src/components/slides/_archive/`，可直接迁移（见 §11 复用列）。

### 0.2 改成「做一步讲一步」（v0.1 → v0.2）

v0.1 的流程是 **0–64 分钟全讲、69 分钟才动手**——立论页和 charter 都排在唯一一次实验之前。这重复了 L7 v0.3 那个已经被否掉的错误：**尺子先于撞墙。** 而且 v0.1 里唯一的「撞墙」只是 §9.1 幻灯片上的一个故事，学员没有亲历。

v0.2 改三件事：

| # | 改动 | 为什么 |
|---|---|---|
| 1 | **课型从「讲授 + 一次大实验」改成 12 拍做/讲交替**，第 6 分钟就动手，立论页挪到第 30 分钟（学员刚看完结论翻转的那一刻） | 每个概念前面必须有一次学员亲手做出来的现象。这是 L4–L7 一贯的「先撞墙，再给尺子」在**每一拍内部**都成立的版本 |

| 3 | **实验题从「三个竞争假设」升级成两道预埋题**（浅题：交界 bug；深题：共因假象） | v0.1 §9.6 只说「课堂脚本必须制造一次通信有价值的时刻」，没说怎么保证。靠脚本提示保不住，一定退化成分工。改成**仓库里的结构性事实**。详见 §6.11 |

连带效果：**本节不再有开课门槛。** v0.1 的三条 🔴（协作开关、显示模式、权限预批）全部只影响第 9 拍那 8 分钟的演示形态，不影响前 8 拍能不能上。§15 的人肉信使也从「国内主路径」升格为**全班主路径**。

## 1. 课程定位

第七节结束时，学员会做一件事：**把一个任务拆成几路，派出去，收回来自己汇总。**

但那个结构有一个硬边界，L7 只埋了一句没有展开：

> **子 Agent 之间没有连线。** A 发现的东西，B 永远不知道——除非经过你。

大部分时候这不是问题。但有两类任务，这个限制会直接毁掉结论质量：

```text
【第一类 · 没有答案】
三路各查一块 → 三份报告都说「我这边没问题」
                        ↓
        而且三份都是对的 —— 在各自的证据范围内，每一条都正确
                        ↓
        「没问题」+「没问题」+「没问题」= 「都没问题」≠ 真相
                        ↓
        bug 在两个正确决定的交界处。不是漏了，是这个结构算不出来。

【第二类 · 错误答案】
三路各查一块 → 都看到同一条吻合的线索 → 三个人一致同意
                        ↓
        没有人有动机去推翻它，因为推翻别人不是任何人的任务
                        ↓
        你拿到一个自洽的、说得通的、错的结论 —— 而且很自信
```

第一类叫**交界 bug**，第二类叫**虚假共识**。前者是结构问题，后者是概率问题——本节各用一道题演一遍（§6.11）。

第八节换结构：**让它们边做边互通。**

```text
L7：Hub-and-spoke
    你 ↔ 主 Agent ├→ A ─┐
                  ├→ B ─┼→ 只回结论 → 你汇总
                  └→ C ─┘
    成员之间没有连线。分工 = 覆盖。
                  ↓
L8：Team
    Team Lead ↔ A ↔ B ↔ C  +  共享任务板 / 信箱
    成员互相挑战、交换证据、协调依赖。对抗 = 收敛。
                  ↓
    但天下依然没有白拿的：
    通信成本、任务状态、冲突处理、更高总消耗
    所以核心不是「更高级的结构」，是「这件事需不需要它们说话」
```

一句话定位：

> 第七节教你**把活分出去**；第八节教你**判断什么时候分出去的人必须互相说话**——以及说完之后，谁负责收敛。

系列主线走第四步：

```text
L1–L5：往 context 里放对的东西
L6：  看懂 context 怎么被消耗、怎么坏
L7：  给 context 分家
L8：  让分出去的 context 互相通信
```

## 2. 两种结构对照

学员已经用透了左边这一列，所以这张表现在才讲得动——**对比需要基础**。

| | Subagent（L7） | Agent Team（本节） |
|---|---|---|
| 形状 | **Hub-and-spoke（主从式）** | **Team（团队式）** |
| 谁分派 | 主 Agent | Team Lead；成员也可能领取任务 |
| 成员通信 | 通常只把结果回给主 Agent | 成员可持续共享发现、互相质疑、协调依赖 |
| 协调发生在哪 | 主 Agent 集中拆分与汇总 | Lead + 任务系统 + 成员通信共同协调 |
| 生命周期 | 聚焦、一次性、完成即返回 | 更持续，任务会更新、阻塞、移交或重分配 |
| 写入隔离 | **可以**给每个成员一份独立工作副本 | **不提供**，成员共用工作副本，只能靠划文件所有权 |
| 嵌套 | 允许（有层数上限） | 不允许，成员不能再开成员 |
| 异构 | **可以**（L7 §18.7 的两条路） | **不行**，成员资格靠共享任务板和信箱 |
| 最适合 | 大量独立搜索、日志分析、明确验证、互不依赖的调查 | 竞争假设、跨模块协作、接口协商、需要成员互相挑战的复杂任务 |
| 主要成本 | 冷启动、brief、回报与汇总 | Subagent 的**全部成本** + 消息、任务状态、冲突处理和更高总消耗 |

一句话判断线：

> **只需要「分头做、回来报」用 Subagent；需要「边做边互通、共同收敛」才用 Agent Team。**

Agent Team 不是更高级、更强的 Subagent。任务不需要成员通信时，上 Team 只会多一层协调成本。

## 3. 学员起点

### 3.0 课堂仓库：`star-mansions`（已锁定）

> **https://github.com/Ruixiaoke/star-mansions** —— **与 L7 同一个仓库**，学员已经熟了，省掉重新摸项目的时间。这是本节最大的一块时间红利。

课堂用得到的结构（老师必须先自己读一遍这几个文件）：

```text
frontend/  React 19 + Vite + TS，部署到 GitHub Pages
  src/lib/authAdapter.ts      登录 / 软会话，localStorage 存 {user, token}
  src/lib/api.ts              apiPost
  src/components/AuthForm.tsx · src/pages/Login.tsx

backend/   Vercel serverless + 本地 Express，部署到 Vercel
  src/handlers/auth.ts        emailToId() / upsert / token = user.id
  src/handlers/history.ts     按 auth 作用域；含内存回落 memStore
  src/cors.ts                 ALLOWED_ORIGIN 允许来源列表
  .env.example · vercel.json · db/schema.sql
  test/xiu.spec.ts            Vitest

.claude/agents/               仓库里已有 4 个现成角色文件，第 1 拍的对照物
```

三条对本节最重要的**结构性事实**（老师课前必须能背出来，它们是两道题的地基）：

1. **前后端跨域**——前端在 GitHub Pages，后端在 Vercel。这不是配置细节，是**天然的调查边界**：一个人看不到另一边。
2. **`token` 就是 `user.id`，而 `user.id` 由邮箱派生**（`u_` + `encodeURIComponent(email)`）。身份链条极短，任何影响邮箱字符串的东西都会一路影响到历史记录的作用域。
3. **`history` 有一条内存回落分支**（`memStore`），代码注释里自己写着「Vercel serverless 不跨请求持久化，仅本地/单测用」。这行注释是深题的钥匙，但它躺在后端调查员的地盘里。

> ⚠️ **小仓库的边界从哪来。** star-mansions 只有几十个文件，一个 agent 全读得完——聪明的学员一定会问「那我为什么不一个人全看」。这个问题必须正面回答，而且答案要在第 2 拍讲：
>
> **在这个仓库里，边界是你在 brief 里划出来的；在你自己的真实项目里，边界是 context 逼出来的。** 今天用小仓库，是为了让你在 12 分钟内看清结构盲区长什么样——盲区的成因是**边界**，不是**仓库大小**。边界存在，盲区就存在，一个 200 文件的项目和一个 20 万文件的项目一模一样。
>
> 顺带回收 L7：你上节课划边界是为了省 context；这节课你会发现，**同一条边界同时也是一道信息墙**。

### 3.1 学员上课前应有

- **L7 的完整体感**：会写六格 brief、跑过三路并行调查、做过一次汇总矩阵、**亲手测过一次过度分派的代价**。没有最后这一条，学员会把 Team 当成「更强的 Subagent」，这是本节最需要防的偏差。
- **带着 L7 交的那张汇总矩阵来**（纸质或截图）。**这是第 0 拍的教具，没有它开不了场**——课前一天在群里通知。
- L7 的三条铁律（不假设继承 / 不重叠所有权 / 不拿自述验收）。
- L6 的诊断体感。
- 本机装好一种支持委派的编码 Agent，**能创建角色文件即可**——本节主教具是手动 Team，**不要求工具支持 Agent Team**。
- 已 clone `star-mansions` 并停在指定 commit。

### 3.2 课前能力预检（老师完成，学员不现场折腾配置）

> **v0.2 关键变化：前三行不再是开课门槛。** 手动 Team 成为主教具之后，工具支不支持 Agent Team 只影响**第 9 拍那 8 分钟的演示形态**——支持就现场跑，不支持就放预录。前 8 拍照常上。
>
> 这张卡因此从「跑不跑得起来」降级成「第 9 拍怎么演」，但**仍然要填**，因为「先做 capability check」本身是本节要传的职业习惯（与 L7 §3.1 同一条）。

| 能力 | 当天实测结果 | 影响哪一拍 |
|---|---|---|
| 协作结构是否要显式开启 | 开箱可用 / 要开开关 / 不支持 | 拍 9：现场跑 or 放预录 |
| 怎么确认结构真的成型了 | 实测动作：______ | 拍 9：防 Subagent 冒充 Team |
| 成员消息看不看得见 | 单终端 / 分屏 / 看不见 | 拍 9：投屏长什么样 |
| **角色文件放哪一级生效** | 项目级 `.claude/agents/` / 用户级 / 都行 | **拍 1：全班要落在同一个位置** |
| **同一份角色文件当队友跑时有哪些字段失效** | 实测：______ | **拍 9 的对照点**（见 §18.4） |
| 成员是否继承 Lead 的对话历史 | 无 / 摘要 / 其他 | 拍 9 的 spawn prompt |
| 成员默认用哪一档模型 | 跟随 Lead / 不跟随 / 其他 | 见 §6.8 |
| 多个成员使用同一还是隔离工作副本 | 同目录 / 隔离 | 本节全程只读，仅口播 |
| 权限弹窗出现在哪 | Lead / 各自 / 无 | 拍 9 要不要课前预批 |
| 是否允许嵌套 | 是 / 否 | demo 的最大深度 |

加粗那两行是 v0.2 新增的，因为课从「搭一个 agent」开始，**角色文件放哪、当队友跑时会不会变**这两件事在第 1 拍和第 9 拍各要用一次。具体到当天工具怎么查，见 **§18**。

## 4. 学习目标

课程结束后，学员能够：

1. **从零搭出一个 agent 角色文件并跑通它**，说清每一个字段在治什么——尤其 `tools` 是唯一能把「范围」从请求变成保证的那一格（回收 L7）。
2. **把同一份角色文件在两种结构里各跑一次**，指出它当 subagent 和当 teammate 时能力边界的差别。
3. 画出 Subagent 与 Agent Team 两张结构图，并从**通信路径、协调位置、生命周期、成本**四个维度解释差别。
4. 说清 **Hub-and-spoke 的结构盲区**：当每一路的局部结论都正确时，三个正确结论加起来仍然是「都没问题」——**这类 bug 不是派得不够多，是结构上发现不了**。
5. 区分对抗辩论治的两种病：**锚定**（概率问题，派得够多有可能碰上）和**交界 bug**（结构问题，不通信就永远发现不了）。
6. 用**第二问**判断一件事该用 Subagent 还是 Agent Team：*这些 context 之间需不需要持续通信和共同协调？*
7. 说清 **Team 的门槛必须比 Subagent 高**：只有当**成员通信会改变任务分工或结论质量**时它才值得。
8. 区分**对抗**与**分工**——并说清为什么按模块分工的「团队」其实是 Subagent，只是更贵。
9. **手动当一次消息总线**，并写出人肉传递的标准句式（原文转贴 + 一个具体问题，不做二次总结）。
10. 为 Agent Team 写一份 **Team charter**：共同目标、成员角色、任务依赖、通信规则、写入边界、收敛条件。
11. 认出并记录三类关键消息：**DISCOVERY / CONFLICT / DECISION**，并说清为什么只留这三类。
12. 认出**虚假共识**：三个成员一致同意一个时间上完全吻合的解释，而它是**共因不是因果**；并说清拆穿它只有一条路——**有人专职去找反例**。
13. 说清 **Team Lead 的收敛责任**：成员「已经达成一致」不是外部判据；任务板完成 ≠ 外部验收完成。
14. 认出**过度组队**：一个不需要成员通信的任务被组成团队，结果只是多付一层协调成本。
15. 说清 **异构只能进 Subagent，进不了 Agent Team**，以及为什么（回收 L7 §18.7）。

### 4.1 过关证据

不是「成功开出了一支队伍」，而是学员离场前能提交：

- **三个自己写的角色文件**（investigator-frontend / -backend / -config），带 `tools` 字段。
- 一份**浅题的翻转记录**：三份「我这边没问题」的原文 + 那一次人肉传递贴了哪句话 + 对方翻转后说了什么。
- 一份 **Team charter**（课堂只填第 2、4 两项；六项全填放作业）。
- 一份深题的**协作包**：任务板快照 + 至少各一条 DISCOVERY / CONFLICT / DECISION 消息 + Lead 最终结论。
- **一条反例**：能打断「部署 → 记录丢失」那条因果链的具体证据。
- 一张**结构选择卡**：这个任务该用哪种结构 + 一句理由。
- 一句话说明：**如果禁止成员互相通信，这个任务会在哪一步变慢或变差。** 答不出来 = 它本来就不该用 Team。

## 5. 非目标

本节明确不做：

- **不重讲 Subagent 的判断线**（该不该派、两层门、汇总矩阵）——那是 L7 的内容，本节只回收不展开。
  - ⚠️ **例外：角色文件怎么写要重做一遍**（第 1 拍）。L7 教过，但本节的三个队友就是那三份文件，**必须是学员自己现搭的**，不能领现成的——否则第 9 拍「同一份文件在两种结构里跑」这个对照就没有主语。
- 不教 SDK / API，也不搭多 Agent 编排框架。
- 不教具体工具的配置项、模型参数或并发上限。**唯二例外**：① 角色文件放哪一级生效（第 1 拍，全班要落在同一位置）；② 协作结构的开关（第 9 拍演示前提）。参数细节留 §18。
- 不把「同时启动很多 Agent」当学习成果；课堂并行上限固定为 **3 个成员**（Lead 不计入）。
- **不在课堂上改 `star-mansions` 的任何文件**。两道题全程只读，唯一允许写的是学员自己新建的 `.claude/agents/*.md` 和任务板 md。写冲突由老师演示。
- **不修那两个 bug。** 本节的产物是「找到并证明」，不是「修好」。修留作业——课上一动手改代码，剩下的拍数全废。
- 只讲**最小协作闭环**：共同目标、任务板、成员消息、收敛与验收；不展开消息协议、失败恢复和跨机器协作。
- 不声称所有工具都提供成员通信或共享任务板——**大多数不提供**，见 §15。**本节主教具不依赖它。**
- **不在课堂上教「让 Agent 当 Agent 架构师」生成专家 Agent**（五阶段访谈法）。它只占拍 11 的 3 分钟预告，完整方法在 `HANDOUT.md` §12，作业里选做。
  - 理由见 §20：**你不会审规格，就不该让 AI 替你写规格。** 拍 1 必须是手写——学员先亲手写过 `tools`、出口、产出合同，才看得懂 AI 生成的规格里哪一格是空的、哪一格是它替你编的。而且拍 9 那句「一个字没改」需要「这是**你**写的」这个主语。

## 6. 核心教学决策

### 6.1 全节只回答第二问

L7 回答了第一问（值得开多个 context 吗）。本节回答第二问：

> **这些 context 之间需要持续通信吗？**

```text
只需把结果交回一个中心 → Subagent（L7 已经会了）
需要互相交换发现、处理依赖、挑战结论 → Agent Team（本节）
```

任何内容如果不能帮助学员完成这次判断、运行一个 Team 或验收结果，就移出主课。

### 6.2 不是能力等级，是通信拓扑

错误心智：

```text
单 Agent < Subagent < Agent Team
Agent 越多、结构越复杂就越强
```

正确心智：

```text
任务的通信需求
   ├─ 无额外 context 收益 → 单 Agent
   ├─ 独立分工，集中汇总 → Subagent
   └─ 持续互通，共同收敛 → Agent Team
```

**选择 Agent Team 的门槛必须比 Subagent 高。** 这一条要反复说，因为本节最容易造成的伤害是「学完什么都组队」——就像 L7 最容易造成「学完什么都派」。

### 6.3 立论：通信治的是两种病，一种是概率问题，一种是结构问题

这是本节的立论段（第 3 拍讲，**在学员亲眼看完结论翻转之后**）。v0.1 只有下面的「病 B（锚定）」，v0.2 把「病 A（交界 bug）」提到前面——因为它更硬，而且它是课堂能百分之百演出来的那一个。

#### 病 A · 交界处的 bug（**结构问题**）

```text
A 查前端：登录只做了 trim，不擅自改用户输入 —— 正确。
B 查后端：拿邮箱派生 id 做 upsert，作用域严密 —— 正确。

各自的结论都是「我这边没问题」，而且在各自的证据范围内，
这两个结论都是对的。

没有人写错代码。bug 出在两个正确决定的交界处。
```

**这不是质量问题，是结构问题。**

```text
Hub-and-spoke 的算术：
  「A 那边没问题」+「B 那边没问题」+「C 那边没问题」
   = 「都没问题」
   ≠  真相

不管你派多少路、每一路 brief 写得多好、模型用多强的档，
只要成员之间没有连线，这个和永远算不出真相。
```

一句话立论（全课最重要的一句）：

> **交界处的 bug，互不通信的调查者在结构上不可能发现。不是漏了，是算不出来。**

它和 L7 是同一条逻辑的下一步：L7 说「边界能省 context」，L8 说「**同一条边界同时是一道信息墙**」。边界带来的收益和盲区是同一件事的两面。

#### 病 B · 锚定（**概率问题**）

```text
单个 Agent 查根因：
  试假设 1 → 说得通 → 停
  假设 2、3 从此再没被认真查过

三个 Agent 互相证伪：
  假设 1 ↔ 假设 2 ↔ 假设 3
  各自被另外两个攻击 → 活下来的那个
```

顺序调查有个固有毛病：**第一个说得通的解释会污染后面所有判断**。辩论不是为了热闹，是为了**不让第一个答案自动胜出**。

#### 两种病的分工：一道题治一种

| | 病 A · 交界 bug | 病 B · 锚定 / 虚假共识 |
|---|---|---|
| 性质 | **结构问题**——不通信就发现不了 | **概率问题**——不通信会一起错 |
| 通信的作用 | **交换证据** | **对抗证伪** |
| 光靠「多派几路」能不能解决 | **不能**，派再多也是同一个和 | 有可能碰上，但不可靠 |
| 课堂用哪道题 | **浅题**（拍 2–4） | **深题**（拍 6–7） |
| 需要什么角色 | 任意两个能互相发消息的成员 | **一个专职找反例的成员** |

讲这一段的顺序不能换：**先 A 后 B**。A 是"不通信就没有答案"，B 是"不通信会有一个错答案"——B 更阴险，但学员必须先接受 A 才听得进 B。

> 教学纪律：**病 A 必须由学员亲手演出来（拍 3 的翻转），不能只讲。** 讲出来的 A 是道理，演出来的 A 是事实。这一拍演砸了，整节课的立论就落不了地——彩排必测项见 §12.2。

### 6.4 对抗 ≠ 分工（本节最容易做错的一步）

| | 分工 ❌ | 对抗 ✅ |
|---|---|---|
| 怎么派 | A 查前端 · B 查后端 · C 查配置 | A、B 各认领一个假设 · C 专职找反例 |
| 拿回来 | 三份互不冲突的报告 | 一个被证伪不掉的结论 |
| 拿到的是 | 覆盖 | **收敛** |
| 实质 | 没人有动机推翻别人——**这是 Subagent，只是更贵** | 每个人都有动机推翻别人，活下来的才算数 |

**必须有人负责唱反调。** 如果三个成员都在「证明自己的假设」，没人在「推翻」，辩论就退化成三份并行报告。这就是实验里 C 角色（Evidence challenger）存在的全部理由。

### 6.5 什么时候辩论才值

> 当这件事**没有廉价判据**的时候。

跑个测试就能证伪的假设，直接跑测试——别开三个 Agent 辩论。辩论换的是「**拿不到确定判据时，怎么让结论更可信**」。

这条是 §6.2 门槛的操作化版本，也是红灯判断的依据。

### 6.6 冲突靠证据裁决，不靠投票

对抗辩论最容易滑坡的地方：三个 Agent 很容易「达成一致」——**而一致不等于对**。

所以 charter 的通信规则必须写死：与其他结论冲突时，**附双方证据，不靠投票解决**。Lead 按证据裁决。

### 6.7 收敛：任务板完成 ≠ 外部验收完成

成员可以在团队内交换证据、暴露矛盾、调整任务，但 **Team Lead 仍要做最终收敛与验收**。

> **成员「已经达成一致」不是外部判据。**

全绿之后 Lead 还要问：

1. 根因结论追溯得到文件 / 行号 / 命令输出吗？
2. 另外两个假设的**排除**有反证，还是只是「没查到」？
3. 验收判据是不是全部真的执行过？
4. 成员没检查的范围，标出来了吗？

一句话收口（与 L7 同一句，本节加重）：

> **多 Agent 改变的是信息怎样流动，不会转移最终验收责任。**

### 6.8 成员选档：跟 L7 同一条判断线，但多一个陷阱

判断线不变——**跟判断密度走，不跟重要性走**：

| 角色 | 密度 | 选档 |
|---|---|---|
| **Team Lead** | 判断密集（读矛盾证据然后拍板） | 最强档。这里省钱最亏 |
| **Evidence challenger** | 判断密集（找反例是纯判断） | 最强档 |
| Client / API investigator | 执行密集 | 中间档够用 |

新增的陷阱（L7 没有）：

> **成员默认不跟随 Lead 的模型选择**，而且**开人时就定死，事后改不了**。
>
> 这跟 subagent 正好相反（subagent 默认 `inherit`）。又一次「不假设继承」，而且方向反直觉。

### 6.9 异构：回收 L7 的那句埋点

L7 §18.7 埋了一句：异构只能进 Subagent。这里回收并讲透：

**成员资格靠共享任务板 + 信箱**，那是工具内部的东西。外部进程收不到消息、不出现在任务板、Lead 看不见它的进度——它永远只能是 Hub-and-spoke 的一根 spoke，**做不了队友**。

推论：想混用别家的 Agent，只能停在 L7 那种结构。这不是产品缺陷，是**结构决定的**。

### 6.10 主教具是「手动 Team」，不是自动 Agent Team

**理由一：自动 Team 在结构上不支持「做一步讲一步」。**

自动 Team 一旦开起来就是黑盒——成员自己发消息、自己认领任务、自己判断该不该继续。你想在第 3 条消息处暂停讲两句，做不到；你喊停它跑完当前动作才停。**一节 12 拍的课，不能把最长的一拍交给一个停不住的东西。**

**理由二：Team 的价值全在消息里，而消息自动飞过去就看不见了。**

这是 §9 讲评那句话的直接推论。消息由学员**手动粘贴**过去，他看到的不是「结果不一样了」，而是「**这一句话改变了什么**」。这个因果关系是本节唯一要教的东西。

**理由三：全班同步，没有开课门槛。**

不要求任何工具支持 Agent Team。国内学员从「走降级方案」变成「和所有人做同一件事」。

**手动 Team 的最小装备**（第 6 拍用）：

```text
三个会话（三个终端 tab / 三个窗口，各自跑一个角色文件）
+ 一个 md 文件当共享任务板（学员自己维护状态）
+ 你自己当消息总线（手动把 A 的原文贴进 B）
```

**自动 Team 的位置**：第 9 拍，8 分钟，老师投屏跑同一道深题做对照。结论定死在两句话上——

> 它替你做了：**传递、认领、状态同步**。
> 它**没有**替你做：**裁决和外部验收**——那两件事在 L7 是你的活，在 L8 还是你的活。

⚠️ 不要把顺序倒过来先演自动版。先看自动版的学员，会把整节课理解成「学一个功能怎么用」；先手动跑过的学员，看自动版时问的是「它裁决那一步是怎么定的」——那才是对的问题。

### 6.11 两道预埋题：一道真实存在，一道只要一页纸

v0.1 §9.6 只写了「课堂脚本必须制造至少一次通信有价值的时刻」，没说怎么保证。**靠脚本提示保不住**——只要三个成员各自跑得顺，谁也不会主动去找别人说话，实验必然退化成分工（§9.4 的头号失败模式）。

v0.2 的做法：把对抗时刻做成**题目本身的结构性事实**，而不是课堂上的一句嘱咐。两道题，教两件不同的事。

| | 浅题 | 深题 |
|---|---|---|
| 用在 | 拍 2–4（约 20 分钟） | 拍 6–8（约 30 分钟） |
| 治哪种病 | A · 交界 bug | B · 虚假共识 |
| 不通信的结果 | **没有答案**（三个「没问题」） | **一个错答案**（而且很自信） |
| 解开需要 | 一次传递 | 一个专职找反例的人 |
| 制作成本 | **零**——它真实存在于仓库里 | **一页现象报告**，不改任何代码 |

#### 浅题：邮箱大小写 → 历史记录消失（**仓库里本来就有**）

```text
症状：用同一个邮箱登录，之前保存的星宿记录有时候看不到了。

A（前端边界）：authAdapter.login 只做 trim()，不改用户输入的大小写。
                前端不擅自 normalize 用户输入 —— 这是对的。
B（后端边界）：emailToId() 用邮箱原文派生 user.id，upsert onConflict: "id"，
                history 严格按 user_id 作用域 —— 这也是对的。

交界：Rick@x.com 和 rick@x.com 派生出两个不同的 id
      → 两个账号 → 历史记录「消失」。
```

**这个 bug 不需要埋，它就在 `main` 分支上。** 三条好处：

1. 学员会信——不是老师造的题，是他们上节课刚读过的代码。
2. 老师零制作成本，只要准备**触发路径**（用两种大小写各登一次、各存一条记录）。
3. 它同时是一次真实的代码审查产出——学员的作业可以是给这个 repo 提 issue / PR。

⚠️ 老师课前必须实测确认这个行为在当天的部署上仍然成立（§12.2）。若上游已修，**降级方案**：让学员停在修复前的那个 commit，或改用同族交界（`logout` 只清 localStorage、后端无失效概念）。

#### 深题：记录在线上丢失（**共因假象**，只要一页现象报告）

```text
症状：线上保存记录后，过一阵子历史是空的；有时又能看到。

三路各自会得出：
  A 前端：save 调用正确、返回 200、state 更新正确 —— 前端没问题。
  B 后端：handleHistorySave / handleHistoryList 逻辑正确 —— 后端没问题。
  C 配置：.env.example 齐全、vercel.json 正确 —— 配置没问题。

然后三个人会看到同一条线索：每次「记录消失」之前，都有一次部署或冷启动，
时间戳完全吻合 → 三人一致得出「部署导致数据丢失」。

这个结论错了，而且是自洽的、部分正确的、按它去修会全错方向的
（去研究部署流程、加持久化、改 Vercel 配置）。

真因：生产环境的 Supabase env 根本没生效，所以走了 handlers/history.ts 里
      那条「仅本地/单测用」的 memStore 内存回落。部署只是触发器，不是原因。
```

**为什么它必须靠对抗才能拆穿**：B 确实读到了 `memStore` 那行注释，但 B 的推理是「这是本地回落，线上有 env 所以不走这条路」——**在 B 自己的证据范围内，这个推理完全正确**。要证伪它，只有一条路：

> **找反例：有没有「没部署但也丢了」的时候？**
> 有——同一分钟内两次请求打到不同的 serverless 实例，一次看得见一次看不见。
> 这条反例直接打断「部署 → 丢失」的因果链，指向「进程内存 = 每个实例各一份」，进而指向 env 没生效。

这就是为什么 charter 第 2 项必须写死一个**专职唱反调的成员**——三个人互传证据是不够的，他们会**一起**相信那个吻合的时间戳。

**要准备的唯一素材**：一页「线上现象报告」（时间线 + 埋在里面的那条反例）。**不改仓库任何代码。** 规格见 §12.3。

### 6.12 为什么从「搭一个 agent」开始

第 1 拍花 12 分钟让学员从零写一个角色文件，看起来是在重讲 L7。它换来三样东西：

1. **今天的三个队友，就是学员现在亲手搭的三份文件。** 从「一个 agent」→「三个 agent」→「三个不说话的 agent」→「你当总线」→「一支队伍」，全课只有一条脊椎，每一步都是上一步的改写。
2. **第 9 拍的对照才有主语。** 同一份文件当 subagent 跑和当 teammate 跑，能力边界不一样（§18.4：`skills` / `mcpServers` 失效，团队协作工具始终可用）。这个对照的说服力全靠「这是**你写的**那份文件」。
3. **`tools` 字段是本节的隐藏主线。** L7 讲过「范围不靠正文嘱咐、靠 `tools` 物理限制」；本节把它推到下一层——**你用 `tools` 划出来的那道墙，既挡住了噪音，也挡住了证据**。学员在第 1 拍亲手砌这道墙，在第 3 拍亲眼看它挡住什么。

> 不要发现成的角色文件。仓库 `.claude/agents/` 里那 4 个只当**对照物**：写完自己的再打开看一眼，比一比谁的 `tools` 划得更死。

## 7. 课堂最终产物

每位完成者应有：

- **三个自己写的角色文件**（`.claude/agents/sm-investigator-{frontend,backend,config}.md`），带 `tools` 字段。
- 一份**浅题翻转记录**：三份「我这边没问题」原文 + 那次人肉传递贴了哪一句 + 对方翻转后的第一句话。
- 一份**关键消息记录**：DISCOVERY / CONFLICT / DECISION 各至少一条，从自己的动作里抄下来的。
- 一份 **Team charter**（课堂填第 2、4 项；六项全填放作业）。
- 一份深题**协作包**：任务板 md 快照 + Lead 最终结论 + **一条打断「部署 → 丢失」因果链的反例**。
- 一张**结构选择卡**：单 Agent / Subagent / Agent Team + 理由。
- 一张**能力预检卡**（老师当天实测版）。
- 一句话：如果禁止成员互相通信，这个任务会在哪一步变慢或变差。

## 8. 120 分钟流程：12 拍，做 / 讲交替

> **每一拍的规矩：「做」出一个现象 →「讲」解释这个现象。** 不是讲完知识点再练习。每一拍的「讲」必须解释的是**学员刚刚亲手做出来的那个东西**，不是一般道理。

| 拍 | 分 | 🔨 做 | 🎙 讲 | 产物 / checkpoint |
|---|---|---|---|---|
| **0** | 3+3 | 摊开你 L7 交的汇总矩阵，看**「冲突 / 缺口」那一列** | 那一列为什么大多是空的：**没有人去挑战别人** | 举手：那列填了实质内容的有几个 |
| **1** | 8+4 | **搭第一个 agent**：从零写 `sm-investigator-frontend.md`，跑一次浅题的前端一路 | 四格逐格收口；打开仓库自带的 4 个角色文件比 `tools` 谁划得更死 | 群里贴自己的 `tools` 那一行 |
| **2** | 10+**2** | 复制成三份（frontend / backend / config），**三路并跑浅题** | 三份「我这边没问题」——而且**三份都是对的**。只讲这一件事，**2 分钟，短** | 群里贴三条结论句 |
| **3** | 3+**8** | 🔥 老师点名一句：把 A 报告里那半句**原样**贴进 B 的会话 → **B 当场翻转** | 🔥 **立论：交界处的 bug** → **回收那道墙**（你一小时前亲手写的那一行）→ **边界从哪来**。全课最重要的 11 分钟 | 群里贴 B 翻转后的第一句话 |
| **4** | 4+4 | 反向再传一次，锁定根因；把刚才发生的三件事写下来 | **DISCOVERY / CONFLICT / DECISION** + 传证据不传结论 + 三个失败模式 | 三条消息记录 |
| **5** | 3+5 | （先讲后做）写 charter 的**第 2 项 + 第 4 项**，只写这两项 | 刚才那两次传递是**我喊的**。没人喊的时候，谁传给谁？ | charter 两项 |
| — | 5 | ☕ 休息 | | |
| **6** | 2+15+**2** | **手动 Team 跑深题**：三会话 + 一个 md 任务板 + 你当总线。老师**每 7 分钟一次节拍** | 讲评只做**过程诊断**，**口播不占页**：有没有 CONFLICT、传递记录长什么样 | 任务板快照（中期也要交） |

### 8.1 节奏铁律

1. **每一拍硬停。** 老师喊停不管跑没跑完，话术照搬 L7 RUNSHEET §5「到点统一停」。
2. **每一拍有兜底产物。** 掉队的人直接领老师的成品进下一拍。**必备兜底**：拍 1 的角色文件成品、拍 2 的三份报告、拍 6 的任务板中期快照。一处卡住不许拖垮整节课。
3. **每一拍一个 checkpoint**（见表末列）。老师靠它一眼看出谁掉队，而不是等到讲评。
4. **拍 1、2、3、6 不可砍。** 时间不足时依次砍：拍 9（自动演示 → 改口播两句结论）→ 拍 10 → 拍 8 的「做」→ 拍 5 压到 3 分钟。
5. **立论（拍 3）必须在翻转之后。** 这是 L7 v1.0 已经付过学费的一条：**先撞墙，再给尺子**。v0.1 把立论和 charter 全排在唯一一次实验之前，等于把这条又违反了一遍。
6. 🆕 **「`tools` 是一道墙」不能放拍 1。** 它一说破「边界也挡证据」，就等于在学员撞墙前 40 分钟剧透立论 —— **还是第 5 条那个错误，只是更隐蔽**。现在它在立论**之后**，性质从预告变成回收：那道墙不是抽象概念，是他们一小时前亲手写下的那一行。
7. 🆕 **「小仓库的边界从哪来」不能夹在拍 2 和拍 3 中间。** 拍 2 讲评的收尾是「记住这个感觉」，情绪必须**直接推到拍 3 的口令**；中间插一页方法论会把气泄掉。它现在是拍 3 的收束。
8. 🆕 **「价值发生在消息里」不能放拍 6。** 深题硬停时全班手里是**错答案**，而那个错答案恰恰是互相通信之后达成的 —— 此刻问「通信有什么价值」，诚实的回答是「好像没帮上忙」，这一问就废了。放到拍 7 揭穿之后，答案才有两层：**浅题里不通信＝没有答案；深题里通信了＝更快地一致地错。所以通信是必要条件，不是充分条件。**
6. **12 拍里只要 3 拍各超 3 分钟，这节课就崩了。** 所以第 4 条的可砍顺序必须提前写进 runsheet，现场不做判断。

## 9. 各阶段教学细节（按拍）

> **本节只写「怎么教」。所有课堂上要打的字、要念的话，完整版在 §19「课堂全部 prompt」**——每一条都配逐句拆解。老师备课先读 §19，再回来读本节。

### 9.1 拍 0（3+3）｜从他们自己交的作业开始

**做**：一句话——「把你上节课交的那张汇总矩阵拿出来，看**最后一列旁边那列：冲突 / 缺口**。」

给 90 秒。然后举手统计三档：

| 那一列你填了什么 | 通常占比 | 它说明什么 |
|---|---|---|
| 空着 | 多数 | 三路根本没打架，你没东西可填 |
| 「待确认」/「需进一步排查」 | 不少 | 你察觉到有缝，但没有人去查 |
| 具体的两条结论相互矛盾 + 证据 | 极少 | 这个学员当时手动做了本节要教的事 |

**讲**（3 分钟，只讲一件事）：

> 那一列为什么是空的？不是你偷懒，是**你的结构里没有人有动机去挑战别人**。三个子 Agent 各写各的，谁也不知道别人写了什么。你拿到的是**覆盖**——三份都覆盖到了；你拿不到的是**收敛**——到底哪个是真的。
>
> L7 那句话现在要还债了：**子 Agent 之间没有连线。**

不要在这里给答案，不要画拓扑图，不要提 Agent Team 这个词。**这一拍只负责让那一列的空白变得刺眼。**

### 9.2 拍 1（8+4）｜搭第一个 agent

**做**（8 分钟，老师投屏同步写，学员跟着写）：

在 `star-mansions/.claude/agents/` 下新建 `sm-investigator-frontend.md`，写完立刻调用一次，让它查浅题的前端一路。

完整文件和调用句见 **§19.1**。课堂上老师一格一格写，每写一格问一句「这一格在治什么」。

**四格的顺序不能换**（这个顺序本身是教学内容）：

| 顺序 | 写什么 | 现场要问的那句话 |
|---|---|---|
| 1 | `name` + `description` | 「`description` 是给谁看的？」——给主 Agent 看的，它靠这句决定要不要派你 |
| 2 | **`tools`** | 「不写这一行会怎样？」——它就能改文件了。**正文里写一百遍『只读』都不如这一行**（回收 L7） |
| 3 | 正文：范围 | 「为什么用否定句？」——`不要碰 backend/` 比 `请专注 frontend/` 强制力高一档 |
| 4 | 正文：产出合同 + 出口 | 「不给『不知道』一个出口会怎样？」——它会编 |

**讲**（4 分钟）：

⚠️ **这一拍的讲评只做四格收口，不讲「墙」。**

「`tools` 那一行是一道墙、它挡噪音也挡证据」这句是**立论的一半**——放在这里等于在学员撞墙前 40 分钟剧透。它移到**拍 3 立论之后**（§9.4c），性质从预告变成回收。详见 §11.2.1。

这一拍讲什么：

1. 逐格回一遍「这一格在治什么」（上表四行）。
2. 让学员打开仓库自带的 `.claude/agents/` 那 4 个文件比一比：**谁的 `tools` 划得更死。只比，不抄。**
3. 一句留白（**只说这一句，不展开**）：「记住你 `tools` 那一行写了什么。**一小时后我们回来看它。**」

> ⚠️ 全班的角色文件必须落在**同一级目录**（项目级 `.claude/agents/`）。放错级别的人后面调用不到，这是这一拍唯一会卡人的地方——预检卡里那行就是为了它。

### 9.3 拍 2（10+4）｜三路并跑，收三份「我这边没问题」

**做**（10 分钟）：

把刚才那份文件复制成三份，只改三处（`name` / 范围 / `description`）：

| 角色 | 只读范围 | 它看不到什么（老师心里有数，先不说） |
|---|---|---|
| `sm-investigator-frontend` | `frontend/src/` | 后端怎么派生 user.id |
| `sm-investigator-backend` | `backend/src/` | 前端有没有 normalize 邮箱 |
| `sm-investigator-config` | `.env.example` / `vercel.json` / `.github/workflows/` / `db/schema.sql` | 上面两条都看不到 |

三路同时跑浅题（题面和三份 brief 见 **§19.2**）。**硬性要求：三路互不喂结果**——这是 L7 的结构，今天先把它跑忠实了。

**讲**（4 分钟，两件事）：

**第一件**：念三份结论。它们长这样——

```text
frontend：login 做了 trim 和格式校验，未发现问题。
backend： emailToId 派生 id、upsert onConflict、history 按 user_id 过滤，逻辑严密，未发现问题。
config：  env 与部署配置齐全，未发现问题。
```

问全班一句：**「这三份报告里，有错的吗？」**

答案是**没有**。这一点必须停下来说透——三份全对，而你还是不知道为什么记录会消失。**这不是质量问题。**（但**先不要**说出「结构问题」四个字，那是下一拍的。）

**第二件**（30 秒，只挡一下，不展开）：如果有人当场问「我一个 agent 全读了不就完了」——

> 「好问题。**先记着，我们一会儿回答它。**」

⚠️ **不要在这里展开。** 完整回答（边界是划出来的 vs 逼出来的，照 §3.0 讲）挪到**拍 3 结尾**（§9.4d）。

理由：这一拍的讲评收尾是「记住这个感觉，这不是质量问题」，情绪必须**直接推到拍 3 的口令**。中间插一段方法论讨论会把气泄掉。**这一拍的讲只有 2 分钟，短是故意的。**

### 9.4 拍 3（3+6）🔥｜一次粘贴，一个翻转

**全课最重要的 9 分钟。** 前 8 拍的所有铺垫都是为了这一下。

**做**（3 分钟，老师喊口令，全班同步做同一个动作）。**这一拍的 prompt 逐句拆解见 §19.3——那是全节讲义最值钱的一页，备课必读。**

口令只有一句：

> 「打开你的 **backend** 那个会话。把 **frontend** 报告里那半句——**『login 只做了 trim，不改大小写』**——**原样**复制进去，然后加一个问题：**『这会影响你刚才的结论吗？』** 现在做，30 秒。」

然后**全班一起等**。B 会翻转。

⚠️ **这一拍的三条纪律**：

1. **原样贴，不许总结。** 学员的本能是「我帮它概括一下」——不行。概括过的证据已经掺进了你的判断，翻转就不再是它自己得出的。这一点在拍 4 讲评时要回收。
2. **只加一个问题，不给提示。** 不许写「是不是大小写导致 id 不一致？」——那是你在替它推理。
3. **老师投屏同步做一遍**，让没跟上的人照着抄动作。

**如果 B 不翻转怎么办**（彩排必测，见 §12.2）：备一句追问——

> 「那如果同一个人先后填了 `Rick@x.com` 和 `rick@x.com`，`emailToId` 会派生出几个 id？」

这句一定翻。翻了之后，**要当众说明刚才发生了什么**：「注意，我刚才给了它一个更具体的提示。**提示越具体，说明这条信息越难自己跨过去。**」——这反而是更好的教材。

**讲**（6 分钟）：**立论，按 §6.3 讲，先病 A 后病 B。**

开场句必须扣住他们刚看到的东西：

> 「刚才那半句话，一共 12 个字。它不是新证据——它 10 分钟前就在你 frontend 那份报告里躺着。**变的不是信息，是信息在谁手里。**」

然后上 §6.3 的算术：

```text
「A 没问题」+「B 没问题」+「C 没问题」= 「都没问题」≠ 真相
```

收在那句立论上：

> **交界处的 bug，互不通信的调查者在结构上不可能发现。不是漏了，是算不出来。**

病 B（锚定）在这里只讲 60 秒，埋个引子——「还有一种更阴险的，不通信不是没答案，是**一起给你一个错答案**。那个留到深题。」

#### 9.4c 回收那道墙（2 分钟 · P07）

立论讲完，**立刻回到他们一小时前亲手写的那一行**：

> 「回头看你 `tools:` 那一行。
>
> 上节课我告诉你这道墙的好处：**它挡住噪音**。子 Agent 翻的 50 个文件不会污染你的主 context。
>
> 刚才那 9 分钟你看见了另一面：**它也挡住证据**。那 12 个字就卡在这道墙外面——**不是它不够聪明，是它读不到。**
>
> 同一道墙，两个效果。**而这道墙是你自己砌的。**」

⚠️ 这一段**必须在立论之后**。放在拍 1 就是剧透——详见 §11.2.1。它的价值全在「**你亲手砌的**」这五个字上，而这五个字只有在学员被这道墙坑过之后才有分量。

#### 9.4d 边界从哪来（2 分钟 · P08 · 拍 3 收束）

现在才回答拍 2 那个被压下去的问题：

> 「刚才有人问：这仓库才几十个文件，我一个 agent 全读了不就完了？
>
> 对，**这个仓库你可以。你自己那个项目你不行。**
>
> 今天边界是你在 brief 里**划出来的**；你真实项目里边界是 context **逼出来的**。
>
> **盲区的成因是边界，不是仓库大小。** 边界存在，盲区就存在——20 个文件和 20 万个文件一模一样。」

顺带回收 L7：**你上节课划边界是为了省 context；这节课你发现，同一条边界也是一道信息墙。**

### 9.5 拍 4（4+4）｜三类消息，从自己的动作里命名

**做**（4 分钟）：反向再传一次——把 B 翻转后的结论贴回 A，让 A 确认前端侧的触发路径。根因锁定。

然后**照着刚才发生的事**填三行（模板见 §19.4）：

```markdown
[DISCOVERY] 我传了哪一句原文，从谁到谁：______
[CONFLICT]  它和对方原来的哪条结论矛盾，双方证据各是什么：______
[DECISION]  最后怎么裁的，谁去确认的：______
```

**讲**（4 分钟）：

1. **为什么只留这三类**：只有这三类会改变后续行动，其它都是噪音。
2. **回收「不许总结」那条纪律**：DISCOVERY 的价值在**原文**。你一总结，就把自己的判断掺进去了——那不叫传递证据，叫传递结论。**成员之间传结论会互相污染，传证据才会互相证伪。**
3. 点一句 §18.7 的产品事实（口播，不上 deck）：**没有广播。** 你刚才手动传一次是一次，工具里也是一条一条点名发。所以下一拍那张表必须写死「什么证据抄送谁」。

三个失败模式在这里第一次亮出来（深题之前必须先见过）：

| 失败模式 | 症状 |
|---|---|
| **退化成分工** | 三个人各写各的，一条 CONFLICT 都没有——最常见 |
| **虚假共识** | 都同意了，但都错。「达成一致」不是外部判据 |
| **Lead 抢活** | Lead 自己下场做，没人裁决，辩论没发生 |

### 9.6 拍 5（5+3）｜charter 只写两项

**讲在前，做在后**（本节唯一一拍先讲后做，因为它是纯设计动作）：

3 分钟，一个问题打头：

> 「刚才那两次传递，是**我喊的**。我不在的时候，谁传给谁？」

学员会说「谁发现了谁传」。追一句：**「那你怎么知道自己发现的东西对别人有用？」**——A 当时根本不知道 B 在查 id 派生。这就是通信规则必须**开工前写死**的原因：**判断「这条要不要抄送」的那个人，恰恰是最没有资格判断的那个人**，因为他不知道别人在查什么。

**做**（5 分钟）：**只填第 2 项和第 4 项。** 六项全填放作业。

为什么只填这两项：第 2 项定「谁唱反调」（深题的胜负手），第 4 项定「什么证据抄送谁」（刚才那个问题的答案）。**其余四项在课堂上填，学员会当表格作业做，填完就忘。**

课堂填法见 **§19.5**（含一份填好的样例）。

完整六项（作业用）：

```markdown
# Team charter

## 1. 共同目标
整个 Team 最终要交付或回答什么：______

## 2. 成员与初始所有权
- Lead：拆分、盯覆盖、处理冲突、最终验收
- Teammate A：______
- Teammate B：______
- Teammate C（唱反调）：______

## 3. 初始任务与依赖
| Task | Owner | Depends on | Done when |
|---|---|---|---|
|  |  |  |  |

## 4. 通信规则
- 发现会改变别人方向的证据：立即发给相关成员并抄送 Lead。
- 与其他结论冲突：**附双方证据，不靠投票解决**。
- 阻塞超过 ______：更新任务状态并请求重分配。

## 5. 写入边界
- 每位成员独占：______
- 共同文件由谁集成：______

## 6. 收敛与停止条件
- 所有必选任务完成；关键冲突有证据裁决；验收判据全部执行。
```

核心差异（回收 L7）：**L7 的六格 brief 只需让「一个 Agent 独立做完」；charter 还必须定义 Agent 和 Agent 之间怎样协作。**

⚠️ 通信规则里没有广播——**成员之间发消息要一个个点名**，想让所有人知道一件事得发多条。所以「会改变别人方向的证据要抄送谁」必须在 charter 里写死，不能靠临场判断。

### 9.7 拍 6（18+4）｜手动 Team 跑深题

**这是全课最长的一拍，也是唯一需要课堂管理手册的一拍。**

**装备**（1 分钟摆好，摆不好后面全乱）：

```text
三个会话  ← 就是拍 1 搭的那三个角色文件，不新建
一个 md   ← 共享任务板，学员自己新建 task-board.md
你自己    ← 消息总线 + Team Lead
```

**发题**（2 分钟）：深题题面 + 一页**线上现象报告**（规格见 §12.3，题面和三份 brief 见 §19.6）。

现象报告是这一拍唯一的外部素材，它必须包含：一条完整时间线（部署时刻和记录消失时刻高度吻合）+ **一条埋在中间的反例**（某个时间段没有部署，同一分钟内两次请求一次有一次没有）。

**跑**（15 分钟）——老师做三件事，别的都不做：

| 时刻 | 老师说什么 | 为什么 |
|---|---|---|
| 开跑 | 「任务板先写三行：谁在查什么。**写完再开始跑。**」 | 不先写板，后面没有状态可更新 |
| **第 7 分钟** | 🔔 节拍问题①：**「停手 30 秒。看你三个会话，有没有一条证据是**该传没传**的？」** | 这是防「退化成分工」的唯一手段 |
| **第 13 分钟** | 🔔 节拍问题②：**「现在举手：你们三个人里，有谁在**找反例**吗？」** | 大概率没有。这个空白就是拍 7 的入口 |

节拍问题只有这两句，**不要加第三句**，不要现场指导个人。巡场只做一件事：记下 2–3 个典型（一个只发结论的、一个板没更新的、一个已经开始找反例的），拍 7 讲评点名用。

**硬停**（第 15 分钟，不管跑没跑完）。

⚠️ **计时终点定义**（写在 deck 上，发题时就要说）：

> **不是「找到根因」，是「第一次 CONFLICT 被裁决」。**
>
> 15 分钟找不到根因是正常的；找不到 CONFLICT 才是失败。终点定错，快的组会松懈、慢的组会崩溃。

**讲**（2 分钟 · **口播，不占页**，投屏停在 P12 的两个节拍问题上）：

这一拍的讲评**只做过程诊断，不问价值**：

1. 举手：任务板上「传递记录」有几行？零行的举手。
2. 有几条 CONFLICT？
3. 点名巡场记的那 2–3 个典型（只发结论的 / 板没更新的 / 已经在找反例的）。

⚠️ **「如果禁止通信会怎样」这一问不能在这里问。** 此刻全班手里是错答案，而那个错答案恰恰是**互相通信之后**达成的——诚实的回答是「好像没帮上忙」，这一问就废了。它挪到拍 7 揭穿之后（§9.8c）。详见 §11.2.1。

### 9.8 拍 7（4+7）🔥｜虚假共识：三个人一致同意，三个人一起错

**先收答案**（1 分钟）。大部分组会交上来这个：

> 「根因：部署 / 冷启动导致数据丢失。证据：每次记录消失前 30 秒内都有一次部署，时间戳完全吻合。」

**不要说它错。** 先说三句实话，让它显得更可信：

1. 时间线是真的。
2. 「冷启动会清空内存」这个机制也是真的。
3. 按这个结论去修，**你会去研究部署流程、加持久化、改 Vercel 配置——三个方向，全错。**

**做**（4 分钟）：补一个唱反调成员，**只问它一个问题**（prompt 见 §19.7）：

> 「找反例：有没有『没有部署但记录也丢了』的时候？」

反例就在现象报告里。找到它，因果链断掉。

**讲**（7 分钟）：

```text
部署 ──→ 记录消失     ← 三个人一致相信的因果
                        证据：时间戳吻合

真相：
      定时任务 ──┬──→ 部署 / 实例回收
                 └──→ 记录消失
      共因，不是因果。

真正的根因：生产环境 Supabase env 没生效
            → 走了 handlers/history.ts 里那条「仅本地/单测用」的 memStore
```

三个必须讲透的点：

1. **B 并没有失职。** B 读到了 `memStore` 那行注释，推理是「这是本地回落，线上有 env 所以不走这条路」——**在 B 自己的证据范围内，这个推理完全正确**（回收拍 3 的立论，第二次）。
2. **交换证据不够，还得有人证伪。** 浅题里，三个人互传一次就解开了；深题里，三个人互传只会**更快地达成一致**——一致地错。这就是病 A 和病 B 的分界。
3. **所以 charter 第 2 项必须写死一个唱反调的人。** 不是「大家都要有批判精神」，是**有一个人的 KPI 就是推翻别人**。回收 §6.4「对抗 ≠ 分工」，这时候学员才真信。

一句收口：

> **共识不是判据。三个人都同意，只说明三个人看的是同一批证据。**

#### 9.8c 价值发生在消息里（2 分钟 · P15 · 现在才问得动）

**现在**才把那一问抛出来：

> **如果禁止你在三个会话之间传递证据，这个任务会在哪一步变慢或变差？**

答案有两层，而第二层才是本节真正要教的：

| | 答案 |
|---|---|
| **第一层 · 浅题** | 不通信 = **根本没有答案**。三个「没问题」加起来还是「没问题」 |
| **第二层 · 深题（他们刚亲历的）** | 这次**通信了**，结果是**更快地达成一致——一致地错** |

收口：

> **通信是必要条件，不是充分条件。还得有人专职推翻。**

配那句诊断（点名拍 6 巡场记的典型时用）：

> **一条 CONFLICT 都没有的 Team，大概率是三个不说话的 Subagent——只是更贵。**

### 9.9 拍 8（3+4）｜任务板全绿 ≠ 外部验收完成

**做**（3 分钟）：拿你的根因结论，去找**一条来自成员自述之外的**反证或证据。在这个题上通常是：翻到 `handlers/history.ts` 里 `memStore` 那行，把**文件:行号**写下来；或者指出 `.env.example` 里有而生产没有的那个变量名。

**讲**（4 分钟）：按 §6.7 的四个追问走，配一份「任务板全绿但不可验收」的反例——所有任务 completed，但根因结论没有行号、排除项只写「没查到」、验收命令没跑过。

收口那句和 L7 同一句，本节加重：

> **多 Agent 改变的是信息怎样流动，不会转移最终验收责任。**

### 9.10 拍 9（8）👀｜同一份文件，两种结构

**老师投屏，学员只看不做。**

关键在于开场那句话：

> 「我现在要用的，**就是你们一小时前写的那三份角色文件**。一个字没改。」

演示三步（spawn prompt 见 §19.9）：

1. 用同样三份文件开一个自动 Team 跑同一道深题。
2. **立刻验成员名单**——名单里有多个成员 = team 成型；只有你自己 = 工具给了你三个 subagent（§18.8、§18.10 头号坑）。当场问一句：**「你怎么知道你现在跑的是 Team 不是三个 Subagent？」**
3. 让它跑到第一条成员间消息出现，停。

两张拓扑图这时候才同屏（学员两种都亲历过了，对比才有基础）：

```text
【Subagent：Hub-and-spoke】

                    ┌→ 子 Agent A ─┐
你 ↔ 主 Agent / Hub ├→ 子 Agent B ─┼→ 结果回 Hub → Hub 汇总
                    └→ 子 Agent C ─┘

成员之间没有连线；分工、补 context、冲突处理都经过 Hub。

【Agent Team：Team collaboration】

                   ↔ Teammate A ↔
你 ↔ Team Lead     ↕      ↕      ↔ 共享任务板 / 信箱
                   ↔ Teammate B ↔

成员不仅交结果，还会互通发现、处理依赖、挑战彼此结论。
```

**结论定死在两句话上**：

> 它替你做了：**传递、认领、状态同步**——就是你刚才手动干的那三件苦力。
> 它**没有**替你做：**裁决和外部验收**——那两件事在 L7 是你的活，在 L8 还是你的活。

顺带点一句 §18.4 的对照（这是「同一份文件」这个设计的兑现）：**同一份角色文件当 teammate 跑时，`skills` 和 `mcpServers` 两个字段不生效，而团队协作工具始终可用**——能力边界跟当 subagent 时不一样。所以「不假设继承」这条铁律在 Team 结构里还要再做一次 capability check。

> 工具不支持 / 现场跑失败 → 放预录，或直接口播那两句结论。**这一拍是全课最先可砍的**（§8.1 第 4 条）。

### 9.11 拍 10（4）🔴｜过度组队红灯 + 快速分类

**判断题，不动手。**

> L7 的红灯是**动手实测**（因为「派不派」是那节的核心判断）；本节的红灯是**判断题**，因为学员已经在 L7 亲手测过分派成本，Team 的额外成本可以在那个基线上推算。

给 6 张任务卡，让学员投「单 Agent / Subagent / Agent Team」：

1. 从 20,000 行日志里找首次异常并给证据。
2. 分别排查前端、API、数据库三种登录失败假设，且**根因未知**。
3. 前后端要持续协调接口变化并分别实现。
4. 对已完成的权限改动按 5 条安全判据做只读审查。
5. 把三个模块的 README 各更新一遍。
6. 一个设计选型，三个方案各有取舍，需要有人反对。

第 5 题是陷阱：三个模块互不依赖 → **分工，不是对抗** → Subagent。

微任务红灯：给一个「查 `MAX_RETRY` 定义在哪」级别的活，让学员估算三种结构各要做多少启动与协调动作。过关答案：它没有多 context 强收益，**更没有成员通信需求**，应该直接做。

> **能组 Team，不代表该组 Team。**

异构那条在这里口播 30 秒回收（按 §6.9），不单独占页。

### 12.3 深题素材：线上现象报告 fixture 规格

> **这是本节唯一需要制作的素材，一页纸，不改仓库任何代码。**

必须包含四块，缺一块深题就演不出来：

| 块 | 内容 | 作用 |
|---|---|---|
| **1. 症状** | 「线上保存记录后，过一阵子历史是空的；有时又能看到。」用户视角，不含任何技术判断 | 不给方向 |
| **2. 时间线（诱饵）** | 5–7 条带时间戳的事件。**每一条「记录消失」前 30 秒内都有一条「部署 / 实例回收」**，吻合度要高到让人一眼下结论 | 制造虚假共识 |
| **3. 反例（钥匙）** | **埋在时间线中段，不加粗、不单列。** 至少一条：某时段没有任何部署，但 `10:14:02` 和 `10:14:31` 两次 `GET /api/history` 一次返回 3 条、一次返回 0 条 | 唯一能打断因果链的东西 |
| **4. 噪音** | 2–3 条无关但真实的日志行（CORS preflight、favicon 404 之类） | 不能太干净，太干净学员会觉得是题 |

**制作纪律**

- 反例必须**只能通过「主动找反例」被发现**，不能是顺着时间线读下来就撞上的。放中段、格式和别的行完全一样。
- 时间线里**不要出现** `memStore`、`SUPABASE`、`env` 任何字样。那是学员要自己从代码里拼出来的另一半。
- 报告本身不下任何结论。一句「疑似与部署有关」都不能写——**诱饵要由学员自己得出，他们才会为它辩护。**

**彩排判据**：把这一页 + 三份 brief 给三路跑，**不给唱反调 prompt**，看它们是不是一致交上「部署导致丢失」。是 → 合格。有一路自己找到反例了 → 反例埋得太浅，往中段挪并去掉一切提示性措辞。

## 14. Exit ticket 与作业

### 14.1 Exit ticket（5 分钟，四题）

1. 今天三份报告全都说「我这边没问题」，而且**三份都是对的**。为什么你还是不知道根因？（考立论）
2. 「A 查前端、B 查后端、C 查配置」——这是对抗还是分工？该用哪种结构？
3. 深题里三个成员一致认为「部署导致记录丢失」，时间戳完全吻合。**用一句话说明怎么拆穿它。**（考反例思维，不是考答案）
4. Team 全部任务显示 completed，是否代表可以验收？还缺什么？

过关标准：四题至少三题正确，**且第 1、3 题必须答对**——那两题分别对应病 A 和病 B，全课就为这两件事。

> v0.1 的第 4 题（异构为什么只能进 Subagent）挪到作业。它是知识点，不是本节的核心判断，占 exit 的一格太贵。

### 14.2 作业

1. **把课堂三份角色文件补完整**：六格 brief 全填 + `tools` 收到最紧，提交三份 md。
2. **给 star-mansions 提一个 issue**：把浅题（邮箱大小写 → 历史记录消失）写成一份可复现的缺陷报告，含复现步骤、`文件:行号` 证据、影响面。**选做：提 PR 修它。**
3. 在**自己的真实项目**里找一个需要成员通信的任务，先填结构选择卡；不能先开队伍后补理由。
4. 提交 Team charter（**六项全填**）、任务板快照、至少各一条 DISCOVERY / CONFLICT / DECISION、Lead 最终结论。
5. 至少执行一个来自成员自述之外的**验收动作**，并附输出。
6. 再找一个**看起来像团队协作、其实是分工**的任务，说明为什么 Subagent 更划算。
7. 说清楚：**异构（混用别家的 Agent）为什么只能进 Subagent，进不了 Agent Team？**
8. 选做：把同一个任务分别用 Subagent 和 Agent Team 各跑一次，记录时间、消息数、结论差异。
9. **选做（进阶）**：按 `HANDOUT.md` §12 的五阶段访谈法，为你自己领域造一个**专家 Agent**。提交三样东西：① 访谈过程里 Agent 问你的问题清单（看它有没有真的在访谈）；② 确认后的 **Agent Specification**；③ 最终 System Prompt。**再加一份审计报告**——找另一个 Agent 按 §12.4 那条 prompt 挑四类具体问题（职责过宽 / 权限过大 / 缺少验证 / 输出不稳定），每类给一个可复现场景。

提交包：三份角色文件 + 缺陷报告 + 结构选择卡 + 协作包 + 验收证据 + 150 字复盘。

> 第 2 题是本节最值钱的作业：**学员的第一份公开技术产出，来自他上课时亲手找到的一个真实 bug。** 这比任何练习都能建立「我在做真实工作」的实感。

## 15. 手动 Team：这不是降级，是本节的主教具

> **v0.2 的口径变了。** v0.1 把这一节写成「国内学员的主路径」，实际上它是**全班的主路径**——拍 0 到拍 8 全部用手动 Team 跑，无论学员手上有没有 Agent Team 功能。理由见 §6.10。
>
> 因此本节**没有工具门槛**：只要能创建角色文件、能同时开三个会话，就能完整上完这节课。

先把话说在前面：**本节的判断框架是工具无关的，产品实现不是。** 第二问、对抗 ≠ 分工、三类关键消息、Lead 收敛责任——换任何工具都成立。但「Agent Team」作为一个开箱产品，目前只有少数工具做了。

| 本节能力 | 国内工具普遍情况 | 本节怎么处理 |
|---|---|---|
| 成员之间直接通信 | **普遍没有** | **全班都手动传**（拍 3–8） |
| 共享任务板 + 自主认领 | **普遍没有** | **全班都用一个 md**（拍 6） |
| 各自独立工作副本 | 多数没有 | 本节全程只读，用不到 |
| 自动 Team | 少数工具有 | 只在拍 9 由老师投屏演示 8 分钟 |

### 15.1 手动 Team 的标准做法

1. 三个会话各跑一个角色文件，边界照 §9.3 划。**不要新建角色，就用拍 1 那三份。**
2. A 拿到会改变 B 方向的证据时，**你手动把那段原文贴进 B 的会话**，再加一个具体问题。
   - ⚠️ **原文转贴，不做二次总结**——这是本节的操作纪律，理由见 §9.5。
3. 冲突出现时，把双方证据**同时**贴给第三个会话做裁决。
4. 你自己维护一张任务板（一个 md 文件就够），三行：谁在查什么、状态、结论。

**绝对不要**用「多个互不通信的 Subagent」冒充 Team——那正是拍 2 演的失败对照组。

### 15.2 为什么手动版的教学效果反而更好

三条，都在课堂上验证得到：

1. **你亲手当了一次消息总线，就知道 Team 帮你省的到底是什么。** §9.7 那句讲评（「如果禁止成员互相通信，这个任务会在哪一步变慢」），手动版学员答得比自动版准——因为慢在哪一步是他们自己扛过来的。
2. **手动传递让因果关系可见。** 自动版看到的是「结果不一样了」，手动版看到的是「**我贴的这一句话改变了它的结论**」。本节唯一要教的就是这个因果。
3. **手动版停得下来。** 12 拍的课需要每一拍都能喊停——这是自动 Team 结构上做不到的事（§6.10）。

### 15.3 这套做法迁移到别的工具

手动 Team 只依赖三件事，任何工具都有：

```text
能同时开三个会话  +  能给每个会话固定一段角色说明  +  你能复制粘贴
```

角色文件的形式各家不同（有的是 md 文件，有的是会话开头一段固定 prompt，有的是「智能体 / 助手」配置）。**形式不重要，重要的是那三段说明互不重叠、各自带一条硬边界。** 换工具时，把 §19.1 那份四格模板照抄进各自的角色配置框即可，判断线一条都不用改。

## 16. 官方依据与数据纪律

### 16.1 稳定原理

- Subagent 是集中协调结构：成员聚焦执行，结果回中心，由中心处理覆盖、冲突与汇总。
- Agent Team 是协作结构：成员需要共享发现、协调依赖或互相挑战，Team Lead 负责最终收敛。
- 两种结构没有固定强弱；选择依据是任务的**通信拓扑**，而不是 Agent 数量。
- 顺序调查存在锚定偏差：先探索的理论会偏置后续调查。多个独立调查者互相证伪时，活下来的理论更可能是真根因。
- Agent 数量增加会增加总 token / 计算成本、协调成本与结果合并风险；墙钟变快不等于总成本变低。
- 对话 context 与工作区隔离是两个维度。

### 16.2 产品事实只做「当天映射」

截至 2026-08-02，Claude Code 官方文档明确区分：subagent 在独立 context 中执行聚焦任务并**只回报主会话**；agent team 是独立会话组成的团队，**成员之间可直接发消息**并共享任务列表。三条对备课影响最大、必须记在案的事实：

1. **Agent Team 是实验特性，默认关闭。** 不显式打开，session 启动时不建 team、不写 team 目录，Claude 既不会 spawn 也不会提议 teammate——**不报错，静默无效**。
2. **Claude 有时会用 subagent 代替 team，而两者在同一个面板里外观相同**——只看面板确认不了。
3. **Agent Team 不给成员做工作副本隔离**，官方处方是划分文件所有权；而 subagent 可以各自跑在独立工作副本里。

参考：

- [Orchestrate teams of Claude Code sessions](https://code.claude.com/docs/en/agent-teams)
- [Create custom subagents](https://code.claude.com/docs/en/sub-agents)
- [Run agents in parallel](https://code.claude.com/docs/en/agents)

这些页面用来验证「为什么要做能力预检」，不用于在 deck 上背产品参数。若课堂改用其他工具，老师必须换成该工具的官方文档并重新实测。

### 16.3 数据纪律

- Deck 只保留跨工具成立的判断框架；具体按钮、开关字面量、并发上限、上下文继承方式放老师备注。
- **模型选型只讲档位和判断线**，不出现模型名、价格、版本号。
- 实验用来观察信息流和协调方式，不包装成模型跑分或普遍性能结论。
- 任何「更快」「更省」「更可靠」的结论都必须说明比较对象和指标。

## 18. 附录 A：Agent Team 的设置与生成方法

> **这一节不上 deck。** 老师备课和学员课后自查用。
>
> **口径与复核**：按 Claude Code 官方文档整理（2026-08-02 核对）。带版本号的条目会继续变——老师上课当天必须用手上那个版本重跑一遍 §12.2 的验收清单。换别的工具则整节作废。

### 18.1 前提：开关默认是关的

这是整节课的开课门槛。在设置文件的 `env` 段落里把 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 置为 `1`（也可以走环境变量）。

不设它：session 启动不建 team、不写 team 目录，Claude 既不会 spawn 也不会提议 teammate——**你会以为是自己指令写得不对，其实是功能没开。**

官方同时标注 agent teams 为实验特性，在会话恢复、任务协调、关停行为上有已知限制（见 §18.9）。

### 18.2 生成：只有自然语言，没有命令

```text
我在设计一个扫描代码库 TODO 注释的 CLI 工具。开三个 teammate 从不同角度探索：
一个负责 UX，一个负责技术架构，一个专门唱反调。
```

两条路径：你主动要，或者 Claude 判断该并行时提议、你确认。**Claude 不会未经批准就开人。** 早期版本需要先手动建 team 再拉人，现在不用了，session 退出自动清理。

**对抗辩论的关键句**（这是本节实验的命脉）：

```text
用户反馈 app 收到一条消息后就退出。开 5 个 teammate 各查一个假设。

让它们互相对话、试图推翻彼此的理论，像一场科学辩论。
最后把达成的共识写进结论文档。
```

去掉「让它们互相对话、试图推翻彼此」这半句，拿到的就是三份互不相干的报告。

### 18.3 指定人数和模型

```text
开 4 个 teammate 并行重构这几个模块，每个都用 <某档>。
```

⚠️ **teammate 默认不跟随 Lead 的 `/model`**。要跟随得去 `/config` 把默认 teammate 模型改成「跟随 Lead」。effort 倒是继承 Lead 的。**成员的模型在 spawn 时固定，事后 `/model` 只改 Lead。**

### 18.4 复用 subagent 定义当 teammate 角色

```text
用 security-reviewer 这个 agent type 开一个 teammate，审一下 auth 模块。
```

teammate 会用那份定义的 `tools` 和 `model`，定义正文**追加**到它的 system prompt（不是替换）。

两个例外，**恰好是最好的课堂教材**：

- 定义里的 `skills` 和 `mcpServers` 两个字段**当 teammate 跑时不生效**——teammate 按普通 session 的规则从项目/用户设置加载。**同一份文件，当 subagent 用和当 teammate 用，能力不一样。**
- 团队协作工具（发消息、任务管理）**始终可用**，哪怕 `tools` 把别的都限制死了。

> 讲法：拿 L7 写好的同一个角色文件，在两种结构里各跑一次，让学员看到能力边界不同。这比讲十遍「先做 capability check」都管用。

### 18.5 要求成员先出计划再动手

```text
开一个架构师 teammate 重构鉴权模块。动手前必须先过计划审批。
只批带测试覆盖的计划。
```

teammate 在只读计划模式下工作，出完计划交 Lead 审；驳回就带着反馈改了再交。**Lead 是自主决策的**——想影响它，得在 prompt 里给判据。

这条是 L6「计划先行」处方在 Team 结构里的实现，写进 charter 第 6 项收敛条件。

### 18.6 显示模式：决定老师投屏长什么样

| 模式 | 长什么样 | 代价 |
|---|---|---|
| 单终端（默认） | 全部挤在一个终端，方向键选成员，回车进它的 transcript | 任何终端都能跑，但**成员互通几乎看不见** |
| 分屏 | 每个成员一个独立窗格，同时看到所有人输出 | 要额外装终端复用工具；**部分常见终端根本不支持** |

本节的教学目标是让学员**看见**消息在成员之间流动。默认模式下这件事发生在你看不到的地方——课前必须确认上课那台机器能不能开分屏；不能的话，预录从「降级方案」升格为主要素材。

### 18.7 任务怎么分

Lead 建任务，成员认领，三态：待办 / 进行中 / 已完成。任务之间可以设依赖，**依赖没完成的任务认领不了**；多人同时抢同一个任务用文件锁挡住。

⚠️ **没有广播**——成员之间发消息要一个个点名，想让所有人知道一件事得发多条。这对辩论是真实的结构性摩擦：**证据不会自动扩散**。所以 charter 的通信规则必须写明「会改变别人方向的证据要抄送谁」。

### 18.8 落盘在哪——用它证明 team 真的成型了

团队名 = `session-` + 会话 ID 前 8 位。三样东西落在本地：

- 团队配置：成员名单，Lead 的类型固定标记为 team lead
- 共享任务列表：**会保留**，供恢复会话时接着用
- 每个成员一个信箱文件

**课堂用法**：实验开始后让学员打开成员名单看一眼——**名单里有多个成员 = team 成型了；只有你自己 = Claude 给了你三个 subagent。** 这是头号坑最便宜的检出方式。

⚠️ 团队配置文件存的是运行时状态，**不要手改也不要预先写好**，下次状态更新会覆盖。

### 18.9 权限与已知限制

**权限**：成员继承 Lead 的权限设置。**成员的权限弹窗全部出现在 Lead 那一个会话里**——23 分钟的实验不预批就会全花在点确认上。

安全边界（值得在课上讲半句）：成员之间发消息时，接收方被明确告知**这来自另一个 Claude 会话，不是来自你**；成员不能代你批权限，被拒的动作也不能转手给别的成员绕过去。这是「多 Agent 不转移最终验收责任」在权限层的同一件事。

**规模**：没有硬上限。官方建议 **3–5 人**起步，每人 5–6 个任务，并明说「三个专注的成员常常胜过五个散的」。课堂固定 3 个成员（Lead 不计）。

**已知限制**，每一条都对应一个课堂风险：

| 限制 | 课堂后果 |
|---|---|
| 单终端模式的成员**不支持恢复会话** | 谁的会话崩了成员救不回来，只能重开。要有重开预案 |
| 任务状态会滞后（成员忘了标完成） | 卡住依赖任务。**这恰好是 §6.7「计时终点不是成员都标 done」的产品级证据** |
| 关停慢（要跑完当前动作） | 下课收尾留 buffer |
| **一个 session 一个 team** | 不能跨会话共享，也开不了第二个队 |
| **不能嵌套**：成员不能再开成员 | 与 subagent 默认可嵌套形成对比 |
| Lead 固定，不能换人 | charter 里的 Lead 角色绑死，不能中途移交 |

### 18.10 头号坑：Claude 会用 Subagent 冒充 Team

官方原文明说：Claude 有时会直接用 subagent 而不建 team，**而且两者在同一个面板里外观相同，光看面板确认不了**。

这是本节实验静默降级的主要路径——全班以为在跑 Team，实际跑的是三个互不通信的 subagent，然后 §9.7 那句讲评就问不出任何东西，因为本来就没通信过。

处方两条：**指令里明确要求 agent team**；开跑后用 §18.8 的成员名单验一次。

> 别浪费这个坑——它是本节最好的即兴教材。当场问一句：**「你怎么知道你现在跑的是 Team 不是三个 Subagent？」** 答不上来，就等于承认自己在假设协作能力。

### 18.11 学员课后自查清单（作业附页）

```markdown
## 开 Team 之前
- [ ] 开关开了吗？（不开就没有 team，且不会报错提示）
- [ ] 我怎么确认成型的：看了成员名单 / 让两个成员互发了消息 / 都没有
- [ ] 显示模式：我看得见成员之间的消息吗？
```

## 19. 附录 B：课堂全部 prompt（逐句拆解）

> **这一节是讲义的核心，要发给学员。** 本节课堂上要打的每一个字都在这里，每一条都配「为什么这么写」。
>
> **教学立场**：prompt 本身会过期，**组词的理由不会**。所以每一条都拆到「这一句在治什么」那一层——学员换了工具、换了项目，照着理由还能重新写一条出来；只抄 prompt，换个场景就废了。
>
> 老师备课顺序：先读 §19.0 的七条通用规律，再读各拍的具体 prompt。课堂上不要念 prompt，要念**理由那一列**。

### 19.0 七条通用规律（所有 prompt 都在用）

这七条是 L5–L7 一路攒下来的，本节全部复用，**讲义第一页就印它**：

| # | 规律 | 为什么 |
|---|---|---|
| 1 | **边界写在字面上，别指望它猜** | 它读不到你和别人的对话，也读不到你脑子里的分工 |
| 2 | **否定句比肯定句强制力高一档** | `不要读 backend/` > `请专注 frontend/`。Agent 默认倾向顺手多做 |
| 3 | **证据格式前置** | 不前置只能拿到自然语言总结，没法验收、更没法给别人当证据 |
| 4 | **逼出 not_checked** | 不问，你永远不知道它跳过了什么——**而缺口正是本节要找的东西** |
| 5 | **给「不知道」一个出口** | 不给出口就是逼它编。这条最容易漏 |
| 6 | **范围靠 `tools` 物理限制，不靠正文请求** | 正文是请求，`tools` 是保证。这是六格 brief 里唯一能从「请求」变「保证」的一格 |
| 7 | **传证据，不传结论** | 本节新增的一条。你把证据总结过再给对方，掺进去的是你的判断——那不叫证伪，叫说服 |

第 7 条是 L8 独有的，也是本节操作层最重要的一条。

### 19.1 拍 1｜第一个角色文件 + 调用句

#### 文件：`.claude/agents/sm-investigator-frontend.md`

```markdown
---
name: sm-investigator-frontend
description: 只读调查 star-mansions 的前端代码，回答关于登录、会话与接口调用的具体问题。需要确认前端实际行为时使用。
tools: Read, Grep, Glob
model: <中间档>
---

你是 star-mansions 项目的前端只读调查员。

## 范围
- 只读 `frontend/` 目录。
- **不要读 `backend/`，不要读部署与配置文件。** 那两块由别人负责。
- 不修改任何文件。

## 产出合同
status: complete | partial | blocked

## findings
- 结论：______
  evidence: `文件:行号` + 一句解释

## checked
- ______

## not_checked
- ______

## 硬规则
- 每条结论必须带 `文件:行号`。没有行号的结论不要写。
- 只描述你**读到的代码行为**，不要推测其它模块怎么实现。
- 证据不足时返回「无法判断 + 缺什么证据」，不要猜。
```

#### 逐格拆解（课堂上一格一格写，每格问一句）

| 这一格 | 现场提问 | 它在治什么 |
|---|---|---|
| `name` | — | 调用时点名用。**必须和文件名一致**，不一致的话点名点不到 |
| `description` | 「这句是给谁看的？」 | **给主 Agent 看的**，它靠这句决定要不要派你。写得含糊，主 Agent 就不会派它——L7 讲过的「①点名 vs ②指名」差别，根子在这一句 |
| **`tools`** | 「不写这一行会怎样？」 | **它就能改文件了。** 正文里写一百遍「只读」都不如这一行。这是全课的暗线：**你砌的这道墙，挡噪音也挡证据** |
| `model` | 「按什么选档？」 | 按**判断密度**不按重要性（L7 §6.9）。调查员是执行密集，中间档够用；拍 7 的唱反调是判断密集，要最强档 |
| 范围（否定句） | 「为什么用『不要』不用『请专注』？」 | 规律 2。而且这里的否定句是**双保险**——`tools` 挡写，正文挡读的范围 |
| 产出合同 | 「为什么要固定格式？」 | 三路格式不统一就没法比对。**而本节要比对的正是三路之间的缝** |
| `not_checked` | 「为什么要逼它列没查的？」 | 规律 4。**这一格是拍 2 的伏笔**——三路的 not_checked 拼起来，就是那道信息墙的形状 |
| 出口 | 「不给出口会怎样？」 | 规律 5，它会编 |

> ⚠️ **数据纪律**：`model` 那一行在讲义和 deck 上都写 `<中间档>`，不写具体模型名（§16.3）。老师上课当天口播实际填什么。

#### 调用句（写完立刻跑一次）

```text
用 sm-investigator-frontend 调查：星宿记录的历史列表有时看不到之前保存的内容。
前端这一侧，从填邮箱登录到调用 /api/history，做了哪些对邮箱字符串的处理？
每一步都要给出 文件:行号。
```

| 这一句 | 它在治什么 |
|---|---|
| `用 sm-investigator-frontend 调查` | **指名调用**（L7 三档里的第②档）。不指名，主 Agent 可能自己干了——这一拍就白做 |
| `星宿记录的历史列表有时看不到之前保存的内容` | 只给**用户视角的症状**，不给任何技术方向。给了方向就等于替它推理 |
| `从填邮箱登录到调用 /api/history` | 划出一条**路径**而不是一个目录。路径比目录更能约束它别乱翻 |
| `做了哪些对邮箱字符串的处理` | 问题要**足够具体到能被证据回答**，但不能包含答案。这里没提「大小写」三个字 |
| `每一步都要给出 文件:行号` | 规律 3。**而且这些行号就是拍 3 要粘贴的原文** |

### 19.2 拍 2｜浅题题面 + 三路 brief

#### 发给学员的题面

```text
【浅题】

用户报告：用同一个邮箱登录，之前保存的星宿记录有时候看不到了。
不是报错，就是列表空的。重新登录一次有时又出来了。

三路只读调查，各自回答：你这一侧，有没有任何东西会影响
「这条记录属于谁」这个判断？

规则：
1. 全程只读，谁都不许改文件。
2. 三路各自独立，不要把 A 的结果喂给 B。
3. 三路都用同一个产出格式，不然没法比对。
```

| 这一句 | 它在治什么 |
|---|---|
| `不是报错，就是列表空的` | 排除「查错误日志」这条捷径，逼它们读代码 |
| `重新登录一次有时又出来了` | 「有时」两个字是关键——**它暗示了状态相关，但没说是什么状态**。这是让三路都能查出东西的必要条件 |
| `有没有任何东西会影响「这条记录属于谁」` | 三路问同一个问题，**问题跨越了三路的边界**。这是交界 bug 能被演出来的前提：题目本身是跨界的，边界是人为划的 |
| `不要把 A 的结果喂给 B` | **这一条是今天的实验变量。** 拍 3 要打破的就是它——先忠实执行，才有对照 |
| `都用同一个产出格式` | 格式不统一，三份报告就没法并排念（拍 2 讲评要并排念） |

#### 三路的差异（只改三处）

| 角色 | `description` 改成 | 范围改成 | 它看不到什么 |
|---|---|---|---|
| `sm-investigator-frontend` | 前端登录、会话与接口调用 | 只读 `frontend/` | 后端怎么派生 user.id |
| `sm-investigator-backend` | 后端鉴权、作用域与数据读写 | 只读 `backend/src/` 和 `backend/api/` | 前端有没有 normalize 邮箱 |
| `sm-investigator-config` | 部署配置、环境变量与 CI | 只读 `backend/.env.example`、`backend/vercel.json`、`.github/workflows/`、`backend/db/schema.sql` | 上面两条都看不到 |

> **为什么只改三处**：让学员看清「三个队友」在文件层面上的差别只有几行。**角色不是人格，是边界。** 这句在拍 2 讲评时说。

### 19.3 拍 3｜🔥 那一次粘贴（全课最重要的 prompt）

#### 老师口令（照念）

> 「打开你的 **backend** 那个会话。把 **frontend** 报告里那半句——**『login 只做了 trim()，不改大小写』**——**原样**复制进去，然后加一个问题：**『这会影响你刚才的结论吗？』** 现在做，30 秒。」

#### 学员实际打的字

```text
frontend 那一路的原文：

> authAdapter.login 只对邮箱做了 trim()，不做大小写归一。
> 证据：frontend/src/lib/authAdapter.ts:31

这会影响你刚才的结论吗？
```

#### 逐句拆解（这张表是本节讲义最值钱的一页）

| 这一句 | 为什么这么写 | 写错会怎样 |
|---|---|---|
| `frontend 那一路的原文：` | **标明来源**。让它知道这不是你的判断，是另一个调查者的观测 | 不标来源，它会当成你在提要求，倾向于顺从而不是核对 |
| 用引用块贴**原文** | 规律 7。**证据是可以被独立核对的，结论不行** | 你一总结，掺进去的是你的判断。它翻转的是「同意你」，不是「发现矛盾」 |
| 保留 `文件:行号` | 它可以自己去读那一行验证 | 没有行号，它只能选择相信或不信——那是社交，不是证伪 |
| `这会影响你刚才的结论吗？` | **开放问句**。不给方向，让翻转由它自己完成 | 写成「是不是大小写导致 id 不一致？」= 你替它推理完了，翻转不算数 |
| `你刚才的结论` | 锚定到**它自己说过的话**，逼它做前后对比 | 不锚定，它会当成一个新问题重新回答一遍，不产生「我错了」这一步 |
| 全程不提「大小写」三个字 | 那是它要自己接的那一环 | 提了，这一拍就从「发现」降级成「确认」 |

#### 备用追问句（B 不翻转时才用）

```text
那如果同一个用户先后填了 Rick@x.com 和 rick@x.com，
emailToId 会派生出几个 id？
```

| 这一句 | 为什么 |
|---|---|
| 给两个**具体的字面值** | 从抽象规则降到具体输入。**抽象它能糊弄，具体它必须算** |
| `会派生出几个 id` | 问一个**有唯一数字答案**的问题。答「2」它就自己把结论推翻了 |

⚠️ 用了备用句要**当众说明**：「我刚才给了它一个更具体的提示。**提示越具体，说明这条信息越难自己跨过去**——这恰恰证明了那道墙是真的。」

### 19.4 拍 4｜反向传递 + 三类消息卡

#### 反向传递（贴回 A）

```text
backend 那一路的原文：

> emailToId() 用邮箱原文派生 user.id，
> Rick@x.com 和 rick@x.com 会得到两个不同的 id。
> 证据：backend/src/handlers/auth.ts:12

你那一侧，有没有可能让同一个人先后提交两种大小写？
```

| 这一句 | 为什么 |
|---|---|
| 同样是**原文 + 来源 + 行号** | 规律 7，双向都要守 |
| `你那一侧，有没有可能……` | 把问题**限定在它的边界内**。不问「所以根因是什么」——**根因的裁决是你的活，不是它的** |
| 问的是**触发路径**不是结论 | 这一步要的是「怎么发生的」，闭合证据链 |

> 这里要点一句 §6.7：**你刚才没有让任何一个成员宣布根因。根因是你根据两边证据自己裁决的。** 这就是 Lead 的活。

#### 三类消息卡（人手一份纸质，课堂填）

```markdown
[DISCOVERY] 我传了哪一句原文，从谁到谁：
            ______________________________________

[CONFLICT]  它和对方原来的哪条结论矛盾？双方证据各是什么：
            ______________________________________

[DECISION]  最后怎么裁的？谁去确认的？
            ______________________________________
```

| 为什么只留这三类 | |
|---|---|
| DISCOVERY | 会**改变别人下一步**的新证据 |
| CONFLICT | 两条结论**不能同时为真** |
| DECISION | **裁决**，以及裁完之后谁做什么 |
| 其它全是噪音 | 「收到」「我这边继续」「同意」——这些不改变任何后续行动 |

### 19.5 拍 5｜charter 第 2 项 + 第 4 项

课堂只填这两项（5 分钟硬停），六项全填放作业。

#### 空白版（发学员）

```markdown
## 2. 成员与初始所有权
- Lead（你自己）：拆分、盯覆盖、处理冲突、最终验收
- 成员 A：______        只读范围：______
- 成员 B：______        只读范围：______
- 成员 C（**唱反调**）：______   它的任务是：______

## 4. 通信规则
- 什么样的证据必须立即转给别人：______
- 转给谁（点名，不能写「相关的人」）：______
- 冲突怎么处理：附双方证据，**不投票**，由 ______ 裁决
- 转发时：贴 ______（原文 / 我的总结）
```

#### 填好的样例（老师投屏）

```markdown
## 2. 成员与初始所有权
- Lead（我）：裁决、外部验收
- A · frontend investigator   只读范围：frontend/
- B · backend investigator    只读范围：backend/src/、backend/api/
- C · 唱反调                  它的任务是：给 A 和 B 的每条结论找一个反例

## 4. 通信规则
- 必须立即转的证据：任何「某个值在我这一侧被改变 / 未被改变」的观测
- 转给谁：A ↔ B 双向互转，C 全收
- 冲突：附双方 文件:行号，不投票，由 Lead 裁决
- 转发时：贴原文，不贴我的总结
```

| 这一格 | 为什么这么填 |
|---|---|
| C 的任务写成「**给每条结论找一个反例**」 | 不能写「批判性思考」「保持怀疑」——那是态度，不是任务。**任务必须是一个可执行的动作** |
| 「必须立即转」定义成**一类观测**而不是「重要的发现」 | 「重要」由谁判断？**恰恰是最没资格判断的那个人**（他不知道别人在查什么）。所以要按**形状**定义，不按重要性 |
| 转给谁要**点名** | §18.7：**没有广播。** 想让所有人知道得发多条 |
| `不投票` | §6.6。三个 Agent 很容易达成一致，而一致不等于对 |
| `贴原文，不贴总结` | 规律 7，写进 charter 才守得住 |

### 19.7 拍 7｜🔥 唱反调 prompt

这是全课**第二重要**的 prompt，也是最容易写错的一个。

#### 正确版

```text
你的任务不是找根因，是找反例。

现在有一个结论：「部署 / 实例回收导致记录丢失」，
证据是每次记录消失前 30 秒内都有一次部署，时间戳吻合。

去《线上现象报告》里找：**有没有「没有部署，但记录也丢了」的时候？**
或者「有部署，但记录没丢」的时候？

找到就给出具体时间戳。找不到就明确说找不到，不要替这个结论辩护。
```

| 这一句 | 为什么这么写 |
|---|---|
| `你的任务不是找根因，是找反例` | **第一句就把角色定死。** 不说这句，它会顺手也去找根因，然后被同一批证据说服 |
| 把要攻击的结论**完整复述一遍** | 它必须知道打的是什么。含糊地说「挑战一下大家的结论」＝ 没有靶子 |
| 把对方的**证据也复述一遍** | 让它能针对证据本身找漏，而不是针对结论抬杠 |
| `有没有「没有 X，但 Y 也发生了」的时候` | ⭐ **把证伪变成一个可检索的动作。** 这是整条 prompt 的技术核心——「批判性思考」不可执行，「找一条 X 不成立但 Y 成立的记录」可执行 |
| 双向都问（`有 X 但没 Y` 也问） | 因果链两端都要打。只打一端，它可能漏掉更容易找的那个方向 |
| `找不到就明确说找不到` | 规律 5 的变体。**不给出口，唱反调的会硬编一个反例出来**——那比虚假共识更糟 |
| `不要替这个结论辩护` | 它的默认倾向是帮你把事情说圆。要显式禁掉 |

#### 错误版对照（讲义里必须印出来当反面教材）

| ❌ 这样写 | 为什么不行 |
|---|---|
| 「批判性地看一下大家的结论」 | 态度不是任务。它会回一段「确实需要更多证据」的正确废话 |
| 「你觉得这个结论对吗？」 | 是非题。它大概率答「基本合理，但建议进一步验证」 |
| 「找出这个结论的三个问题」 | 逼它凑数。**没问题的时候它会编三个出来** |
| 「假设这个结论是错的，那根因是什么？」 | 跳过了证伪直接换答案，等于换一个没有证据的猜测 |

> 讲这一段时点破一句：**「唱反调」不是一种性格，是一个有具体检索目标的任务。** 你给不出检索目标，就得不到反调。

### 19.8 拍 8｜外部验收 prompt

```text
不要重做调查。

现在的结论是：生产环境未生效的 Supabase 配置导致
history 走了进程内存回落，实例之间不共享。

只做两件事：
1. 把这条结论追溯到 文件:行号 —— 那条内存回落分支具体在哪一行？
2. 指出一条**这个结论无法解释**的现象（如果有）。

只回答这两条，不要给修复建议。
```

| 这一句 | 为什么 |
|---|---|
| `不要重做调查` | L7 §9.12 的老规矩：**verifier 不重做探索**，重做就是又一次同样的偏差 |
| 把结论**完整给出** | 验收的对象必须明确 |
| `追溯到 文件:行号` | 外部判据第一条。**「说得通」不是证据，行号才是** |
| `指出一条这个结论无法解释的现象` | 第二条，也是更狠的一条——**逼它找结论的边界**，而不是确认结论 |
| `不要给修复建议` | 本节非目标：不修（§5）。一给建议，学员就想动手，后面全乱 |

### 19.9 拍 9｜自动 Team 的 spawn prompt（老师投屏用）

```text
用 agent team 开三个 teammate，分别用
sm-investigator-frontend、sm-investigator-backend、sm-investigator-config
这三个 agent 定义。

任务：找出线上记录丢失的根因（现象报告已在 docs/ 下）。

让它们互相对话、试图推翻彼此的理论，像一场科学辩论。
发现会改变别人方向的证据时，直接发给相关成员并抄送我。
最后把裁决过程和结论写进任务板。
```

| 这一句 | 为什么 |
|---|---|
| `用 agent team` | §18.10 头号坑：**不明说，工具会用 subagent 冒充**。而两者面板长得一样 |
| `分别用 ...这三个 agent 定义` | ⭐ **这一拍的全部意义**：同一份文件，换个结构再跑一次。开场那句「一个字没改」靠它兑现 |
| `让它们互相对话、试图推翻彼此的理论` | §18.2：**去掉这半句，拿到的就是三份互不相干的报告**——那是 Subagent，只是更贵 |
| `发现会改变别人方向的证据时，直接发给相关成员并抄送我` | 把 charter 第 4 项翻译成 spawn prompt。**没有广播**，所以要写「抄送我」 |
| `把裁决过程写进任务板` | 只写结论的话，学员看不到消息流动——而那正是这一拍要展示的 |

**开完立刻做两个验证动作**（§18.8）：

1. 看成员名单：**多于一个成员 = team 成型；只有你自己 = 三个 subagent。**
2. 让两个成员互发一条消息，在 Lead 侧看到。

然后当场问全班：**「你怎么知道你现在跑的是 Team 不是三个 Subagent？」**

---

### 19.10 讲义怎么用（发给学员的话）

印在讲义第一页：

> 这份材料里的每一条 prompt，右边都有一列「为什么这么写」。
>
> **考试不考 prompt，考右边那一列。**
>
> 因为你回去用的不会是 star-mansions，可能也不是今天这个工具。
> prompt 抄过去就废了，理由抄过去还成立。
>
> 判断标准很简单：**遮住左边，你能不能照着右边把左边重写一遍？** 能，这节课你就带走了。

## 20. 附录 C：让 Agent 当 Agent 架构师（课后进阶）

> **完整方法、五阶段逐句拆解、可直接复制的提示词，在 `vibe-coding-master-l8/HANDOUT.md` §12。**
> 老师的 3 分钟口播稿、学员会问的两个问题、砍掉时的补救动作，在 `RUNSHEET.md` 拍 11。
> **本节只记录教学决策**——为什么它在课程结构里是这个位置。

### 20.1 它解决什么问题

学员回去造第二个 agent 时，大概率会直接说：

```text
帮我创建一个安全专家 Agent。
```

拿到的是一段「你是一名资深安全专家，拥有十年经验……」的人设提示词。

**这就是一个没有 `tools` 字段的角色文件。** 缺的是真实职责、能碰哪些系统、用什么工具、按什么流程走、拿什么判据定级、什么时候必须交给人。

正确做法：**让 Agent 先当 Agent 架构师，通过五阶段访谈把规格问出来，最后才写 Prompt。**

### 20.2 为什么不能提前到拍 1（教学决策，不能让步）

| # | 理由 |
|---|---|
| 1 | **你不会审规格，就不该让 AI 替你写规格。** 学员必须先亲手写过 `tools`、写过「不知道」的出口、写过产出合同，才看得懂 AI 生成的规格里哪一格是空的、哪一格是它替你编的业务规则 |
| 2 | **拍 9 那句「一个字没改」需要主语。** 「同一份文件当 teammate 跑」的对照，说服力全靠「这是**你**写的那份」 |
| 3 | **违反本系列一贯的「先撞墙，再给工具」。** 第一拍就给自动化 = 给了工具没撞墙 |

顺序是死的：**手写在前，访谈在后。**

### 20.3 判断线：什么时候值得走五阶段（HANDOUT §12.1 的依据）

五阶段访谈认真做要半小时对话。**不是每个 agent 都值得。**

```text
只读 · 一次性 · 自己用            → 手写四格（拍 1 那套），5 分钟够了
要交给别人用 / 长期复用 / 要交接  → 走五阶段
能改东西 / 碰得到权限 / 能花钱    → 必须走五阶段
```

这跟本节 §6.2「Team 门槛必须比 Subagent 高」是**同一种判断**：别因为方法更高级就都用它。学员最容易犯的错，L7 是「学完什么都派」，L8 是「学完什么都组队」，这里是「学完什么都走五阶段」。

### 20.4 它和本节四条判断的对应（这是它能进 L8 的理由）

**这一节不是外挂内容，是把今天四条判断用到「设计 Agent」上。**

| 访谈法里的 | 就是本节的 |
|---|---|
| **规格先于 Prompt** | **charter 先于开跑**（§9.6）。规格能逐条审，Prompt 是散文审不动；写 Prompt 就是开跑。而且失败模式一样：**临场判断的那个人恰恰最没资格判断** |
| **第三阶段「风险检查」那 10 条** | **全是交界问题**（§6.3 病 A）。职责重叠、权限超出职责、输出无法被下游消费 —— 每条单看都合理，合起来才出事。`「A 没问题」+「B 没问题」≠ 真相` |
| **「让另一个 Agent 当审计员」** | **拍 7 的唱反调成员**（§9.8）。而且同一条纪律：不能说「审计一下」，要给**有限且具体的检索目标**——「找一个它会越权的具体动作」。**态度 ≠ 任务**，本节第二次出现 |
| **「不要只询问抽象的风格或角色定位」** | **L7 的 `tools` 那一行**（§9.2 暗线）。人设写在正文里是请求，`tools` 才是保证。**人设不是边界，权限才是** |

### 20.5 两条必须写进讲义的风险

1. **AI 会很乐意替你填 Severity 定义和升级门槛——而那些恰恰是只有你知道的。** 所以第三阶段的 prompt 里「**不要自行假设关键业务规则**」不能省；拿到规格后要把「AI 填的」和「你填的」分开标一遍。
2. **不能跳过第一到三阶段直接要规格。** 跳了会拿到一份看起来很完整、但业务规则全是它编的规格。前三阶段的全部意义就是逼出「它不知道、必须问你」的那些格子。
